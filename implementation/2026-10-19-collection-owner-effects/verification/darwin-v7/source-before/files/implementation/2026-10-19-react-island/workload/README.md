# Native to React island workload

The native arm compiles `compiler/fixtures/native-react-island.tsx` through the Rust/OXC native compiler. It mounts two native roots containing three React islands rendered by `ReactDOM.createRoot` through the public bridge. The React arm renders the same `ReactLeaf` interaction through ordinary React roots. Only `react_arm.tsx` and `react_leaf.tsx` enter the Babel React Compiler pipeline; the native fixture enters the native compiler. The build proof checks an actual `_c` call inside `ReactLeaf`, along with the native registration and lowered Store/state sites. The compiler fixture gate is explicitly an AST/source proof, not a ReactDOM execution test.

Both arms click a React button and a native-side button, update a Store-derived point, reorder keyed islands, remove and reinsert one island, and settle a prestarted promise after pending work. The native arm also prepares and discards a candidate, rejects a stale candidate, and verifies both roots are accepted before its grouped callback. Assertions check button and private container identity, React state, event delivery, prop observations, mount/cleanup counts, pending accepted props, and empty teardown. Native publication and React rendering are separate commits; the workload does not claim cross-renderer visual atomicity. Native VNodes are not accepted as React `children`; React children must be created by React code.

The workload reports setup-return time and first matching mount output separately because the native ReactDOM mount can complete after the controller returns. A 2,048-sample clock quantum is recorded; neither mount field is a cold CPU timing. Luna runs `node implementation/2026-10-19-react-island/workload/build-gate.mjs --proof-dir ABSOLUTE_NEW_PROOF_DIR` after primary source review. The gate freezes source and compiler hashes, captures transformed modules and a production bundle, and preserves failure logs. After review of that proof, the primary writes `run-authorization.json` in the same directory with `status: "APPROVED_FOR_ONE_DESCRIPTIVE_PAIR"` and `buildProofSha256` equal to the exact `build-proof.json` SHA-256. Luna then runs `node implementation/2026-10-19-react-island/workload/run-pair.mjs --proof-dir ABSOLUTE_PROOF_DIR --origin https://react-island.localhost`. The one-shot runner uses a headless, GPU-off browser and fulfills synthetic HTTPS requests only from the frozen local asset manifest; it starts no project server. Its timer runs from final promise settlement to the first matching `MutationObserver` for all React island labels, which includes scheduling and observer delivery but excludes paint and CPU attribution. It preserves the first receipt and does not retry for a favorable result.
