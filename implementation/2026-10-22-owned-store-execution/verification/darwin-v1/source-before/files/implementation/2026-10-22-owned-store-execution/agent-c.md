# Root integration handoff

This slice replaces callback execution for explicit data-owned closed Store programs. `defineComponent` normalizes `closedStoreExecution` against the already normalized host program and keeps that association in private registration metadata. Schema 7 requires exactly one supported kernel or data arm; simultaneous declarations reject. Legacy kernel 1 retains its `executeRange` identity, contiguous run inputs, offsets, output-buffer checks, finite guards, and thrown-error behavior.

`#stageClosedStoreOutputs` now tests whole-selection data eligibility from private registrations, cache records, reader membership and selected sources before invoking a legacy callback. A qualified selection captures canonical World lineage/cells, then sends all ordered Store requests to the new single-operation batch. The owner loop consumes captured values, evaluates the privately associated expression plan, and uses the existing `stageLeaf`, scalar regions, current checks and publication lifecycle. Schema-5 primitive empty-child data uses the scalar region path. The data arm does not populate or check legacy kernel input/output buffers; the common function still allocates its empty buffer arrays. `#captureRetainedCells` uses the same canonical World capture for eligible Root-internal mixed local writes; public structural handles retain their original route.

Root cache `props` are copied into a new plain `componentProps` record during component expansion (`#expand`), then held only in the private component cache. Passive preflight reads own descriptors from that record. It does not reflect on a candidate Store object; exact private membership/selection identity is checked first, and B's private-brand check rejects Proxy/noncanonical Store receivers before its audit. A frozen caller object alone never establishes ownership.

The batch is conservative. A legacy/opaque/resource/noncanonical owner, an unsupported cache/output, unselected accepted Store input, unmatched reader, or noncanonical World falls back to the original ordered per-owner preparation. Data owners in that route still evaluate their data plan one by one; they do not synthesize an executable callback. A declined Store batch also returns to that route without staged readers; subsequent candidate failure discards the fresh transaction through existing cleanup. No batch integrity fact survives into validation or publication. Existing owner coverage, ancestry overlap, effect-site, retained-child, source-version, hold, live Store/World, exact acknowledgement, reentry, fork-history, host and final private-group checks remain in place.

Trace: all-data selected readers pass preflight, World capture and ordered Store batch, then each output stages in owner order and `store.owned-data.batches` increments after successful staging/current validation. Legacy-only bypasses capture and follows its existing contiguous kernel runs. Mixed data/legacy bypasses capture, evaluates data at its original position and flushes legacy runs at every boundary. A noncanonical World makes capture decline, so the conservative route retains public method behavior. An unselected accepted reader prevents whole-batch admission and retains receipt checks. Preparation failure discards candidate artifacts and staged Store readers; host/publication failures use the unchanged lifecycle quarantine and cleanup.

New costs include whole-selection private preflight, copied World rows, ordered batch requests/results and expression-tree evaluation in place of generated DAG CSE/inlining. They are unmeasured. The observable capability is removal of selected-owner `executeRange` callbacks and repeated per-reader Store canonical audits within a successful batch, with no claimed speed benefit. A falsifier is a data owner still invoking `executeRange`, a legacy callback reordering, a reused audit fact after return, or a failed history/publication gate.

No tests, builds or benchmarks were executed by this agent. Luna should include `deno test --frozen src/closed_store_numeric_kernel_test.ts src/component_state_runtime_test.ts` in the consolidated correctness gate, followed by the primary-owned compiled fixture and installed proof commands.

## Publication finalization correction

The specialized closed-input path retains public World capture and validation callbacks before and after host writes. Final private group validation now uses canonical `scalarSourceForCell`/`versionForCell` with the existing post-host newer-version rule. Before publication, closed Store staging records canonical lineage; accepted cache and keyed-region swaps consume that owned lineage, and cell acknowledgement calls the captured canonical World implementation. Installing `ownerLineage` or `clearCellChangesThrough` overrides after public preflight cannot run a new callback after accepted Store history advances. This treats final bookkeeping as an internal protocol; public validation remains observable, including inherited World overrides.

Resource-retained publication uses the same final private cell validator, captured lineage and canonical acknowledgement. The existing retirement deletion sequence is factored into one Root helper. Reveal staging records retired-owner caches, canonical lineages and source references; final admission rechecks them and calls World’s fresh zero-lane retirement predicate. Accepted retirement uses the World-owned internal operation, whose private recursion avoids a late public `destroyOwner` override. A lane-backed fallback owner declines the specialized reveal and remains eligible for generic rendering. The resource stage’s existing effect cleanup and reader/subscription paths remain unchanged.

The reveal preflight still performs its established public `ownerLineage` sort, preserving callback observation. Accepted retirement sorts the captured canonical lineage records deepest first. A subclass that reports false public depths cannot make an internal parent retirement destroy a child before that child’s accepted cache deletion and exact retirement check.
