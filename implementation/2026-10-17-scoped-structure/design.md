# Scoped structural/cache publication

This slice replaces whole-root version rejection only for explicit, existing-row collection move/remove transactions. `prepareCollections(collections)` selects every mounted region reading the supplied collection identities; `enqueueCollections` groups those cuts through the existing root queue. Unsupported work declines explicitly, while ordinary full-tree and implicit mixed paths retain conservative validation. Roots with Store readers or resource/Suspense history remain outside this first subset, as do inserts, replacements, leaf renders and combined numeric/structural cuts.

The authority remains the World owner/slot lifetime, collection reader cutoff and version, compiler revision, mounted key/region indexes, and Root accepted publication history. The existing immutable region-parent VNode is its order-generation token. A scoped VDOM cut pins that parent, bucket, and actual operation key/anchor identities. It does not copy all region members or introduce a parallel region/version registry. A nested disjoint VDOM edit can survive under a moved row; removal detaches current live writers. Root scoped removal currently requires a single-owner row. Acceptance revokes that owner's World capabilities, cache membership and pending state before ref detach or effect callbacks; existing effect ownership then supplies exactly-once cleanup. Same-region edits and remove/reinsert revoke the captured order token.

Root preparation pins each selected region's direct cache/keyed-region/reader identities. Shared App ancestry is not a conflict: acceptance invalidates the current ancestor cache records and preserves unrelated keyed maps, instead of reinstalling captured whole caches. Pure moves do not advance numeric accepted history or acknowledge dirty row state. Exact reader acknowledgements are staged before group acceptance; host-time newer collection logs remain pending. Runtime-created structural candidates use the same host/applying/published/quarantine lifecycle as retained props, with a discriminated private admission mode and an explicit VDOM version delta. Whole-tree candidates keep their original bases.

Public operation/request getters can mutate a region during preparation. The region order token is captured before those getters, and final live validation must reject a revoked target. Public collection-version getters can revoke World slots; World publication inputs must be checked after those callbacks as well. Staged reader acknowledgement reports whether its authentic collection frontier is caught up, avoiding a public getter during acceptance and retaining newer pending actions. Arbitrary physical host mutations are not rollbackable. Failed batches keep accepted pointers/revisions old and quarantine the root; resource/ref/effect cleanup follows the shared lifecycle.

The measured savings budget is unresolved. This is semantic admission work over existing buckets and traversal layouts, not a selected storage optimization. Correctness falsifiers include: an unrelated region invalidating a safe cut solely through common ancestry, a stale owner/key reaching a writer, a pending numeric action lost during movement, a newer collection log consumed by old acknowledgement, or accepted history advancing after partial failure. Consolidated checks and one bounded matched browser comparison are recorded separately; historic narrow wins and the later dense FAIL stay unchanged. Full async reveal, mixed scoped edits, host/resource conformance, packaging/portability, cold/memory/second-device qualification, and human maintainability evidence remain open.
