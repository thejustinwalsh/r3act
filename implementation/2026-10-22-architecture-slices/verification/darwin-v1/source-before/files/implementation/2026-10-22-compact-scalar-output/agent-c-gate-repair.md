# Packet C Darwin v1 source repair

The immutable Darwin v1 gate found five Root type errors and a first-cut runtime error. `PassiveRow` had intersected `Owner.inputs` with its narrower Store input type, hiding the `store` field at two checks. It now replaces that field with `Omit<Owner, "inputs">` and retains the exact captured Store input records. `nextShape` now requires a prior shape before comparing its bindings; the former optional first comparison could succeed with both requests undefined, then dereference an absent shape. The structural keyed rejection fallback now materializes the candidate's authored output through the canonical cache view, replacing its removed `ComponentCache.result` access.

A source search of the remaining `.result`, `.expandedResult`, and closed-shape crossings found no further `ComponentCache` field reads. Remaining `.result` accesses belong to prepared renders and keyed items. The compiled fixture's doubled warm rows and renders are not treated as new expectations: VDOM's type-only `OwnedScalarFrame` value import can throw during compact preparation and cause a generic fallback; Packet B owns that repair. No fixture assertions were weakened.

This repair changes no public API, Store wait rule, candidate admission, accepted history, or benchmark workload. It has not been tested or typechecked by Packet C. Luna should rerun the consolidated frozen Deno and compiled gate after primary review and Packet B integration; a repeated Root type error, first-cut TypeError, stale authored output after keyed rejection, or unexplained warm fallback falsifies the repair.
