# Packet A handoff: owned scalar output

Packet A replaces the admitted internal tuple/region producer with one complete immutable scalar frame per ordered captured row. The frame copies primitive values, including constants, before either numeric scratch buffer is reused. Its normalized layout owns fixed prop names, dynamic slots and literal constants. Private fields brand both types; the classes and prototypes are frozen. Frames hold no previous frame, Root, mounted node, source or callback. An explicit adapter creates the former frozen Store region only when an ordinary tuple consumer asks for it.

The new `closed_scalar_output.ts` exports `OwnedScalarLayout`, `OwnedScalarFrame`, `isOwnedScalarLayout`, `isOwnedScalarFrame`, `materializeOwnedScalarPropEntries`, `materializeOwnedScalarPropRecord` and `OwnedScalarOutputCounts`. Layout reads use `length/nameAt/slotAt/constantAt`; frame reads use `layout/length/valueAt`. Caller-owned optional counts have `frames`, `rootMaterializations` and `propMaterializations`. The producer signature is `prepareOwnedClosedStoreOutputs(world, transaction, orderedRequests, counts?)`; its ready rows retain `owner`, `lineage`, `cells`, and add `frame`, `key`, `tag`, optional `retainedChildren` and `componentOwner`. `materializeOwnedScalarStorePropDelta(row, counts?)` is the legacy adapter. `materializeOwnedScalarRuntimeElement(frame, {tag,key,owner,children?}, counts?)` creates a runtime-owned ordinary JSX view; separate authored and expanded calls preserve their distinct child references.

The producer retains bound requests, fresh World capture, batched Store projections, request order and identity checks. Verified schema-2 kernels and unsupported interpretation use the same finite output check. The existing public `evaluateClosedStoreDataExecution` still returns frozen tuples through the explicit frame adapter. Public forged and unsupported metadata still decline. Exact Store acknowledgement, Root publication and VDOM mounted semantics are owned by the other packets.

Source-only review found and closed three authenticity risks: factories copy caller arrays once and validate the captured copies; those copies use indexed reads with a captured `Object.defineProperty` rather than a mutable Array iterator or late property hook; and the copy checks actual array identity plus a safe length of at most 32 before iteration. Duplicate names, nonprimitive or nonfinite constants and values, mismatched width, signed-zero constant mismatch, prototype forgeries and Proxy-wrapped frames are rejected. Counter objects are never retained in a frame or layout. The compatibility materializer creates frozen pairs, props and region, with its existing private region brand.

Tests were authored in `closed_scalar_output_test.ts` and updated in `closed_store_execution_test.ts` for 1/32 output props, mixed primitive constants, schema-5 marker and nonretained key cases, signed zero, nonfinite rejection, scratch reuse, historical immutability, exact legacy adapter shape and forged/prototype/Proxy decline.
