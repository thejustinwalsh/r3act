# Mounted frame execution retirement and limits

This wave replaces repeated owned frame descriptions with mounted execution and one authenticated candidate-private cut. The source is implemented and under consolidated verification; this document makes no passing-gate or performance claim.

| Replaced mechanism | Current mechanism | Invariant authority |
| --- | --- | --- |
| Fresh request vectors and repeated immediate eligibility discovery | Root retained composition and one live selection pass | Existing Root live readers/cache and module revision |
| Owned output rows, PassiveRow, per-owner generic staging maps and regions | Cut ordinals plus current cache bases | Genuine privately constructed OwnedClosedFrameCut |
| Per-cut reader source maps and Store regrouping | Mounted reader/Store partition and fresh transaction snapshots | Existing Store transaction and accepted history |
| Generic owned descriptor parsing and copied target geometry | Direct cut preparation and mounted binding references | Existing VDOM node/key bucket and prepared record |
| Warm private retained child-array copies | Reuse of runtime-owned private child array | Existing mounted target generation and full live validation |
| Full-tree replacement retaining retired composition | Accepted full-tree composition reconciliation/pruning | Next accepted cache and live owner set |

Generic parsing/publication remains for actual generic callers. There is one publisher; this wave introduces neither accepted-state mirrors nor a second identity/version registry. Fresh captured values, private fill buffers, immutable result pages, accepted output/VNode/cache identities, target next/base references and membership validation still cost work. Required live reader/target/bucket/per-write/final checks remain.

Exact acknowledgement and captured snapshots preserve newer reentrant actions and per-root accepted history. Candidate discard does not install proposed bindings; partial host failure quarantines rather than replaying writes. Root, Store, World, VDOM, module and resource authorities keep their existing roles. Old snapshot observations must remain immutable and removed resources must be released while surviving roots remain live.

The measured budget is the previous same-run publication median/p90 of2.40/2.70ms versus React0.60/0.70ms on the retained256-mesh comparison. That is a target gap, not a prediction of savings. One balanced prechange/candidate/React episode evaluates the integrated source after correctness/delivery. A failure, a regression outside the predeclared margin or failure to close parity is reported as such; no helper timing campaign or favorable rerun follows.

The archived prechange is the actual verified dirty source and tarballs before this wave. [Production accounting](production-source-accounting.json) compares that source directly, excluding tests, dependencies, generated output and evidence. The wave deletes old paths but is a net source addition; it is not a claim of a massive net cleanup. Full-product cold/memory, broader same-root merge/discovery, independent-device and maintenance evidence obligations remain open.
