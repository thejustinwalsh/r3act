# Dependency-orchestration installed boundary

This is a new authored route and a new source lock. It does not reuse or amend the 20 October async UX receipts. `prepare.mjs --proof-dir NEW_PROOF_VN` stages the current public package tarballs, their packaged compiler, the current `examples/dependency-scoped/{app.tsx,main.ts}`, this consumer and harness source, selected runtime/compiler source, installed dependency graph, build logs, actual transforms and separate minified Native and React assets. The package report must match current source hashes. Every recorded input and output is hashed before and after browser work, and every offline HTTPS asset response is checked against its locked bytes. The two arms must not load each other's assets.

The React arm receives the same known route key and explicitly starts profile, permissions and recommendations together. It waits for the profile account ID before starting projects, deduplicates equal provider keys and the shared navigation derivation, and uses the same controllable deferred resolution sequence as Native. This comparator tests compiler-integrated orchestration and accepted progress against equally informed React Compiler code; it is not a serial strawman. Provider start/settle event order and critical-path diagrams from deferred promises are deterministic semantic evidence, **not** network-latency measurements.

The browser driver runs an untimed proof first in fresh, headless GPU-enabled contexts over exact offline HTTPS replay. It proves independent known-key starts, the profile-to-projects hard prerequisite, one start for shared requests, navigation reveal while recommendations remain pending, urgent Store progress, independent fork acceptance, cancellation, late-result rejection and disposal. Native and React snapshots, request traces and output text must match at corresponding stages. A failure receipt retains partial stages, browser errors, blocked requests and closure state. No timing can run until a primary-reviewed proof receipt is locked by a separate `timing-authorization.json` containing the exact build/input/proof hashes.

The single authorized timing phase uses eight fresh contexts in `Native, React, React, Native, React, Native, Native, React` order, with 12 warmups and 60 measured urgent dispatches per context while the recommendations promise remains pending. A matching accepted DOM MutationObserver or declarative Three commit event timestamps each sample; full snapshots, provider events and animation-frame waits stay outside samples. Each warmup and measured sample retains its ordinal, start, observed timestamp and duration. Nearest-rank median and p90 are primary; raw p95/max are retained. Record request starts/settlements, navigation and slow reveal stamps separately. This is dispatch-to-matching-observer delivery, not CPU time, actual paint or input-to-presentation latency. The fixed deferred schedule supports correctness and update responsiveness only; cold/setup, retained memory, independent-device and real-network loader performance remain open.

The browser phase has a 90-second interruptible deadline, closes only contexts and browser instances it owns, and writes one exclusive proof or timing receipt before launch. A failed receipt is never overwritten or rerun for a favorable result. No project server, VM or focus-stealing browser is used.
