# Packet A source handoff

Replaced mechanism: `_readOwnedClosedProjectionBatch` no longer creates a singleton reader Set, per-Store pending marker Map entry and observation object for each direct reader. The existing `StoreRenderTransaction` now has one discriminated `owned-direct` reader mode with one row per distinct reader ID pointing to the captured Store snapshot. Store snapshots, root pins, projection path deduplication and accepted `AsyncStore` reader histories remain the authorities. No savepoint-journal closure saving is claimed; inactive checkpoints already omitted those closures. The expected budget is zero generic materializations on a canonical direct frame; the removable time, memory and JIT effects are unmeasured. A falsifier is changed history identity, a newer-head reread, lost reader footprint or public input entering the private cut constructor.

`#promoteDirectReaders` converts the captured rows once to the generic reader/pending/observation maps. It is called by `checkpoint`, `preserveReaders` (and thus `preserveCapturedReaders`), `dropReaders`, `retireClosedReaders`, `readClosedProjections` (and thus `readClosedNumeric`), `read`, `preparePublication` and `preparePublicationAfterHost`. Closed/prepared and invalid-reader errors remain before promotion where they existed. `rollbackTo`, `releaseCheckpoint`, `readersSince` and `observationsSince` operate only after a checkpoint has promoted. Read-only `readers`, `observations` and `getObservation` synthesize captured views without promoting. `stores`, `validate*` and `closedInputsChanged` still inspect the original pinned snapshots. Blocked-reader receipts remain restricted to `capturedReaderCut`, never compact direct rows. Published direct rows remain available for postpublication read-only views. Discard leaves reader footprints while hiding observations; neither successful publication nor discard performs a generic materialization.

`prepareCanonicalClosedStorePublication` audits replaceable transaction phase/public preparation methods, snapshot phase methods and canonical closed Store shape before any accepted-history staging. It stages after-host lineage through the same `AsyncStore.#prepareReaderEntries` used by the existing `_prepareReaderValues`; the direct adapter passes grouped reader IDs without recreating generic pending marker maps. Every direct ID gets its own frozen `AcceptedReaderHistory` and captured stamp. Its final private phase check precedes `#preparedPublication` assignment. A public-required result leaves the transaction unprepared so Root may run `preparePublicationAfterHost` on the same captured cut; that route promotes and invokes public methods. Caller exceptions propagate rather than becoming stale. `publishAccepted` remains the single publisher and still uses `_publishPreparedReaderValues`. `readOwnedClosedStoreCaptureCounts` reads actual private counts and allocates a frozen snapshot only on request; it conveys no validity or publication capability. Counts remain available after candidate publication/discard.

World `_captureOwnedClosedInputs` is the canonical producer for both entry points. `captureOwnedClosedWorldInputBatch` requests a `ClosedWorldCellCut` built from the actual captured handle/source/version/value, deduplicated by owner/site with exact identity and `Object.is` value checks. `captureOwnedClosedWorldInputs` requests rows only and avoids allocating the unused cut for retained-cell consumers. The internal `includeCut` parameter defaults to rows-only, preserving existing four-argument callers. Both exports use the same private request normalizer, preserving descriptor access and exception order while copying supplied arrays. Public `createClosedWorldCellCut` keeps descriptor copying and validation; it cannot invoke the private constructor with caller-owned arrays. `prepareOwnedClosedStoreOutputs` returns the authentic cut with ready rows. Root retains responsibility for exact dirty-handle coverage, held footprints, acknowledgement and last source values.

Callback/deopt boundaries: request normalization and public `preparePublicationAfterHost` may observe Proxy/getter/override behavior. Canonical admission audits those methods and uses captured private calls. Host-time changes are accepted only under the existing Store lineage rule; stale or overridden cases return to the existing public path before acceptance. No host write is replayed by Packet A. Compact rows are released with the transaction, while pinned snapshots and immutable accepted histories keep their original lifetime.
