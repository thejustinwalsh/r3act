# Dependency-scoped route

This private-alpha example uses the public `@r3act` packages and the bundled Rust/OXC compiler. It mounts a navigation DOM root, a recommendations DOM root, and a Three object tree. The Three host is observed as an object tree; this example does not create a WebGL renderer or claim a drawn frame.

The compiled `asyncTask` relations start `profile(query)`, `permissions(query)`, and the slower `recommendations(query)` when the route key is known. `projects(profile.accountId)` waits for the actual profile result. Navigation derives from profile, permissions, and projects. The same three-root operation requests `reveal: "independent"`, so navigation can be accepted in the DOM and Three roots while recommendations remain pending. A Store-driven urgent counter can still update the accepted roots. Default coherent publication remains the separate queue policy.

`main.ts` supplies a caller-owned `AsyncTaskDemandScope`. Explicit provider definitions own startup and receive an abort signal; one explicit pure navigation definition shares derived work. Stable provider definitions, the compiler module revision, and captured input identities/versions key sharing across the three child executions. A bound provider or derivation still executes its same definition without sharing if the scope is full; unbound tasks use their authored callbacks. Compiler dependency metadata does not declare purity or provider ownership. Each execution releases its leases on completion or cancellation; the scope evicts the entry after its last interest. Late results from an aborted provider cannot publish to a retired root.

The page exposes `window.dependencyScoped`. Call `begin("B")`, then `resolveProfile("B", {query:"B",accountId:"account-B",name:"Bea"})`; `projects` starts only then. Resolve permissions and projects to reveal navigation while recommendations remain pending. `urgent()` dispatches an independent Store update. `cancelPending()` cancels the pending route operation after already accepted navigation stays visible. `resolveRecommendations("B", {query:"B",label:"late"})` can then demonstrate late-result quarantine. `snapshot()` returns DOM values, the Three group name, Store heads, provider events, task status, accepted snapshot strings, and scope size. `dispose()` cancels work and cleans up all roots.

Install fresh private-alpha package tarballs before building. The development server follows the repository's Portless HTTPS workflow. This example demonstrates dependency order, sharing, reveal and lifetime semantics; it makes no timing or performance advantage claim.
