# React update-window ordering audit

This is a diagnostic copied-asset variant of the frozen [v3 declarative React proof](../2026-10-22-native-frame-publication/proof-canvas-v3/canvas-proof-one-shot.json), not a new timing result. The question is whether the visible work that makes frame `e` correct occurs between the **original** `updateStart = performance.now()` and `publishEnd = performance.now()` expressions in the shared `scene.start` tick ([frozen bundle lines 22633–22650](../2026-10-22-native-frame-publication/proof-canvas-v3/dist/react/assets/react-Dn0IWIE6.js#L22633-L22650)). `make-ordering-variant.mjs` pins the original React bundle hash, requires unique exact-text anchors, copies `dist/react` into an exclusive new output directory, patches only the copy, and writes `ordering-manifest.json` with original source byte offsets and before/after hashes. It does not modify authored React, installed packages or archived proof bytes. It has not been executed by this author.

The browser collector is the exported self-contained `initReactBoundaryAudit()` function. The runner imports it and injects `(${initReactBoundaryAudit.toString()})();` as an init script **before** loading the copied `react.html`. The copied bundle requires `globalThis.__reactBoundaryAudit`; absence is an error. The helper installs 769 per-instance scalar-property observers and wraps the shared `renderer.render` after mount and before `controlProof`: motion `position.x`, `position.y`, `rotation.z` for each of 256 groups, plus marker `position.x`. It delegates existing accessor setters/getters or wraps own writable data properties, records the old and accepted new values, and retains descriptor cleanup callbacks. The renderer wrapper records entry/exit, preserves `this`, arguments, return value and the original exception; its diagnostic log cannot replace a thrown renderer error. Installation, initial mount renders and the local-control activation/reset all have `phase: 'setup'` and are excluded from frame-window assertions. The shared `stop()` marks `phase: 'teardown'` immediately before `arm.dispose()`: unmount root passes and any later checkpoints stay in raw events but are excluded from the final frame's counts and reported separately in `teardownEventCounts`. Observer accessors alter object shapes and the extra logging changes execution, so **all variant durations are invalid for comparison** even when value ordering passes.

The patch leaves both original timer expressions in place and inserts `begin(epoch, updateStart)` immediately after the first, and `end(epoch, publishEnd)` immediately after the second. It observes input before snapshot replacement, snapshot after replacement, every `getSnapshot` read, each listener callback entry/exit, `App` entry, `Position`/`Rotation`/`FrameMarker` render after `useSyncExternalStore`, reconciler synchronous root render/commit entries, and R3F `commitUpdate` entry for the mapped motion/marker objects. The unique bundled `mu(t,r,a)` entry has the same execution-context/dispatcher/fresh-stack signature as pinned `renderRootSync` ([bundle line 8942](../2026-10-22-native-frame-publication/proof-canvas-v3/dist/react/assets/react-Dn0IWIE6.js#L8942), [pinned source line 10445](../2026-10-22-native-frame-publication/proof-canvas-v3/inputs/installed-store/react-reconciler@0.34.0_react@19.3.0/node_modules/react-reconciler/cjs/react-reconciler.production.js#L10445)); bundled `Cp(t,r,a,l,c,d,h)` matches pinned `commitRoot` by its seven arguments and finished-work lane/child-lane body ([bundle line 9138](../2026-10-22-native-frame-publication/proof-canvas-v3/dist/react/assets/react-Dn0IWIE6.js#L9138), [pinned source line 10839](../2026-10-22-native-frame-publication/proof-canvas-v3/inputs/installed-store/react-reconciler@0.34.0_react@19.3.0/node_modules/react-reconciler/cjs/react-reconciler.production.js#L10839)). The original `clock.dispatch` and R3F host writer remain the operative implementation. Every event includes `kind`, `sourceAnchor`, `epoch`, `phase` and `atMs`; writes add `id`, `field`, `previous`, `value`. The renderer wrapper verifies zero draws in the original update window and exactly one ordered shared draw after `publishEnd` for each epoch, separating retained property commits from GPU/matrix-world rendering. A queued microtask and zero-delay task after `publishEnd` record explicit event-loop checkpoints; any later observed React work/writes remain labelled `after-update` or by the next frame, rather than silently disappearing. The per-frame summary reports all after-update event kinds/counts and their first/last timestamps; `getSnapshot` reads are reported by phase without asserting they all occur inside the timer. The collector exposes raw `events` and `summarize()` on `window.__reactBoundaryAudit` for Luna's separate runner to serialize after `window.realtimeHarness.done` settles and before closing the page.

For each of the 72 frames, `summarize()` reports the original timer window, warmup (`1–12`) or measured (`13–72`) cohort, counts, unique write targets and posttimer checkpoints. It independently checks one input/snapshot, zero `App` entries, 257 listener entries/exits, 257 leaf renders, one synchronous root-render entry and one root-commit entry, 257 mapped host `commitUpdate` entries, 769 unique scalar writes, and one renderer entry/exit after publication. A root count mismatch is a finding rather than a hidden second-pass assumption; no per-fiber traversal is instrumented. `getSnapshot` counts are descriptive and may include postpublication checks. These are **expected from source, not presumed actual**: a mismatch is a finding. The dispatch, listener, subscribed-leaf render, root-render/root-commit, mapped commit and property-write events must be timestamped within the original update window; renderer events must follow it. Every observed property must change exactly once from the epoch `e−1` formula to epoch `e` (the marker follows `e−1→e`); duplicate, missing, late or wrong writes produce explicit violations. The original 256-object graph/value/pixel/identity/disposal proof still runs through the copied asset; its receipt and this ordering summary are both required to interpret the result. `status: PASS` would establish this bounded frame's ordering and completeness under instrumentation, not explain 0.70 ms, prove no unobserved React work anywhere, or qualify an uninstrumented timing.
