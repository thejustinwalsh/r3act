# Installed HMR boundary

The replaced mechanism is an ambiguous plugin chain that could classify one TSX module both as native and as React Refresh input. The public `nativeReactPlugins` composition owns source-derived membership before React plugin construction. The native plugin and semantic-plan registry retain revision authority; the application owns root and borrowed-resource lifetimes. This fixture adds no identity, accepted-view or version registry.

The contract is conservative. A native module revision invalidates its old plan and may remount through a Vite full reload. Before remount, the app disposes the native work queue, DOM and Three roots, React island and caller-owned borrowed geometry/material. The receipt must show zero old owners, pending changes, Three resources and event registrations, balanced React body lifetimes, and no stale pending reveal. A pure React panel edit should update via React Refresh, preserve its local counter and leave the native roots and Three object count intact. A file changing native classification requires the integration plugin to restart Vite and reconstruct the filters.

The source basis is `examples/installed-scene`, `implementation/2026-10-19-installed-scene/prepare-build.mjs`, its browser conformance receipt, and the 19 October async-recovery checkpoint. The copied app keeps the real shared World/Store, DOM/Three Suspense, grouped reveal, native events and controlled Radix React island. Its extra revision strings are exact temporary edit targets. The `main.tsx` pagehide/HMR disposal receipt survives a full reload in same-origin session storage; it does not imply visual atomicity or React commit coordination.

The measured budget is one 90-second headless browser behavior run after an untimed fresh installed build proof, plus one Native-first fresh-process production build pair at the completed slice boundary. The matched counter entries each render a main heading, increment button and count output using one `useState`; native uses the public composition helper with source discovery while React uses the ordinary React plugin plus React Compiler. The untimed pair proof requires actual native numeric binding/semantic revision and React memo output, then the one-shot pair must match its transforms and assets. Build timing includes process startup and may use warm caches; HMR latency is not a performance gate here. The falsifiers are a double transform, missing native invalidation, stale old owners or resources, a React edit that replaces native roots, React state loss under Refresh, a new root that inherits an old pending reveal, a missing compiler output, or any timed source/transform/asset drift. A failure is preserved and does not authorize repeated favorable performance samples.
