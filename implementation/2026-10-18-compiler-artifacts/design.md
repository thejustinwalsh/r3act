# Compiler artifact provenance and selection

Source basis: c6a1af9. This is master-plan Unit 9's packaging/portability seam, following the verified resource-subtree boundary. The replaced mechanism guesses a packaged executable from Node OS/CPU and records neither an actual Rust target nor its protocol or binary hash. Both current package builders need one manifest selection contract; historical package names, private imports and frozen evidence stay unchanged.

A Rust `--compiler-info` mode identifies the compiled Cargo target, Node-compatible OS/architecture, crate version and native protocol version. Each package builder captures that info, hashes the executable and exact Rust/Cargo source inputs, preserves executable mode and writes a target-labelled artifact manifest beside compiler files. The JS Vite plugin selects a compatible artifact, validates path confinement, size/hash and executable info, and fails clearly before starting an incompatible packaged compiler. Installed packages never use consumer Cargo as recovery. Explicit compilerBinary remains a caller-supplied override; checkout development still uses its existing Cargo path.

The package manifest and actual executable are the artifact authority; compiler source/site/module revisions remain the semantic authority. This adds distribution provenance, not another runtime identity/version/publication registry. One native build does not establish other OS/CPU/ABI support. Linux libc differences must be checked or conservatively declined. Manifest claims are local integrity metadata, not a cryptographic publisher trust guarantee.

Falsifiers are executing a mismatched or modified packaged binary; accepting path escape, ambiguous selection or unsupported protocol; silently falling back to Cargo from an installed package; mislabelling a stale host binary after target configuration changes; breaking executable mode/source maps/shared runtime identity; or changing native transform/site/revision output merely by adding info. Node/Rust/toolchain paths are discovered or supplied deliberately; frozen historical manifests are never rewritten.

Sol medium agents own disjoint Rust info, package builders, and Vite selection files. Primary reviews interfaces and owns consumer verification, adversarial fixture source and documentation. Luna stays idle until integration review, then runs consolidated frozen correctness/tooling/compiler/host/installed-consumer gates. The boundary comparison is one bounded matched installed Vite build per native/React arm, including compiler/plugin startup and bundle bytes; no server/browser or favorable retry. It is descriptive setup-cost evidence, not runtime latency or cross-platform qualification. Existing runtime performance receipts retain their original source bounds. Cold/retained-memory budgets and independent-device product qualification remain open.
