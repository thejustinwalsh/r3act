# Authored async recovery slice

This slice exercises a compiler-authored native resource view across DOM, a forked DOM root, and Three. The application starts with an accepted value, queues a replacement that rejects, renders the declared error view, starts retry resources, cancels a superseded attempt, ignores its late settlement, permits urgent Store updates, and disposes pending work early. The browser comparison uses the same provider inputs and output with React Compiler, React `use(promise)`, Suspense, an ErrorBoundary, and `startTransition`.

The replaced mechanism is an earlier success-primary cache that could resurrect old content after a rejected replacement. The invariant authority remains the existing resource identity, root publication and queue capability model. The replacement resource is passed in queued tree props; cancelling that queue intent cannot undo a separately dispatched Store action. The urgent Store remains independent. A rejected scoped resource must fail selection and release its hold; the generic boundary can then publish an error. Queued and direct retries retain the accepted error while pending under the current recovery contract.

The compiler execution fixture is `compiler/native_async_recovery_execution_test.mjs`. It uses the existing debug compiler executable without rebuilding it, writes the actual Rust/OXC transform and provenance under `.cache/compiled-async-recovery-*`, imports the emitted module, and checks actual DOM/Three/fork behavior. Its selected rejected-resource subcase asserts the declined scope leaves the generic error visible. It does not claim that arbitrary error renderers are compiler-proven closed expressions.

The comparison lives in `comparison/`. The build script creates a source lock and captures the compiler, native/React transforms, and exact Vite assets. The browser verifier replays only those assets offline in a bounded headless browser, checks behavior before reporting one Native-first settlement-to-MutationObserver pair, and preserves failures. Proof builds and behavior validation are separate from the sole timing invocation. No server or external network is required.

The one pair is descriptive prepaint scheduling evidence. Its falsifier is a wrong visible state, stale publication, lost urgent update, leaked owner/resource/subscription, source or asset drift, or failed exact output comparison. A pair cannot establish CPU cost, paint, tails, cold or retained memory, equivalent bundle size, host-wide visual atomicity, second-device behavior, or a general React speed claim.
