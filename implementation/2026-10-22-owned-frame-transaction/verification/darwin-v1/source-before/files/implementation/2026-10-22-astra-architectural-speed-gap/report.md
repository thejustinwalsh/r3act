# Execute the compiler-proven frame as one transaction

22 October 2026. Architectural review requested by the human, using the evidence-first skill. **Conditional recommendation: replace repeated generic reader staging and phase traversal inside the existing ordinary immediate scalar route with one owned batch representation and two complete mounted-target validation sweeps.** Keep the same publication core, accepted histories, retained VDOM, compiler proof, host writer and generic fallback. This is one integrated vertical change, not another arithmetic/cache/copy patch.

This is a concrete implementation candidate, **not a demonstrated fix for the milliseconds gap**. No safe source analysis can promise parity. Its removable time and new overhead are unknown. The existing capture-contraction slice must finish its boundary first; it has not run any gate or timing at this review. If it achieves parity, do not dispatch this speed slice. If it fails correctness, repair that slice first. If it passes correctness and still loses, dispatch the three packets in [orchestration.md](orchestration.md), then evaluate the complete change once.

[source-basis.json](source-basis.json) hashes analyzed files. No runtime source, tests, benchmark, build, server or shared checkpoint was changed or executed by this review.

| Through common draw/readback | 5.10 / 6.60 | 4.25 / 6.60 | 6.50 / 7.50 | 4.90 / 6.60 |

Native needs 1.55 ms / 62% less median update time and 2.00 ms / 60.6% less p95 time **if that episode's React denominator were held fixed**. These are target distances, not removable phase budgets. Nothing in the source establishes that the proposed deletions occupy 62%. Counts, sampled profiles, old/new episodes with varying React totals and subtraction of interval medians cannot establish that claim. Through-draw includes shared inspection, rendering, pixel readback/allocation and checksum; it is not presentation. Current dirty source inherits none of these timings.

The authored scene really changes three scalar props on each of 256 motion groups and one epoch marker: 769 changed scalar writes, with 770 frame slots because the marker also has a constant name. Both declarative arms retain the same structural objects, children and 512 geometry/material resources. `value(epoch) = epoch`; there is no repeated-value bailout hiding these updates.

I inspected the actual installed transform and delivered bundle in `../2026-10-22-compact-scalar-output/proof-canvas-v1`, not a hypothetical React implementation. Pins are React/React DOM 19.3.0, Compiler 1.0.0, reconciler 0.34.0, R3F 10.0.0-alpha.6 and Three 0.186.1. Generated Position/Rotation use `_c(8)`: activation closure/dependency-array memoization occupies three slots; all three changing arithmetic expressions execute, then changed outputs create a new group element. Stable child elements survive. FrameMarker uses `_c(2)` and changes each epoch. App's static element graph is cached and App does not subscribe to the clock. Native already avoids those owner bodies, activation reruns and child reconstruction on its closed route. **Missing React-style component memoization is not the demonstrated Native gap.**

R3F `reconciler.tsx::commitUpdate` validates, checks reconstruction, calls `diffProps`, replaces the instance prop snapshot and calls `applyProps`. Delivered bundle `react-DWlubxoR.js` contains the actual diff and scalar assignment path. There is no layout-effect host mutation shortcut in this arm. React's clock is a frozen snapshot plus a listener Set; Native's `AsyncStore` also maintains chronological actions, per-root accepted reader history, holds and publication failure semantics. The comparison matches visible authored interaction, not every transactional promise. That asymmetry must be stated; it does not invalidate a normal-user comparison or justify losing indefinitely.

The useFrame arm uses actual pinned update-phase jobs, ref mutations, a render takeover and manual advance. Its update interval includes scheduler work. It does not run React reconciliation for every frame callback. Its slower observation cannot be generalized to all R3F or used to replace the faster declarative baseline. The imperative loop is a different obligation set, not a same-contract lower bound.

## Current path and the exact remaining excess

The source now does the following. Names refer to the hashed worktree, not old line numbers in the historical master-plan inventory.

1. `AsyncStore` dispatch updates current state/log and notifies Root. `flush` and `#tryFlushClosedStores` capture notification generation, choose unheld subscribed Stores and preserve the partial/generic progress decision. The selected clock reaches all motion readers; sparse selection cannot turn this into a small output set.
2. `#prepareClosedInputCandidate` captures explicit dirty local cells; `#stageClosedStoreOutputs` selects live readers/owners and reuses each accepted shape's bound inputs. `prepareOwnedClosedStoreOutputs` captures canonical World cells and distinct Store/path values and calls the already verified emitted numeric kernel per row.
3. World captures rows, then Root flattens `inputCellWrites`, combines them with explicit writes, and `createClosedWorldCellCut` descriptor-copies and deduplicates these runtime-created captures again. For mixed local+Store updates, selected cells can additionally be captured first by `#captureRetainedCells`. The whole semantic cell cut is necessary; the second conversion is an adapter cost.
4. `StoreRenderTransaction._readOwnedClosedProjectionBatch` captures once per Store/path but builds generic `#readers` singleton Sets, `#pending` maps containing `directReaderCut`, and `#values` observation objects for every direct reader. These are candidate staging structures. Final `#readerValues` histories in AsyncStore are a different, required authority. Savepoint journal closures are **already omitted** without an active checkpoint; deleting alleged per-frame journal closures would be a false optimization.
5. Root stages accepted frames/templates/shapes and regions. VDOM `#prepareStorePropDelta` resolves live keyed targets, builds candidate-local bucket membership proofs and creates successors. The quadratic peer proof is already gone. Root and VDOM frames are already compact, and the dirty slice removes the verified intermediate value array and warm throwaway input records. Do not redispatch any of those changes.
6. `#createCandidateLifecycle(spec, true)` already avoids the deferred public facade. It still drives generic `validate`, `commitAdmitted`, `publish` closures and their full validation callbacks. `prepareScopedKeyedRetainedAndStoreDeltas` builds a composite program with empty structural/retained parts even when only owned Store images exist. Six full VDOM target sweeps remain, plus per-write guards.
7. `#applyCheckedStorePropDelta` compares aligned slots, journals accepted mounted state, invokes the existing host writer in original row/prop order and updates mounted image pointers. `three_host.ts::setProp` retains custom/event/resource behavior; generic numeric fields use its existing property resolver. Final Store/Root/VDOM publication and exact acknowledgement happen through the same lifecycle before notifications.

Required work: discover actual affected readers; capture fresh source identity/version/value and action cutoffs; evaluate changed outputs; retain immutable accepted output; apply 769 changed writes; preserve live ownership/resources and callback behavior; publish each participating reader's accepted history; clear only captured actions. Current per-root history cannot become one shared Store version. The proposed removal concerns **how many temporary descriptions and complete checks implement those obligations**, not whether the obligations exist.

## Selected end state

The complete ordinary frame path should be:

`dispatch → select/prove compiler rows → capture one World cut + Store snapshots/direct-reader rows → evaluate existing verified kernels → prepare existing VDOM target record → public preflight → final private admission → existing host application/per-write checks → public post-host preparation → final private acceptance → existing accepted pointer/history/ack publication → callbacks`.

All steps remain synchronous main-thread work. No worker, async DAG, adaptive traversal selector, global execution registry or direct Three assignment API is added. The existing compiler expression DAG continues to perform local CSE. Cross-owner arithmetic fusion is deliberately absent: alternating Position/Rotation rows have distinct local offsets, while the computation is tiny and surrounding coordination remains. A new heterogeneous kernel/interpreter would not by itself delete that coordination.

**No new compiler metadata schema is required.** Closed host schemas 5/6/7 identify ordered Store use sites/paths, local state sites, effect sites, retained child, host key/tag and prop expressions. Execution schema 2 supplies revision-associated arithmetic whose actual source is proved against those expressions. Existing `definedComponents`, normalized execution associations and `ComponentCache.output.shape` provide provenance. They cannot certify the absence of future host callbacks; phase-local admission still must do that. Do not widen the numeric verifier or invent a compiler-issued “trust me” boolean. An actual Rust/OXC compiled fixture is required to prove selection through normal TSX.

### A. Compact candidate reader state inside StoreRenderTransaction

Introduce a discriminated **storage mode of the existing transaction**, not another transaction object or accepted-history registry. Canonical empty direct-reader capture can hold one ordered, uniquely keyed reader row per ID, referring to its existing Store snapshot. This replaces the simultaneous singleton Set, pending-marker map entry and observation object. Keep Store snapshots, root pins, projection result sharing and mutation discovery under their current authority. Store/path deduplication must retain actual source/path identity and independent reader IDs; equal projection values never merge readers.

General operations materialize the generic representation once, from the same captured snapshots, without rereading current Store state. A read-only `readers`/`observations` request may materialize its returned view without changing accepted state; mutation/checkpoint entry converts the transaction permanently to generic mode before operating. There must never be two live mutable representations of the same staged reader state. Default/public/general transactions retain current behavior.

At `#stagePublication`, compact rows produce the existing `PreparedReaderValues` and distinct `AcceptedReaderHistory` entries. Keep `_prepareReaderValues`/`_publishPreparedReaderValues` as the single accepted-history authority; factor their common direct-reader staging internally instead of maintaining a second publisher. Do not share one history object across readers or replace accepted receipt identity with the Store head. Pre-/post-host stamp rules stay exact/current versus lineage-with-newer-actions.

### B. Produce the authentic World cut during canonical capture

The private `_captureOwnedClosedInputs` already reads actual cell identities/versions through the owning World. Have this capture also produce the existing opaque `ClosedWorldCellCut` and a deduplicated cell sequence; do not serialize its rows out and descriptor-normalize them back in. The public `createClosedWorldCellCut` remains defensive for supplied arrays/handles. Only the canonical producer can use the internal constructor; no `owned=true` argument, frozen-object test or caller array adoption qualifies.

Pass the authentic cut beside output rows through `prepareOwnedClosedStoreOutputs` and the existing ClosedStoreOutputCut. Ordinary clock-only frames consume it directly. Mixed local+Store admission may use it only if every explicit dirty handle is found with exact owner/site/incarnation/source/version in the captured cut and every required local input is included. Otherwise retain the current combined-cut path. Keep exact dirty action acknowledgement separate from the complete dependency read set: unchanged local inputs must not accidentally clear newer pending setters. Reuse the producer lineage for Root publication; no second owner lineage registry.

### C. Coalesce phase traversal in the already-shipped immediate core

Add a private, source-controlled validation strategy to `CandidateLifecycleSpec` for the authentic owned scalar case; do not add another lifecycle/state machine. The existing phase variable, candidate holds, host domain claim/barrier, AcceptedMountedJournal, quarantine, release, notifications and disposal code remain the only owners. `ordinaryImmediate` is already implemented: the new work is inside its validation strategy and the VDOM program adapter.

For this strategy, split observable/public preflight from complete private target validation. Canonical method audits may avoid invoking canonical wrappers, but any overridden method that the current route observes must continue to be observed in the same logical pre-/post-host phase. A host Proxy's descriptor/prototype operations can execute code even when `setProp` is a data property; run those before the private sweep. Plain/frozen shape is not proof of non-Proxy identity. Root's VDOM counter bridge only increments its private counter Map; the public profile counter is delivered at `reportFlush`. Standalone VDOM users can supply arbitrary callbacks, so the specialized internal entry cannot infer their passivity.

The narrow case has two complete VDOM target/bucket sweeps: inside existing admitted commit after pre-host public work and journal setup, and immediately after post-host public work/staging. This is a proposed source-work count, not milliseconds. Exceptions/overrides may keep the conservative six-check strategy. Per-write target checks and the application-end pointer sweep remain. No escaping admission witness or skip-validation API is needed: keep the existing complete private VDOM check inside admitted commit (endpoint 4), after Root admission (endpoint 3).

## Six validation endpoints: exact disposition

| Current endpoint | Selected internal scalar strategy | Reason and hard condition |
| --- | --- | --- |
| 1. Tail of `#prepareStorePropDelta` | Build the same complete record without the tail full currentness sweep; it cannot escape as a public usable token. | No host mutation occurs. Endpoint 4 must validate every construction invariant before use. Public `prepareStorePropDelta` and generic/composite callers retain endpoint 1. Any fallible preparation callback remains before the final private checks. |
| 2. `core.validate → spec.validatePrepared → program.validate` | Perform public callback/audit preflight and cheap lifecycle checks; defer the full mounted scan to 4. | For the internal candidate only, `validate` is immediately followed by admitted commit on the same Root stack. No candidate escapes. Public validate semantics are unchanged. Source/World/Store overrides go through conservative validation or are called before the final private sweep. |
| 3. `preHostPrivateCurrent → validatePreparedPrivate` | Keep complete private Root/code/reader coverage and captured World/Store checks after the last public callback; the VDOM portion is deferred to 4. | Reject stale owners, membership, code, holds and direct intent. Root admission is followed only by existing internal claim/barrier/journal setup before VDOM admission. |
| 4. Scoped `commitAdmitted → commit` after `beginPublication` | **Keep the existing complete private VDOM target/bucket sweep**, with the active-publication predicate, immediately before application. | Between 3 and 4 only existing internal claim/barrier/journal setup and phase bookkeeping may execute. `tryClaimHostPublicationDomains` has no callbacks; `beginPublication` creates the journal but does not serialize it. If a new callback appears here, Root admission must run again after it. No externally callable skip-check operation is introduced. |
| 5. `preparePublication → validatePostHost` | Keep observable writer/method checks, Store reader-history staging and error behavior; defer the full target scan to 6. | Host writers have run arbitrary code. Do not reuse pre-host currentness. Public post-host methods can reenter and must finish before 6. If a public override requires generic transaction observations, materialize from the captured cut first. |
| 6. `finalPrivateCurrent → finalGroupCurrent` | **Keep one complete private post-host sweep** after all public work, then enter the existing callback-free accepted publication. | Validate applied VNodes, lineage, code, membership and root lifetime. Newer Store/local versions are permitted only by existing after-host semantics; exact old acknowledgements survive. |

**Never merge the pre-host checks with 6. Never remove `#isStoreTargetReady`.** Each host writer is an arbitrary callback. Its guard freshly checks the writer/target/placement/retained children after host descriptor lookup; later target invalidation is still caught by subsequent guards and the final complete sweep. A partial write followed by failure remains quarantined, not replayed. No claim is made that every custom setter sees globally current host objects or that physical writes roll back.

This is unavailable to explicit groups, deferred candidates, generic callbacks, structural replacements, resource/selector cuts, legacy public regions, compiled binding graph or unsupported lanes. They keep the original strategy. If an override appears during host application, **continue post-host conservative checks on the same cut**, never fall back by redoing host application. A stale result after any write is terminal under the existing rules. A successful conservative completion publishes the same captured old cut; later input work stays pending.

## Budget, falsifier and stop

There is no measured budget for the removable pieces. The whole relevant latest gap is the 1.55/2.00 ms update median/p95 distance above. New costs include the transaction-mode branch, lazy promotion, private strategy selection and changed JIT shape. Root/VDOM staging and actual host writes remain output-linear. Cold setup, retained memory, GC and independent-device performance remain unqualified.

Acceptance requires all semantic/delivery/lifecycle oracles, source review proving old work is absent on the selected path, then one unchanged four-arm comparison. Two target sweeps with zero generic reader staging on the complete canonical clock frame is the mechanism oracle. It is not a performance result. If it still misses same-run declarative parity, report the exact miss and stop this candidate; do not append a range kernel, another cache or host bypass. The result may establish that the stronger normal frame contract remains too expensive on this workload, but one episode cannot prove impossibility.

Historical Snake wins, qualified dense DOM failure, exhausted Recording A/physical HOLD, equal-preload async parity and zero human maintenance participants remain scoped to their original evidence. No new causal ledger is a prerequisite for this authorized semantic integration. Broader structural/async UX, cold/memory, package/host and independent-device obligations remain. This review gives a bounded next implementation, not a universal React-superiority claim.
