# Owned closed Store execution: one viable semantic boundary

Read-only strategy review of production HEAD `04b7757e606de235f228ee4f9966f39e28feb2e1`. No product edits, tests, builds, benchmarks, browser, server or VM execution occurred in this review. The report files were created only after primary released the separate frame-baseline correctness freeze. Source identities are in [source-lock.json](source-lock.json).

## Decision

**Yes, a bounded runtime-owned computation/capture capability is coherent.** Add an explicit data-execution alternative, reuse the existing normalized expression evaluator, and capture the complete eligible Store request set inside one synchronous private operation. Preserve legacy schema-1 `executeRange` behavior exactly. This is a semantic execution boundary enabling heterogeneous affected-owner work to prepare without authored executable callbacks; it is not proof of a faster physical plan or general DAG fusion.

The new arm must actually contain only normalized data. Calling the existing generated function through a brand, revision token, cached canonical flag or renamed method does not meet the contract. A data plan does not certify an arbitrary component body, World override, Store selector, resource method or host writer as pure.

Select at most this one follow-on after the independent useFrame comparison closes. It is the concrete execution/effect prerequisite left open by the previous Astra report, not another cache within its closed contraction slice. Existing layouts, callback ordering on legacy paths, live admission and publication remain. If the private segment cannot be implemented without crossing an unclassified public call or bypassing an override, keep the conservative route and close the attempted batch capability as unsupported. Do not add an interpreter, JIT, global interning, persistent canonical-status cache, new traversal family or residual-timing program.

## Minimal executable contract

Use a distinct metadata field, for example `closedStoreExecution: { schemaVersion: 1, kind: "owned-data", componentProgramId, moduleRevision }`. Its authoritative expressions and input order are the associated normalized `closedStoreHostProgram`; do not duplicate them in another graph. Registration descriptor-copies this marker, checks exact fields/identity/revision, requires a supported data shape, and stores only its normalized result in the existing component registration. Reject simultaneous `closedStoreExecution` and `closedStoreNumericKernel`: precedence must not silently suppress a manually supplied callback.

This marker selects an implementation that never invokes a supplied executable. It is safe to accept manually authored **data** under that explicit contract, after complete normalization. It does not establish correspondence between a manual component body and its claimed host plan; retain the existing metadata author's responsibility and compiler whole-owner proof boundary. The actual compiler must emit the marker only from its existing proven closed owner forms, from the same source/revision. Opaque helpers, getters, escaping captures, unsupported controls and child bodies acquire no new proof.

The first admitted batch grammar is deliberately finite: numeric leaf/wrapper forms already admitted by kernel 1, plus the existing schema-5 empty-child scalar marker with its primitive static name. Support mixed Store/local schema 7 through the same evaluator using `closedStoreHostValueCount`, preserving Store-path order followed by local-site order. The retained child is carried unchanged; its body does not execute. No new operators, aggregate values, subtree/text traversal, resource inputs or automatic transaction grouping enter this batch. Broader existing schemas keep their established routes.

The compiler ceases emitting callback kernel code only for owners selected into this new data arm. Old kernel 1 remains accepted and executable. New-runtime registration permits schema 7 with exactly one supported execution alternative. Older runtimes must either reject the unsupported mixed form before mounting (current schema-7 registration already does) or use an already equivalent conservative data path for older shapes; they must never interpret the marker as a permission to skip validation. Installed compatibility proof must record this behavior rather than assume a new marker is recognized everywhere.

Evaluate rows and props in their current logical order; keep existing finite-input/output rules, `Object.is` behavior and arithmetic grouping. The data evaluator may perform repeated expression traversal that the generated DAG kernel currently avoids. This loss of generated CSE/inlining is a real new cost, not a promised win. No cross-owner common-subexpression elimination, vectorization or arithmetic complexity reduction is claimed.

## Passive capture contract

Prefer one whole eligible batch over a resumable audit permit. The operation consumes data requests, performs its integrity checks, captures/stages all reader observations and returns values. There is no `trusted: true`, user callback parameter, public begin/end scope, or reusable audited-store token.

1. Root selects from existing private owner/cache/reader records. Eligibility preflight must itself be passive; any uncertain registration, output provenance, resource input, legacy kernel, selector or opaque reader sends the **whole selected batch** to the existing per-owner route before execution. This avoids moving a legacy callback relative to adjacent capture. Existing external input normalization remains outside the passive segment and preserves its getter/exception behavior.
2. For local inputs, use a small World-internal canonical capture returning existing immutable handles, exact sources, versions and primitive values. Admission must reject subclass/Proxy receivers and own/prototype overrides of every method whose public call it replaces, before bypassing them. Private brand checks precede reflection that could consult a Proxy. Use private committed cell identity; never trust caller-supplied handles by TypeScript shape. Preserve exact incarnation and source `value` data-property checks. Unknown World variants use the conservative per-owner route with their original public calls.
3. Root records the complete ordered Store requests and local captures into candidate-owned arrays. Use exact owned normalized path identities. Copy any caller-shaped request container before the Store audit; all Proxy/descriptor activity must finish first. Registration/cache/props/output/child references are captured from existing owned records or normalized before the segment, then checked against current private authority. Frozen external objects are insufficient provenance.
4. One Store-owned operation audits shared `AsyncStore.prototype` integrity and every distinct participating instance after all potentially observable normalization. Its unchecked capture subroutines remain private lexical/class functions. They read private log/root-version/epoch/transition state, traverse branded paths through `storeRecord` values, and stage the existing per-reader membership, direct history, observation and savepoint journal. They do not call public `beginRender`, selectors, reducers, overridable accessors, or the public per-reader method recursively.
5. Initially admit a fresh, Root-created transaction and selected canonical Stores only. A transaction containing earlier opaque/generic observations, noncanonical snapshots, or a mixed owner whose unselected Store requires accepted-reader preservation keeps the current route. This avoids silently widening public `StoreRenderTransaction` or held-reader semantics. Independent unrelated held work can remain pending; overlap/lease checks still apply. A later widening is not part of this slice.
6. The Store operation ends on return. No integrity fact from it authorizes later work. Root evaluates only copied normalized expressions and numeric arrays, builds the existing owned scalar deltas, and runs all existing current-owner/source/code/reader/hold checks. Any VDOM/host preparation callback remains outside this passive operation and retains its subsequent live checks.

The source proof required for audit sharing is concrete: all request normalization occurs first; private brand checks exclude proxies; class/instance audits occur next; the remaining call graph contains only private capture, owned primitive/data traversal and transaction bookkeeping until return. Under that proof, one shared class audit and one instance audit per distinct Store suffice **inside that one operation**. This is a proposed contract, not an observed current count. It is not one audit per frame: public validation, accepted-reader inspection, host preparation and post-host publication checks remain independent. The old 515 count cannot be relabeled as one.

`StoreRenderTransaction` currently has publicly accessible `readonly` root/options fields, and snapshots expose TypeScript-readonly fields. An internal operation must use constructor-owned captured values/private snapshot state or prove exact own data fields before the last audit. A cast, frozen function metadata or method binding does not close this detail. Root-owned fresh transactions simplify this proof; the public method must still reject hostile receivers/inputs without exposing a bypass.

## Retirement, lifetime and fallback

| Retire only on eligible data batch | Retain / new cost |
| --- | --- |
| Per-owner public `executeRange` calls and contiguous-run bookkeeping | Existing recursive primitive evaluation, input capture and every affected value decision; possible loss of generated CSE/JIT shape. |
| Kernel eligibility's redundant per-owner canonical Store audit and per-reader audit within the single private Store operation | One operation-local distinct-Store collection and integrity sweep; later live/public audits stay. |
| Kernel-only output buffer/count/extent validation when no public writer can populate that buffer | Owned evaluator output checks and candidate-owned prop values; no weakening of kernel-1 checks. |
| Repeated canonical projection snapshot setup within that operation | Existing pinned snapshots, per-reader histories, projection memo and savepoint behavior; no second accepted history. |

Batch request arrays/owner rows are candidate scratch, cleared on success release, decline, discard, failure and disposal. Immutable expression metadata lives with the existing component registration and revision lifetime. No persistent per-Store canonical-status table, owner index, new source version, accepted-value mirror or cross-frame projection cache is added. Captured Store registration side effects use existing uncommitted-root cleanup. Decline must not leave staged readers or suppress/replay external callbacks. Existing checkpoint rollback continues to restore reader observations while pinned snapshots retain their present documented lifetime.

If one selected reader is legacy/opaque or one capture is noncanonical, the whole selection follows the current order and public checks. New data owners can still evaluate one at a time on that conservative route; this needs schema-7 data evaluation, not a synthetic callback masquerading as legacy kernel 1. Unsupported data input/output then declines to existing generic rendering under its repeatable/non-speculative contract. Do not execute opaque bodies speculatively merely to make fallback convenient.

Host code, VDOM current-target scans, writer generations, per-write reentry checks, full-tree replacement guards, final private group admission, old accepted reads during applying, exact acknowledgement, fork/held history and failed-partial quarantine remain unchanged. No check is moved across a writer. No host callbacks are batched or declared pure.

## Counterexamples that must remain observable

* A manual kernel increments a counter, dispatches a newer Store action, mutates `AsyncStore.prototype`, retires another owner, changes a World method, throws, or writes Infinity. Existing tests already retain exact kernel identity/call offsets and nonfinite fallback. A data marker or matching revision cannot legalize suppressing these calls; mixed batches must keep their order and fresh audits.
* A later World override changes an earlier Store or destroys an earlier cell. Bypassing that override is wrong; the passive route must reject the World and preserve the original path. A returned Proxy handle is not owned data.
* The last metadata/request Proxy trap mutates the first Store prototype. Auditing before all request copying is unsound. A frozen Proxy remains a Proxy.
* The same owned projection plan is used by two roots with different accepted frontiers, or a held unselected input has a retained reader receipt. Same Store identity is not same accepted snapshot; initially keep these mixed cases on existing capture.
* A host preflight getter or the second root's public validation invalidates the first root. Capture integrity is not publication admission; final private all-member checks must reject before writes/acceptance as before.
* The first host writer dispatches a newer action or retires the second target; the second writer throws. Preserve exact old-cut ack/new pending work, target-local checks, old managed history and quarantine. An effect-free computation does not make host application rollbackable.

## Finite acceptance

This review permits primary to consider one separately recorded semantic slice. Source review must demonstrate the new data-only call graph and actual retirement before gates. One consolidated correctness boundary and one installed proof/comparison may evaluate it under the existing human cadence after the frame comparator unit closes. Do not run per-helper timings or reopen Recording A. Preserve the comparator's distinct declarative, useFrame and imperative contracts.

Failure to establish passive capture, preserve manual callback behavior, retain exact history/lifetime semantics, or retire the named per-owner callback/audit work closes this proposal. A correct implementation that still loses is a negative performance result, with no rescue cache, alternate evaluator, container or repeated timing selected. Primary must separately decide whether the semantic capability merits retention given the added route and evaluation cost. Broader fusion and the full product evidence remain incomplete either way.
