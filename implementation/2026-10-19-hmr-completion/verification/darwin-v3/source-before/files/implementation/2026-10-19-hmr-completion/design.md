# HMR completion contract

## Generic progress behind a declared resource hold

Proof-v2 reached actual installed rendering and equal counter clicks, but the independent dialog Store could not open the React portal before the declared resource group settled. The root's publication-intent barrier admits closed Store/scalar cuts and blocks generic Store/tree work. Opening, removing and reinserting this opaque island are part of the retained authored sequence; settling the resources early or initially opening the dialog would evade that requirement.

The integrated extension replaces that whole-root scheduling stop only for an eligible generic candidate that retains the held boundary's accepted subtree. The candidate still replaces a whole tree/cache and must retain strict root and VDOM bases. Existing resource selection/leases, owner incarnations, module revisions, Store transactions, accepted caches and publication receipts remain authoritative. The retained branch must have unchanged owned child/fallback/control descriptors and the same resource/host/owner identity. It transfers accepted owner/effect/cache and reader/subscription lifetimes without executing the held branch. Independent opaque owner rendering keeps the existing generic contract; no imported callback becomes a compiler purity proof.

Only consumed unheld inputs may advance or be acknowledged. Changed held inputs or boundary footprints conservatively park the latest direct intent until the hold releases; an old prepared group must reprepare against intervening root publication. Replacement resources retain accepted primary UI while pending under the existing Suspense policy. Removed island owners retire, reinsertion allocates a new lifetime, host failure preserves old managed history and newer host-time actions survive. Final validation follows callbacks, with private callback-free checks before acceptance. No whole-root version check, accepted history or generic fallback may be deleted.

The falsifiers are premature A reveal while B waits, stalled independent dialog work, a stale accepted cache overwrite, lost held/newer action, wrong fork history, changed held source admitted as fresh, retained removed island state/ref/effect, callback-bearing final acceptance, or partial host failure advancing accepted history. The new runtime corpus and actual installed HMR sequence must pass a refreshed consolidated boundary before the one build observation. Generic traversal and retention costs remain unqualified; this is not a claim of general structural locality or visual atomicity.

The replaced mechanism is the earlier installed HMR consumer's offline-only proof and optional invalid-edit verifier. The invariant authority remains the compiler's module revision/instance, the runtime's existing owner/source/publication receipt, and each root's accepted history. This harness adds no mutable identity or version registry. A native edit first proves the new source can compile; a failed source remains an overlay against the accepted old app. A valid edit sends invalidation for the exact prior revision/instance and permits Vite's full-page reload. A React-only edit uses the ordinary React Refresh boundary and preserves the native roots.

The required behavior is: equal initial and clicked counter output; actual native and React dev transforms with the correct plugins; React local count retained without navigation or native root replacement; old accepted DOM, Three, pending reveal and island still live during a rejected native syntax edit; old pending work cancelled and owners/resources released on a valid revision; fresh DOM/Three state; and empty final owners, pending changes, scene, portal, Three handles/listeners, React effects and borrowed-resource lifetimes. The browser records WebSocket frames, navigations, stage snapshots, source hashes, overlay text, exact errors and cleanup closure. It does not claim cross-renderer visual atomicity.

Preflight covers parsing and Rust semantic rejection for a tracked native module. Imported dependency syntax, runtime execution and later third-party transforms are outside that guarantee; failures there may still surface during reload. HMR latency and the added edit-time parsing/compilation cost remain unmeasured.

The source basis is the current `compiler/vite_native_module.ts` HMR hook and `compiler/vite_native_plugin.ts` public composition, `src/native_runtime_api.ts`, the current module-level const-arrow lowering, `implementation/2026-10-19-installed-hmr` frozen receipts, and the same shared-store scene authoring. Historical paper/notebook HMR checks cover earlier private or explicit-remount workloads; they do not certify this installed package graph. The preparation lock binds current package report source hashes, five tarballs, copied consumer/harness source, selected installed files, compiler bytes, production transforms and assets. The browser checks that lock before and after its temporary edits. The pair binds its one-shot authorization to all three completed receipts.

The measured budget is one 90-second headless/GPU-off browser behavior run and, after source-locked untimed proof and primary release, one bounded Native-first build pair. The falsifiers are an invalid edit that retires accepted owners or cancels pending work, any unrelated browser error, missing React Refresh state, a React edit that reloads native roots, missing exact native revision invalidation, retained old owners or resources, a new root inheriting old pending output, compiler plan/revision disagreement, a non-generic Native counter plan under current source, missing React Compiler output, or source/transform/asset drift during the timed pair. Any failure remains archived with its exact evidence and gets a new proof directory after correction.
