# Host contract and reveal slice: verification plan

## Scope and evidence limits

This is a semantic slice from local `main` at `1689595`; the 18 October first-pass results do not qualify the changed source. The implementation contract in [`design.md`](../design.md) keeps existing World, Store, resource, owner, boundary, compiler revision, writer lifetime and accepted publication authorities. The intended first supported reveal case is an already-accepted fallback for stable boundary B. Its fallback and primary each normalize to one compatible keyed host element. B's observed resource settles and reveals a primary containing one resource-reading child, with no Store reader, effects, numeric binding or collection region. A may be a previously revealed sibling whose Store switch makes its next primary pending. A's accepted host subtree must remain in place, and B must reveal without reading or acknowledging A. Unknown/shared resources, unaccepted candidates and changed boundary, owner or host shape remain on the generic full-root path.

No performance advantage is presumed. Any browser timing here is one manually settled Promise diagnostic, not the historic network-DAG recording or async UX qualification. The interval measures promise settlement to committed visible B content. It does not measure request start, waterfall avoidance, presentation/paint or user input latency. No worker, data-layout experiment or per-helper timing is in scope.

## Optional single descriptive pair

The candidate harness in [`../benchmark/`](../benchmark/) uses authored Native TSX through Rust/OXC and authored React TSX through the installed React Compiler/Vite plugin. It mounts two independent boundaries per arm. A starts revealed from a ready resource; B starts in its accepted keyed fallback. Native wraps B's controlled Promise once in a direct `AsyncResource` during mount and passes that same object to B; React reads the equivalent Promise directly. The workload switches A's Store to a second pending resource and verifies that A keeps its original DOM node and accepted text. It then resolves B's Promise and records settlement-to-visible-primary duration while A's new resource is still pending. B's fallback and primary use the same host tag/key. The exact compiled program and React memo transform must be visible in the build proof. Final observable text must match between arms, and the A primary host element must retain identity across B's reveal.

This is one trigger per arm with no warmup or sample selection. Install a MutationObserver before resolving B; time through its first callback that sees B's primary, so the interval includes observer delivery delay and stops before paint. Sample timer quantum outside the interval. Preserve both raw intervals even if one fails. Report each interval and their descriptive difference only when both arms complete the same observable transition; do not convert the result into p95, latency qualification or a ratio claim. The page records initial mount and final disposal separately, along with boundary text, fallback/reveal state, A's retained element identity, whether A fallback was inserted, computed A visibility samples, exact source/artifact hashes, browser version, timer quantum and any page or console errors. Verify both roots dispose and leave no child DOM; preserve resource cleanup. Keep A pending through B's reveal, then dispose before resolving its unused Promise.

The page is headless Chromium, GPU disabled, 1200×900, with a 90-second hard interruptible deadline and no focus stealing. Reuse the reviewed offline production-asset replay pattern: serve only exact manifest assets through Playwright routing at a synthetic HTTPS `.localhost` origin, abort every unmanifested or external request, and make no network/TLS connection. Do not start a project server, Portless proxy or modify trust state. This does not test live transport. The Promise is manually controlled and cannot replace an equal-network-DAG or async UX gate.
