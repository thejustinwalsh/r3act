# Native platform verification and delivery

Source basis: 609333c. This Unit 9 slice replaces machine-local verification commands and Darwin-specific lifecycle fixture data with one source-locked native-platform runner, an isolated Linux execution route and native CI jobs. Cargo's actual target, executable info, binary/manifest hashes, installed consumer and unchanged product inputs remain the authority. No runtime identity, publication, traversal layout or semantic version registry changes.

The runner checks actual Node OS/CPU and compiler target, performs frozen dependency installation and consolidated runtime/compiler/host/package checks, preserves failures and exact command outcomes, and archives actual compiled fixtures plus installed-package evidence. A stale target, host Node binding copied into Linux, missing evidence, failed check or source drift prevents PASS. A configured job is not evidence that the hosted job ran. Each runner produces a separate native single-target artifact; their existence does not make a tarball multi-platform.

The user requested Apple container tooling with its storage on Depot. The Linux route uses Apple container 1.5.0 and its ARM64 per-container VM; installation and native execution must be verified before releasing the gate. The container route reads checkout sources through a read-only mount, copies the required product inputs into owned Linux storage, installs native dependencies and builds native Rust output, and writes only a new evidence directory. No ports, project server or browser are used. CPU/memory/time limits and owned-container cleanup bound the workload. Shared images, containers, routes and historical cache evidence must not be removed or overwritten. Base image/Apple runtime/toolchain identities and the actual source hash inventory are recorded.

Local Linux ARM64 execution proves that operating-system/ABI installation and execution case in a VM on the same physical machine. It does not establish another CPU architecture, a hosted CI run, independent-device replication or cross-host visual atomicity. CI is configured for explicit Darwin ARM64 and Linux GNU ARM64/x64 identities using the currently documented GitHub runner labels, and must assert those actual identities. Windows remains unsupported by this POSIX conformance route until its executable/mode/blocker fixtures are implemented and verified.

Sol medium agents own the platform-aware fixture, shared receipt runner and CI/container source separately. Primary reviewed the integrated source and released consolidated Darwin correctness to Luna. Linux execution remains unreleased until Apple service setup is verified. Consolidated verification includes actual Linux package compilation and fresh installed consumption, not synthetic target metadata alone. One bounded native-first installed Vite build comparison runs on Linux at the boundary using a reviewed source-locked protocol. Required proof builds prime filesystem caches; fresh-process timing is descriptive, without cold-cache, runtime, tail or independent-device qualification. No physical optimization budget is selected; the dense FAIL and exhausted Recording A remain unchanged.

Falsifiers include silently skipping a failed or unavailable platform, relabelling emulated/VM execution as independent hardware, launching an unowned container/server, executing the wrong-target binary, accepting mismatched source or package hashes, losing fixture/failure artifacts on container cleanup, or modifying the read-only checkout and frozen historical evidence. The full master-plan finish line remains in force, including async UX, cold/retained memory and independent-device gates.

Runner label reference: [GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), checked 18 October 2026. Labels describe the configured jobs; receipts must prove the actual runner.
