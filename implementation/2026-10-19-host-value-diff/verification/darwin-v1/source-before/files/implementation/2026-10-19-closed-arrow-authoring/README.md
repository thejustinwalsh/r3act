# Closed const-arrow authoring proof

This unit replaces the function-declaration-only closed-proof gate for a finite set of module-level synchronous `const` arrows. The authored fixture is `compiler/fixtures/native-closed-arrow-authoring.tsx`; its actual Rust/OXC transform is inspected and executed by `compiler/compiled_closed_arrow_authoring_test.mjs`. Existing component/site IDs, module revisions, Store reader history, owner state, resource versions and root publication receipts remain the authorities. No parallel identity, version or publication registry is introduced.

`HeldDom` and `HeldThree` read canonical Store A before their resource and return finite DOM/Three hosts. Their multiline JSX indentation and comment containers must elide without text nodes. A concise `ForwardHeldDom` carries the existing closed forwarding proof. `NumericCounter` has an output-only numeric local-state prop and must emit the existing numeric program; it makes no interactive numeric-update claim. Significant inline space, captured callbacks and lexical `this`/`arguments` remain generic and execute with their JavaScript meaning. The fixture also checks an independent Store B and local state during the held group, a separately scheduled fork's accepted output, latest-A joint reveal, changed Store/local resource selection rejection, unchanged-selection admission, exact revision retirement, late stale-resource suppression and final owner/reader/host cleanup. The two resource leaves must have schema-5 Store-A-first/resource-second metadata from the compiler, not fabricated metadata in the fixture.

The installed consumer uses the same authored arrow leaf, forwarding and generic dialog forms with DOM, Three, Radix and a React island. The matched React arm preloads the same two deferred values and keeps the dialog outside Suspense. Both arms update the dialog's local state while the group remains pending; that one host attribute change is the timed episode. The pure numeric arrow is checked for emitted provenance and stable mounted output but is not used as a benchmark trigger. React Compiler memoization is required for the interacting `App` and `DialogSlot`, with actual `react/jsx-runtime` output. The two arms do not claim identical package graphs or cross-renderer paint atomicity.

The protocol archives the package-build report and its source hashes, five tarballs, selected installed package files, compiler bytes, authored fixture/test, consumer/harness source, transformed modules and production assets. Every phase checks input hashes. `run-build-pair.mjs` builds Native then React without timing. `verify-browser.mjs` serves only the hashed production assets through offline HTTPS request interception, without a project server, Portless route or VM. It runs headless with GPU disabled and a 90-second deadline, records phase checkpoints and preserves errors and cleanup failures. An untimed full behavior proof must pass before the primary writes a hash-bound `run-authorization.json`; only then can one Native-first matched interaction pair run. These timings describe a single local update delivery, not a speed, CPU, tail, paint, cold-start or memory qualification.

The primary chooses a new proof directory path; `prepare.mjs` creates it. Luna executes the commands after source review, current compiler/package build and the consolidated correctness gate:

```sh
node implementation/2026-10-19-closed-arrow-authoring/prepare.mjs --proof-dir implementation/2026-10-19-closed-arrow-authoring/proof-v1
node implementation/2026-10-19-closed-arrow-authoring/run-build-pair.mjs --proof-dir implementation/2026-10-19-closed-arrow-authoring/proof-v1
node implementation/2026-10-19-closed-arrow-authoring/verify-browser.mjs --proof-dir implementation/2026-10-19-closed-arrow-authoring/proof-v1 --phase proof
node implementation/2026-10-19-closed-arrow-authoring/verify-browser.mjs --proof-dir implementation/2026-10-19-closed-arrow-authoring/proof-v1 --phase measure
```

Failures keep their exact receipts and logs. The falsifiers are a false closed proof, changed arrow initializer/lexical semantics, elision of meaningful text, extra whitespace children, stale resource publication, lost reader/fork/owner history, changed or unverified installed inputs, an unproven React memo path, unexpected browser errors, incomplete teardown or an unbounded run. Previous held-reader and arrow-unit evidence keeps its own scope.
