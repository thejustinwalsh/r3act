All members had passed the strict private grouped admission before the first write. The newer action belongs to the next accepted cut; it must not invalidate the already admitted captured group.

`prepareStores` alone now opts into an admitted-continuation validator when it produced an owned scalar phase. The existing bound group claim and its touched-domain state select that validator only for a later member after an earlier member entered host application. Before any write, grouped admission and the first member still require the original exact prepared validation. Legacy callback/numeric programs and other lifecycle consumers retain that rule. The later owned-data member runs the existing VDOM owned-phase writer preflight first, then rechecks its unstarted VDOM targets through the private prepared validator and canonical Store and World lineage. Root rechecks lifecycle after the validator returns, so such a trap cannot retire code or dispose the later root and then enter its host application. The public program validator is not invoked after application began; post-host VDOM validation remains reserved for programs that have actually committed.
