# Sol A source handoff

The native compiler transform now registers its clean absolute input with Vite through `this.addWatchFile(absolutePath)`. The call follows native candidate classification, the configured React boundary checks and the project-root check, and precedes helper registration and Rust compilation. This replaces the implicit assumption that project-root crawling or a requested module alone makes the native input a live watcher member. It does not explain the historical three-directory failure, whose exact cause remains unknown.

The existing native HMR regression now captures `addWatchFile` calls from actual plugin transforms. A queried native request must register exactly its query-free source path; ordinary React TSX, a `?raw` request and a marked outside-root candidate must not register a native source. A syntax-invalid native transform must retain the source watch before its compile error, and the repaired transform must register it again. Existing assertions for old revision/instance invalidation, full reload, retained accepted view on invalid edits, imported helper traversal, React Refresh and explicit accept boundaries, superseded edits, React/native boundary restart and compiler shutdown remain in place.

Source review: the compiler still derives native trust from static/resolved runtime imports and keeps the same helper/component and root checks. The new watch call neither creates a registry nor changes revision, instance, publication or HMR message authority. The relevant exception order is classification and root rejection, own-input watch, helper/runtime watch, compilation, then successful revision bookkeeping. Thus rejected sources create no own watch, while a compiler failure leaves the input observable for repair. I have not run tests, builds, browser or server work under this assignment.

Proposed Luna commands after primary integration review, from the repository root: `node --experimental-transform-types compiler/native_hmr_revision_test.mjs` and `pnpm check:native-tooling`. Include the former in the single consolidated frozen correctness gate and use the unit's bounded workbench proof for live Vite watcher membership and HMR delivery. Falsifiers are a missing exact source in the live watcher after `server.transformRequest`, registration for a declined/outside source, loss of invalid-edit old-view retention, or wrong revision/instance invalidation and reload.
