# Packet C compact scalar Root handoff

Packet C replaced `ComponentCache.result`/`expandedResult` and the parallel `closedStoreOutputShape` field with one discriminated `ComponentCache.output`. The ordinary arm owns authored/expanded RuntimeNodes; the scalar arm owns an immutable producer frame, distinct authored/expanded templates, expanded validity and the bound shape. `cacheOutputView` is the explicit ordinary adapter. Generic expansion, sparse/numeric/structural commits, Suspense, keyed output maps, collection overlays, resource reveal and HMR retirement now read or replace that one output. `PreparedRender.result` is unrelated and remains unchanged.

The passive Store route now keeps one mutable candidate-private preflight row per owner in order, with its exact reader ID, prop, Store source and membership captured once. Bound warm inputs reuse the accepted immutable input records. `prepareOwnedClosedStoreOutputs` returns images at those same row indices; staging attaches the image's cell cut directly to that preflight row, checks resource holds and coverage, and puts the same row in the candidate owner map. It deleted the second passive owner Map, the passive input and cell reconstruction arrays, the duplicate staged-by-region wrapper objects and the passive branch of the generic live-reader loop. A warm row checks its cached scalar layout and aligned values, or validates the entering ordinary element, then carries `frame` directly in a frozen `OwnedScalarStoreRegion` to the existing VDOM candidate. It caches no ordinary props or authored/expanded elements. Validated authored/expanded templates and static bound shape are reused on warm frames; the VDOM successor plan lives once in the accepted output rather than causing another shape copy. Retained authored and expanded children stay distinct. Legacy schema 1–3 programs take the existing closed tuple fallback with no owner render. A keyed parent that needs an ordinary child view gets it during preparation, before host application. Publication installs the scalar output only after the existing candidate has accepted, and invalidates ancestors explicitly. Store/World/resource currentness, after-host checks, exact acknowledgements, blocked-reader witnesses, newer reentry, forks and fallback paths were not removed.

The three opt-in counters are `store.scalar-output.frames`, `store.scalar-output.root-materializations`, and `store.scalar-output.prop-materializations`. Producer counts are caller-owned and folded into the existing flush map; explicit Root cache materializations count through the same map. Public `update`/`render` now uses a temporary map only when profiling is enabled and no outer map exists, restores the old map before leaving the direct host domain, and emits after a successful host-domain exit. No callback runs during the passive batch or inside the materializer. Timing-disabled runs allocate no counter map.

The new Deno test checks cold plus warm frame counts, zero unobserved Root/prop materializations, stable host identity and historical snapshots, then positive actual generic Root materialization. The existing mounted scalar test now asserts frame and Root counts while retaining all prior assertions. The new actual Rust/OXC fixture uses compiler-emitted schema-2 arithmetic and real marker registration, checks 257 compact rows and zero ordinary warm materializations, public generic observation, applying snapshots, newer host-time action, independent roots, HMR retirement, bounded GC and same-key peer removal. Its peer check now uses authentic compact frames through the VDOM composite candidate. Cold VDOM before-images count as real additional frames; warm rows count one producer frame each.

Primary review should inspect the complete Root cache crossing and the new direct render counter boundary before releasing Luna. Suggested frozen commands for Luna: `deno test --frozen -A src/native_compact_scalar_output_test.ts src/native_mounted_scalar_plan_test.ts src/realtime_store_progress_test.ts` and the repository's existing compiled fixture command with `compiler/compiled_compact_scalar_output_test.mjs` added to the runner manifest. Packet C ran no tests, typechecks, builds, benchmarks, browser/server work or Git commands. The source change makes no performance claim. Falsifiers are any warm ordinary materialization without an actual ordinary observer, stale generic/keyed/HMR output, a changed saved snapshot, lost newer action, invalid accepted history or retained removed host/resource.

Final Root source review also found that invalidating a scalar ancestor must drop the old expanded child as the prior `expandedResult = null` did. `invalidatedOutput` now keeps the authored template and frame, replaces the expanded template with a header-only value, and clears the mounted plan. Passive staging rejects invalid expanded output before reading its child; generic expansion reconstructs the view.

The Store-progress prerequisite now uses the exact blocked-reader receipts already stored on pending resource subscriptions to build candidate-local parked boundary state. It pins accepted boundary/owner caches and lineages, verifies current resource/Store stamps, all accepted subtree reader histories and ancestor controls, and repeats these checks through final publication. A generic candidate can retain that one blocked healthy branch while publishing an independent opaque sibling. Successful parked-only generic publication marks an unchanged notification generation handled by its validated wait; the blocked reader's accepted history remains retained. Explicit publication-intent holds retain their former acknowledgement rule. Resource settlement, replacement, reader/source change, props change, owner retirement or HMR invalidates pre-host parking and requires ordinary generic work. A newer Store action or recognized resource settlement during host application may publish the old cut under the Store's canonical after-host lineage, while queuing resource retry and withholding notification acknowledgement. The added Deno case dispatches a ready Health replacement from the Scene host write and requires the old Health output to survive that cut before a later retry shows the replacement. Same-Store opaque sibling and resource wake regressions remain falsifiers; no new registry or accepted-history authority was added. This source extension was not tested by Packet C.

The final after-host guard also accepts a newly queued local cell action in the parked subtree only when its committed cell capability, owner and version still resolve canonically; it accepts newly retained ancestor Store receipts only with unchanged reader membership and root epoch. Both mark the existing retry flag and leave the old Health output and Store reader history accepted until the later cut. The new bounded Deno case drives those actions from Scene host writes, checking that the Scene edit publishes the old Health value and subsequent resource-ready retries publish the local and ancestor values. Before host, the no-local-change and current-ancestor-reader rules remain exact. Unsupported or revoked identities still fail closed. Packet C authored but did not execute these tests.
