## Selected representation: immutable values, ordinary views on demand

The vertical migration has three parts, delivered together. It changes the internal representation of the existing accepted output, not the source, owner, version, publication or dependency authorities.

**1. One compact scalar frame per owner/candidate.** Introduce a private owned value image containing a reference to the normalized immutable output layout and a complete fixed-order primitive value array, including literal props. Copy the verified kernel results into this image before scratch reuse; validate finite numbers and all supported scalar kinds. Store no previous-image pointer, mounted node, root, live World source or callback in the image. Static prop names, slots and constants belong to the normalized execution/layout, not each frame. The existing public tuple-returning helper remains a compatibility adapter; the internal owned producer returns this image directly. Public or forged records still normalize/decline as today.

The image is **the accepted scalar value**, not a mutable latest-value cell. Candidate, Root output and VDOM target may reference the same immutable image. Store input history remains separate because projected output cannot reconstruct input history. Per-root caches and candidates still have independent accepted images. A saved public snapshot retains its immutable values after arbitrary later updates. No delta chain accumulates across frames.

**2. Replace eager Root cache output fields on this path.** Replace the cache's raw `result`/`expandedResult` pair with an explicit internal output representation: ordinary tree output, or owned scalar output plus captured authored/expanded templates. Generic producer and consumer behavior remains ordinary RuntimeNode. Use centralized authored/expanded materializers at generic consumers, not JS getters on `ComponentCache` that `...cache` would accidentally invoke every frame. Root's warm scalar path reads the scalar variant directly and carries one candidate row from selection through capture, evaluation, validation and publication. It does not materialize RuntimeElements, construct the `passive` result Map and then rebuild another owners/input map, or compare outputs via `expanded.props`.

Templates contain the tag/key/component owner and the **distinct** authored/expanded child references captured under current guards. A materializer produces the same runtime-owned, frozen ordinary element/props shape using existing JSX ownership authority when required. Memoized views, if retained, live on that immutable image/template instance and only memoize derived data; they are not a latest-output registry or accepted-version authority. At most one view per role is retained for an observed image. Do not materialize an entire root or unrelated subtree.

Generic fallback must see the newest *accepted* scalar image, never the original mount output. All cache output reads and writes in the table below must migrate. A tree-producing replacement installs ordinary output and releases scalar templates/recipes. An ancestor whose expanded output is invalidated retains its current authored representation with an invalidated expanded status. It must not resurrect an earlier scalar frame. Root requested `#tree` remains separate.

**3. Let the mounted scalar target consume the same image.** Within the existing Store-delta record, carry output layout plus immutable old/new images rather than tuples plus a duplicate previous-props dictionary. Current node/key/owner uniqueness still comes from the existing candidate bucket index. Keep a small exact-VNode successor capability; reuse static layout/child facts rather than copying all fields into another shape record. No persistent key→owner/node registry is added.

Use an explicit privately authentic internal scalar-element variant containing header, child references and the scalar frame. Do not add JS getters to RuntimeElement, ComponentCache or VNode props. Generic mounted-element consumers cross a named materializer; the journal and children-only clones preserve the variant directly. Keep this internal union separate from the public VNode union and explicitly convert at public snapshot/ordinary tree boundaries. Private-field authenticity must not treat arbitrary frozen objects or public accessors as safe. Public snapshot serialization emits ordinary own data props with the existing public shape. **Do not leave stale ordinary props beside a second current-value field.** There must be one authoritative accepted value image; a plain prop object is solely a derived view of that exact image.

`AcceptedMountedJournal.capture` must retain the old immutable owned scalar shell/image directly. Its current generic `{...acceptedVNode}` must not receive the new private variant; the generic path keeps its current snapshot copy. `cloneMountedElementVNode` must preserve an owned scalar image when changing children only, and convert to ordinary output when changing props generically. `publicElementSnapshot`/`serializeMounted` materialize the captured image, including the old image during applying or quarantine, not whatever is currently mounted. Per-write checks retain exact node/VNode/parent/handle/writer/children and publication identity. Generic replacement and same-key remove/reinsert invalidate old capabilities as before.

This is a broader integrated simplification than a new helper cache: it removes the intermediate tuple output and duplicate row description on the internal route, replaces the Root's eager accepted-output pair, replaces VDOM's repeated scalar prop copy, and adjusts all observation/fallback consumers in the same slice. Do not land a producer that adds a compact array while still eagerly constructing every old representation downstream. That would add cost without completing the migration.

## What not to change in this slice

The compiler already emits a finite verified arithmetic function with CSE support. The three expressions here have little repeated compound work within an owner. Reordering all Position rows before Rotation rows or identifying equal local offsets is not justified by this trace. Main-thread batching in this slice means one ordered captured output batch and shared normalized layout, not workers, promises or a new DAG interpreter. Broader fusion remains a later source/alias/effect decision where there is actual shared computation to retire.

Do not reduce public/prototype validation, remove per-write checks, change Store action semantics, collapse forks into latest state, replace immutable snapshots with live views, or bypass the Three host. Do not add explicit app opt-ins or manual per-frame refs to qualify the benchmark. Do not alter DOM/canvas cadence or infer coherent groups from shared ancestry. Explicit groups retain their current publication contract; independent roots remain independent.

Keep unsupported selectors, opaque inputs, mutable vectors, aggregate props, legacy kernels, lane cells, structural/resource composites and ordinary generic authoring on existing paths. A compact scalar image is admitted only where the current owned scalar proof already succeeds. Unverified kernels retain interpretation and existing fallback. The migration must support all currently admitted scalar arities/literal kinds, including the schema-5 frame marker; it must not be special-cased to motion components or three props.
