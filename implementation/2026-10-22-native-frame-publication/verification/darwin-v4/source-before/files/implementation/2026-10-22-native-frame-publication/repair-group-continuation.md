# Grouped Store continuation repair

The frozen first gate passed the existing Store and queue phases but failed the new compiled two-root frame fixture on its second Store frame. Luna's bounded diagnostic traced `Native root candidate is stale` to `commitHostInternal` rechecking the second admitted member's exact prepared Store version after the first host writer dispatched a newer action on that shared Store. All members had passed the strict private grouped admission before the first write. The newer action belongs to the next accepted cut; it must not invalidate the already admitted captured group.

`prepareStores` alone now opts into an admitted-continuation validator for an authenticated owned Store-only cut, whether represented by compact scalar frames or privately marked owned props. The existing bound group claim and its touched-domain state select that validator only for a later member after an earlier member entered host application. Before any write, grouped admission and the first member still require the original exact prepared validation. Unsupported callback, structural and resource programs, and other lifecycle consumers retain that rule. The later owned-data member runs the compact phase's writer preflight or the generic owned program's public validation first, then rechecks its unstarted VDOM targets through the private prepared validator and canonical Store and World lineage. Both preflights use host descriptor/prototype reflection; a Proxy host can run a trap during that lookup. Root rechecks lifecycle after the validator returns, so such a trap cannot retire code or dispose the later root and then enter its host application. Post-host VDOM validation remains reserved for programs that have actually committed. No identity, version, claim or admission registry was added.

The new Deno regressions cover a shared Store action and a mixed local input interleaved between members, original accepted output and later work, strict pre-first-write invalidation, writer, owner, code, and root-lifetime revocations, and a Proxy reflection trap that retires later-member code after the first write. Packet A ran no tests, builds, servers, or benchmarks. Luna's Darwin v2 full gate is preserved under this unit's verification directory; it exposed four new-test failures while the prior suite passed. The compiled fixture remains the separate delivery oracle.

The v2 source review found the continuation phase was unreachable from explicit `prepareStores`: its owned-scalar selection required `internalCellCapture`, which that route does not set. Selection now accepts that route's existing `groupContinuation` opt-in while retaining every other eligibility guard and the internal-only immediate return contract. The v2 grouped fixtures also replaced a host writer after mount, violating their own captured writer identity; they now arm a stable host subclass callback after mount. The mixed fixture used `data-x` on a `group`, which the closed host schema rejects, and now uses supported `position-x`. The reflection fixture now proxies the prototype of a branded memory host so its descriptor trap remains observable without breaking private-field methods. None of these fixture repairs relaxes admission or post-host checks.

The v2 frame test retried `advance` after a terminal writer failure, reaching a quarantined root. The frame controller now retains the failed publication receipt and error; later manual advance returns that same failure and start throws it without rerunning update or enqueueing the root. Other callback failure and draw restart policy is unchanged. These source repairs have not been executed by Packet A; Luna should run the consolidated successor gate after primary review.

Luna's Darwin v3 Deno gate passed 1304 tests and failed two new continuation fixtures. The mixed schema7 fixture and failed-frame latch test passed; the compiled frame fixture also passed. Source review showed both remaining fixtures used the common schema1 `output` helper. Schema1–3 passive rows materialize privately marked owned props rather than scalar `frame` regions. The first continuation implementation required frame regions, so these tests remained on the generic admitted path: the shared-action group failed, and the reflection trap fired after the later writer. The schema1 fixture is retained as the regression. The continuation gate now accepts both frame regions and authenticated owned Store props after the same no-write, no-resource, no-collection eligibility checks. The generic program's public `validate()` checks the captured writer and mounted targets before private target and canonical after-host Store/World lineage validation. Its public reflection can invoke Proxy callbacks, so lifecycle and identity checks follow it. Strict all-member admission and first-member checks remain unchanged. Generic structural and non-owned Store routes remain conservative.

The v3 source audit reported a mismatch because `Object.freeze` was added to the failed-publication latch after the primary released the gate; the primary identified this as an orchestration timing error. The mixed-source v3 run does not qualify a source snapshot. This broadened owned continuation and the frozen latch need the next complete reviewed gate. Packet A has run no tests, builds, servers, or benchmarks.

Unknown cost is the extra private target and lineage validation on an admitted later Store member. Falsifiers are accepting a removed or replaced writer/owner, acknowledging a newer action in the captured cut, drawing a mixed group, or bypassing strict admission before first host application.
