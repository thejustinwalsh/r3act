# Packet C Deno oracle repair after Darwin v1

Darwin v1 preserved two Deno failures; the new `native_owned_scalar_capture_contract_test.ts` stopped at its clock body-count assertion (actual 3, expected 1). All 57 compiled fixtures passed, including `compiled_owned_scalar_capture_test.mjs`. This repair changes only the new Deno fixture and this note. No check was executed.

The failed assertion was made after dispatching a pending Health resource. At that point the generic Outside reader of the same Health Store is actionable while the boundary Health reader is parked. `ComponentStateRoot.#tryFlushClosedStores` can publish a closed clock part, retain the blocked Health reader, and return `partial-generic` when the opaque sibling still needs work. `flush` then reaches the generic branch: `#everReadResource || #everHadNativeBoundary` calls `#renderAndCommit(this.#tree, ...)`. That whole-tree preparation can execute the Clock component body even though its `data-epoch` target remains the same host node and the accepted value is correct. The old fixture conflated a closed-only owner-body bypass with generic progress beside a parked boundary.

The corrected oracle checks zero extra Clock and Outside owner-body renders during a clock-only cut before Health is parked. During the later mixed interval it requires current clock values and target identity, actionable same-Store Outside progress, independent Studio progress, immutable saved snapshots, an old accepted Health cut during host-time Store/local actions, and eventual resource/local wake. The mounted local setter is still captured before suspension. The unchanged `realtime_store_progress_test.ts` remains the broader progress authority.

This is a source-based test-oracle repair, not a claim that Darwin v1 now passes. The other v1 Deno failure in `closed_store_execution_test.ts` is separate and outside Packet C ownership; primary and its owning packet must address it before another consolidated gate.
