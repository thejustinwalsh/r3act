# Browser frame-loop integration

The Three workbench replaces its local `frameId`/`lastFrameTime` RAF loop and marker-equality draw gate with `createNativeFrameLoop`. The explicit frame publication group is the scene root and `frameClock`; DOM roots remain on their ordinary independent schedules. The controller owns the RAF callback and pending queue work. The application still owns roots, Stores, renderer, borrowed assets and disposal. It stops and disposes the controller before retiring roots and resources. A frame draw now occurs from the controller callback after the declared Store group settles, with the marker retained only for diagnostics.

The update callback first flushes the scene root's ordinary Studio work, then dispatches the next clock phase and diagnostic epoch only while playing with motion allowed and positive `deltaMs`. The scene root's default microtask scheduler is restored so generic Studio controls can progress while a frame group waits. Paused and reduced-motion frames keep rendering without advancing clock props. The existing diagnostics retain requested/drawn epochs, marker position, resource counts and HMR teardown observations. The old marker-gate deferral counter is removed with its gate.

The existing root publication receipt, Store reader history and queue determine readiness; no marker or app-maintained frame version authorizes draw. A source review of the current controller and Root confirms a mounted unchanged selected Store can yield a valid no-op candidate with `requireOutputChange=false`; the queue establishes its hold synchronously before the scene root's default microtask scheduler runs. The workbench's prior HMR proof established controls/reset/resource/remount/disposal behavior on its prior source, not this integration. No measured time saving is claimed; queue and callback overhead are unknown. Falsifiers are a draw before group publication, stalled Studio control/reset progress, paused/reduced-motion clock advancement, lost HMR remount or leaked RAF/holds/resources. This packet ran no tests, builds, servers or benchmarks. Primary should source-review and freeze it with A/C before Luna's consolidated gate.
