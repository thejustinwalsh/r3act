# Packet A handoff — realtime Store progress

Owned changes: `src/component_state_runtime.ts`, new `src/realtime_store_progress_test.ts` and this note. No tests, builds, browser, server, benchmark or Git commands have run.

`flush()` returns after any successful `#tryFlushClosedStores` publication. When its complete selected cut declines, that helper may publish one closed clock candidate and return success while an opaque Studio reader still needs a generic render. A fresh clock action before each `flush()` can repeat the partial success and postpone Studio indefinitely. Conversely, a closed clock frame can be partial simply because an unchanged subscribed opaque Studio cannot form a closed candidate; treating every partial result as generic work would rerender the Scene owner every frame.

The proposed authority is the existing per-root accepted Store reader history. Urgent dispatch bumps that Store's root version; `captureCanonicalStoreReaderReceipt` and `inspectCanonicalStoreReaderReceipt` report `current` for an unchanged accepted reader and `retained` when its root version moved beyond the accepted stamp. After a partial publication and its callbacks, inspect fresh receipts for unheld stores whose per-store closed candidate declined. A retained or unprovable reader needs the existing generic fallback; current readers do not. A successful closed Store with a newer reentrant action remains on the closed route. This uses only call-local selection, not a new dirty registry or cached truth across callbacks.

The helper now reports `none`, `complete`, `partial` or `partial-generic` to `flush()`. Complete retains the immediate return without fallback scratch allocation. Partial clock publication remains accepted; when a failed unheld Store has a retained, missing or unprovable accepted reader, `flush()` continues through its existing generic/held/resource route in that same call and carries the partial-published result through early exits. One fresh pass over live reader memberships classifies all failed Stores in O(F + R + memberships), with no persistent registry. The aggregate notification generation advances after partial publication only when its captured generation is unchanged, exact live subscriptions match the selected set, every selected Store was attempted and every failed Store's readers are current. Candidate validation, acknowledgement, newer actions, independent root history, host failures and publication callbacks remain the semantic authority.

The new Deno regression mounts an opaque array-valued control Store reader, a compiled-shape closed clock leaf and a resource boundary. It requires zero generic owner renders on ordinary clock-only frames, bounded control reset progress despite a fresh clock action before each flush, and continued zero generic renders after settling. It then makes generic Scene preparation throw an exact sentinel after a partial clock publication: the error must propagate, the clock epoch must remain accepted, old generic keys and the saved immutable snapshot must remain accepted, and a newer control action must recover. Finally it requires independent closed clock progress while a health resource remains pending. The actual compiled fixture in Packet B covers reentrant clock action and second-root history. Existing Store/held-resource/fork/lifetime tests remain in the consolidated platform gate. Run the frozen consolidated platform gate from the unit design after primary integration review; `deno test --frozen --allow-read src/realtime_store_progress_test.ts` is only a focused failure-isolation command. Darwin-v1 preserved three failures: a host-time newer closed action was consumed in the same partial-to-generic flush, and two pending-health tests gained an unnecessary owner render. The bounded repair defers generic work after partial publication if a callback advanced the Store notification generation. For parked health, an original retained reader is exempted only when its exact boundary-scoped pending-reader ID has a current canonical accepted receipt for the same Store, the native boundary is live with that reader in its subtree, and the same pending resource has a live subscription to that boundary. A newly dispatched replacement Store value advances the root version and makes the pending receipt retained, requiring generic work. Missing, null and retained pending proofs also require generic work; parked original receipts never authorize global generation acknowledgement. This uses one call-local pending-reader map and no new registry.

The Deno regression now also requires an unrelated Studio edit to progress beside parked health, a ready health resource to replace an unresolved old one, and fulfillment and rejection of later pending resources to wake the boundary.
