## Contract and retired mechanism

The new optional @r3act/react-bridge/radix-dialog subpath exports RadixDialog, ReactRadixDialog and RadixDialogProps. The native component uses the existing island adapter; the React view uses the actual Radix Root/Trigger/Portal/Overlay/Content/Title/Description/Close. Open state is controlled through boolean props and onOpenChange; the native author can use a normal Store and declarative props. Title/description are required strings. Children are real React nodes. Modal behavior is explicit; caller-owned portal containers and finite content/overlay styling are allowed. Radix providers/contexts, focus and portal descendants remain inside the React commit domain.

The replaced restriction is having only an unqualified opaque island with no tested selected-library bridge. Existing native owner/ref/publication and React/Radix lifetime remain the sole authorities. There is no new Store/identity/version/publication registry. Native candidate preparation does not mutate React; accepted refs deliver props, and React schedules independently. Portal DOM is outside the private native container but its ownership and cleanup remain Radix/React's. Caller containers and unrelated nodes must survive. Removing a native owner unmounts the island and its open portal; reinsertion has new React state. Pending native work retains its accepted dialog until native acceptance. Whole-tree guards and opaque fallback remain.

The default core and bridge entries do not import Radix. The separate public subpath requires exact 1.3.1 as an optional peer. Both five-package and legacy builder source declare that route; frozen historical legacy artifacts remain unchanged. Fresh five-package consumer verifies identity, types and installed exports. The two native bridge AST proofs share one exact-site/compiler-cleanup helper, retiring the previous island proof body rather than duplicating it. These proofs do not execute React DOM.

## Integrated workload and falsifiers

A compiled native application controls an actual dialog from Stores, local state and resource/suspense updates. A direct React arm uses the same ReactRadixDialog. Source review checks native sites and opaque metadata; actual React Compiler output is reviewed before the single descriptive comparison. Correctness includes controlled opening/closing, actual headless keyboard Tab/ShiftTab/Escape, focus trap/return, aria title/description, caller-owned portals, retained form value/selection/identity through prop updates and keyed move, stale/discard rejection, pending accepted UI, removal/reinsert and disposal while open. The browser must restore portal/body/aria/focus-guard state and leave unrelated host nodes untouched.

Falsifiers are unaccepted props reaching the portal, state loss on a stable owner, escaped portal or modal side effects after retirement, premature cleanup, stale controlled callbacks, false purity, or duplicate semantic authority. One source-locked headless/GPUoff offline HTTPS pair is bounded and interruptible; it starts no project server or VM. Keyboard focus is confined to a headless page. Any server would first require Portless. A synthetic dispatch/keyboard-to-matching DOM observer is not physical input, paint, full accessibility certification, CPU isolation or cross-renderer visual atomicity.
