# Packet A: native frame controller

Replaced application-owned frame callback/readiness scheduling with `createNativeFrameLoop` over one owned `NativeRootWorkQueue`. The controller accepts an explicit root/Store group, freezes each update's time, clamps elapsed time, publishes the group through `enqueueStores`, and draws only after a committed receipt. An unchanged selected Store still takes the accepted scoped no-op path, so paused and reduced-motion ticks can draw. No root, Store, renderer, or action scope is owned or disposed by the controller.

Pending work keeps the original frame and update; another advance refreshes it. A host/resource wake may settle the receipt outside the frame callback, but cannot draw. The committed queue version for each selected root is recorded only with that frame receipt and compared to current root `publicationVersion` before delayed drawing. A mismatch reprepares the same group without replaying update. The queue remains the publication authority; the recorded values are short-lived validation data, not another root version registry.

Stop and disposal cancel the owned RAF and pending work, including a handle returned after a stop inside preparation. A retired participant disposes the controller. Reentrant advances fail before a nested update. A failed host receipt stops scheduled replay and exposes its error in the result and optional reporter; update, draw, and scheduler exceptions stop the loop and preserve cleanup failures. A draw error occurs after accepted publication and does not roll it back or poison the root. The injected scheduler must invoke its callback asynchronously; synchronous invocation is rejected and its returned request ID is cancelled.

`src/native_frame_loop_test.ts` covers manual timing and unchanged Store publication, stale RAF callbacks, grouped roots, newer Store dispatch during host write, a busy host followed by delayed settlement and intervening root publication, stop/dispose and retirement, reentry, failed writer, scheduler synchronous invocation, and original plus cleanup errors. These are authored regressions, not executed results. Luna handoff: `deno test --frozen src/native_frame_loop_test.ts`, then the primary's consolidated native gate and installed consumer checks after integrated source review. No tests, builds, benchmarks, or servers were run in Packet A.

Unknown costs include queue preparation and no-op publication per frame, callbacks and retained holds while waiting, and browser frame cadence. The slice has no measured performance saving. Falsifiers are a draw before the selected group accepts, loss of a newer action, a delayed draw across an intervening root commit, replay after host failure, or leaked RAF/work/holds after stop or retirement.
