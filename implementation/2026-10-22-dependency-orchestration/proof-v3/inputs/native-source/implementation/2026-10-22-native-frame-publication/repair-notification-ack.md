# Closed Store notification acknowledgement

The Darwin v5 integrated HMR check observed `sceneRenderCount` 52 where the existing marker expected 28. A grouped `prepareStores([clock])` accepted the frame clock's host output, but `ComponentStateRoot` left `storeNotificationGeneration` dirty. The default scheduled flush then treated the unchanged opaque Studio Store as work and rerendered the scene. This was a scheduling acknowledgement gap, not evidence of a measured frame-time cost.

The replaced mechanism only advanced `committedStoreNotificationGeneration` when an internal closed flush selected every subscribed Store. An explicit subset publication now audits all live subscribed readers in its postpublication `runEffects` phase. It uses the existing canonical accepted-reader receipt and requires `current` for every Store/read-site pair, complete subscription coverage, unchanged notification generation and reader/subscription membership, and no blocked reader. It then advances the existing committed generation. A retained receipt from a newer host-time action or Studio action leaves dirtiness for ordinary scheduling. The audit allocates only local temporary collections; it adds no persistent identity or version registry and does not suppress state, collection, resource, or direct work.

The new Deno fixtures cover repeated clock-only grouped frames with a default microtask scheduler and an unchanged opaque Studio sibling, a real Studio action that must still rerender, manual scheduling with a newer clock action dispatched by the writer, and preservation of a pending Studio transition projection across a clock-only subset publication. They are authored regressions, not executed results. Actual forked-root history remains covered by the compiled fixture maintained separately by Packet C. Packet A ran no tests, builds, servers, or benchmarks; Luna should run the consolidated gate after primary review.

The additional receipt scan costs one pass over live Store reader pairs after each explicit accepted subset publication. Savings remain unknown. Falsifiers are a skipped opaque Studio update, a lost newer clock action, acknowledgement with a retained or blocked reader, or a repeated generic scene render on unchanged Studio after an accepted clock-only frame.
