The first bounded HMR proof failed before HMR: the scene rendered 52 times for 51 requested frames where the pre-HMR scene-render limit was 28. The public clock group's accepted reader history advanced, but its root retained a global Store-notification generation. A later default-scheduled generic flush then rerendered an opaque Studio scene even though Studio had no new action. This is an observed browser failure, not a performance qualification.

The compiled frame fixture now places an opaque use(studio) scene and the retained closed clock motion in the same Three root. Its authored TSX is transformed by the real Rust/OXC compiler; the fixture verifies the motion's closed Store metadata and the scene's absence of a closed Store host program. The Three root uses the default microtask scheduler. After repeated accepted clock frames, drained microtasks must leave the scene and retained child render counters unchanged. A real Studio action must still schedule a generic scene render and change the host scene name. The prior newer host-time clock action, DOM/Three group, fork history, busy completion, retirement, failed host, and exact Three resource disposal checks remain.

The replaced mechanism is unconditional generic work after a clock-only accepted Store notification. The existing canonical Store reader receipts and root notification generation are the intended authority for A's repair; this fixture adds no notification registry or acknowledgement mechanism. The semantic budget is no scene/child rerender on clock-only frames while real Studio and newer clock actions remain observable. The falsifiers are a generic rerender from clock-only notification, lost Studio update, consumed newer clock action, stale child identity, or leaked Three resources.

This is a source-only Packet C handoff. No tests, builds, benchmarks, or servers were run by this implementation agent.
