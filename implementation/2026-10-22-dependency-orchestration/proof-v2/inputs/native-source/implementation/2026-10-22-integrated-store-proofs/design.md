# Integrated Store proof slice

The human resumed implementation after the React source/boundary/profile investigation and explicitly rejected helper-by-helper benchmarking. This unit implements the reviewed path as an integrated Store/Root/group change, then verifies once at its boundary. No individual timing result decides which helper survives.

## Replaced work and invariant authority

1. Store notification acknowledgement currently captures and immediately inspects one temporary receipt per reader, repeatedly auditing the same Store prototype. A synchronous cohort checks existing accepted histories directly, audits canonical shape once and each distinct instance once, then returns. Its proof expires before callbacks; unknown/custom objects retain defensive acknowledgement. The Store’s existing root epochs, root versions and accepted reader histories remain authoritative.
2. Root currentness currently reconstructs owner-prefix metadata every time. Candidate-owned coverage metadata is prepared once and released with the candidate. Live membership remains checked on every required sweep; no new persistent membership index/version is introduced.
3. Public group publication currently reenters each candidate’s posthost validation from preparePublication. Existing private group receipts can prepare eligible canonical Store publication after required public checks, avoiding that inner revalidation. Nonmutating all-member eligibility must reject custom/accessor methods before phase mutation. Existing last public group validation, final private all-member target sweep and each changed-write readiness check remain. VDOM’s existing private target authority suffices; no redundant VDOM mechanism is added.

The last item is deliberately bounded by actual passivity. Arbitrary host descriptor reflection may invoke Proxy traps. Such operations are never called callback-free merely because the operation is synchronous. Store-only preparation can use captured canonical operations after a fresh intrinsic/shape audit. Any failure after preparation enters follows existing terminal failure/quarantine handling, not generic mid-group replay.

## Required behavior and falsifiers

Exact captured acknowledgement, newer reentrant actions, independent root/fork accepted histories, saved immutable snapshots, live component/code/reader/target identity, opaque/default-scheduler progress, resources and original error preservation remain mandatory. Swallowing newer work, accepting stale targets, changing custom callback order, losing old snapshots, unsafe partial-failure replay or retained roots/resources falsifies the implementation.

The DevTools sample distribution motivates removing duplicated work; it is not a numerical saving budget. No parity forecast follows. One consolidated source/package/actual-compiled correctness boundary and fresh installed proof precede one bounded unprofiled matched minified-production comparison. Historical evidence remains unchanged; this comparison is not a causal old/new estimate against prior unminified episodes. Cold/memory, independent-device and human maintenance claims remain open.
