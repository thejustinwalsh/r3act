# Realtime architecture reassessment — source at `46babf10c`

**Recommendation.** Keep the compiled incremental engine, retained keyed VDOM, and shared identity/version/publication authority already built. Recast the default mounted-frame path as one compiler-certified, single-root data cut: capture owned inputs, execute a prepared row program, apply declared host writes, publish that root's accepted view, and acknowledge exactly the captured versions. Enter the existing group candidate machinery only for an explicit coherent multi-root transaction, structural/resource transition, or opaque work that requires it. This is a coherent integration and retirement decision, not a new runtime or a claim that a quick branch will beat React.

The generic candidate state machine at `component_state_runtime.ts:4900–5210` covers host claims, post-host validation, accepted-pointer publication, and partial-failure quarantine. The architecture should **reuse** these authorities and mounted plans, rather than propose another graph, receipt, output world or frame scheduler.

The October 22 integrated Store slice retired repeated reader audits, coverage normalization and an eligible inner publication wrapper; its source review says VDOM private target authority was reused unchanged. The one balanced, minified production comparison still reports Native/React adjacent-pair ratios of 4.29× update median, 4.00× update p90, 1.84× through-draw median and 1.77× through-draw p90. That is a failed parity observation for this workload, not a measured budget for any proposed deletion. The earlier DevTools sample put sizeable shares in Store proof and owner staging, but sampled stacks are not removable CPU time. `implementation-checkpoint.md` and `implementation/2026-10-22-integrated-store-proofs/results.md` preserve the cold/memory, second-device and causal limits.

## Necessary semantics versus generality on every frame

Keep exact owner incarnation, compiler site/code revision, mounted target/writer generation, root-specific accepted history, captured Store/cell cuts, newer reentrant actions, forks, HMR retirement, resource lifetime, callback order, generic fallback and terminal quarantine after partial host writes. A final live check remains necessary after a callback can revoke a lease. A reused output buffer cannot become an accepted snapshot if a host or observer may retain it. These are correctness contracts, not incidental overhead (`final-master-plan.md` §§5, 17; `architecture-proposal.md`, state ownership and host sections).

The avoidable question is **when** the full machinery is entered. `ComponentStateRoot.flush` (`component_state_runtime.ts:6275`) currently surveys mixed cells, Store generations, resources, boundaries, publication intents and direct work before selecting its path. The ordinary scalar row route itself maintains Root tokens, epochs, buffers, fallback retry and VDOM validation (`:11766`); the Store route constructs grouped schedules and private frame objects (`closed_store_execution.ts:520`, `closed_scalar_output.ts:207–288`). These may be justified for the eligible cases they serve, but should not be presumed the cheapest representation of every RAF frame. Do not delete checks simply because the frame is common: change the *admission proof and data shape* so static facts are settled at registration and only mutable leases/versions are checked at commit.

The present defensive surface also treats overridden intrinsics, public accessors, arbitrary Proxies and custom host callbacks as possible inputs. Preserve documented generic behavior at that boundary. A product choice can make the certified hot path require compiler/runtime-owned, non-escaping records and explicit host capabilities, so arbitrary intrinsic/prototype override semantics do not dictate its inner-loop representation. This would narrow **specialization eligibility**, not silently narrow public authoring or host behavior. It needs explicit diagnostics/fallback and adversarial verification; `closed_store_execution.ts:84–88,118–181` and `closed_scalar_output.ts:20–28` show current canonical intrinsic/ownership defenses.

## One architecture, two publication shapes

At compile/registration time, emit one immutable semantic plan with owner/site/sink identities, dependency footprint, output value policy and writer capability. Certify closed expressions only when hidden reads/effects are excluded; opaque work remains the retained VDOM oracle. Mount resolves the plan to current entities, row slots and host targets. Sparse fanout, bounded clustered scans and dense row kernels are *physical traversals over that same plan and receipt*, selected first by compile-time eligibility; add runtime density choice only after its selection and switching cost is measured. Current row and Store kernels become implementations of this contract, not parallel worlds.

For an ordinary single-root frame, capture versions/values into owned private scratch; compute changed sinks once; stage immutable accepted scalar values or copy-capability values; validate live owner/target/writer and root base after the last user callback; apply host writes; then swap the accepted view and acknowledge only captured versions. Defer notifications/effects until publication. Reentrant setters land in a later cut. If the host throws after partial application, retain old accepted history and quarantine its publication domain. The private scratch may be reused only before publication; accepted values need stable ownership or a proven copy contract. This keeps the existing `#tryCommitNativeRows`, `#executePreparedNumericRows`, `#publishDirectHostMutation` and `#acknowledgeNativeCellCut` concepts, but should converge their duplicated capture/validation/publication plumbing with the Store path only where source review proves the same invariant.

For explicitly coordinated roots, use the existing `publishPreparedNativeGroup`/candidate lifecycle (`component_state_runtime.ts:382,4900–5210`) and `NativeRootWorkQueue`. Its all-member final checks, host-domain claims and pointer swaps define a coherent declared group. Forks outside that group may retain different accepted versions. Avoid a second frame world that later has to reconcile with this authority; a single-root cut should be the one-member receipt case with a smaller physical representation. Cross-host paint atomicity and rollback of arbitrary custom setters remain outside the promise.

## Lessons and migration boundary

React Compiler plus subscribed R3F leaves is a serious comparator: the measurement audit found 257 leaf renders, 257 R3F commits and 769 correct writes inside its timer, while App did not render. Its fast interval is real for that boundary; drawing is separate (`implementation-checkpoint.md`, React measurement audit). The useful lesson from fine-grained/subscription approaches is to keep invalidation close to consumers and batch one frame, while compiler-static plans can avoid per-leaf component work where proved. React's preload matched the earlier async DAG completion, so the differentiation is explicit readiness/conflict/reveal control, not automatic network speed. Fixed-topology Snake wins show a dense compiled lane can work; the qualified dense DOM and current canvas parity failures show it is not a general conclusion. No source here proves another framework cannot match the target.

Make one integrated migration slice: (1) specify the certified closed-cut ABI and host copy/retain capabilities using existing identities; (2) route the ordinary mounted single-root RAF/Store/scalar cohort through one capture, execution and acknowledgement pipeline, retiring named duplicate schedules/receipts only after semantic parity; (3) keep generic VDOM, async/resource and explicit group routes as the correctness boundary; (4) verify exact snapshots, forks, reentry, HMR, target reuse, resource disposal, fallback and partial failure, then run one consolidated same-output production comparison. Do not add a plan cache, mutable version registry, output pool, container carousel or helper-by-helper timing campaign. If the full update and through-draw result still misses the gate, attribute the remaining cost before another physical choice. Product decisions to settle explicitly are certified-subset eligibility, immutable/copy value semantics for custom hosts, and which multi-root operations require a coherent group; none is silently changed by this review.
