# Astra repair plan from the Native DevTools trace

**Native already uses the small-update pattern: it retains static children/resources, skips eligible component bodies and executes compiled batches. It is slower because it surrounds those writes with substantially more discovery, transaction construction and repeated validity proofs. The next coherent slice should consolidate that proof path, not add another arithmetic compiler or memoization layer.** The trace supports this priority; it does not promise React parity after the slice.

This is a source-and-saved-trace review. Implementation remains frozen; no agents are dispatched and no product code, test, build, browser or benchmark is executed by this review. [Source basis](astra-source-basis.json), [source cost map](native-cost-map.md), [independent filtered analysis](primary-ancestry-review.json).

The one actual DevTools episode ran Native/React/React/Native, each with 12 warmups and 60 measured updates. Traced update median/p95 is Native 3.80/4.40 and 4.00/4.70 ms; React 0.60/0.80 and 0.70/0.90 ms. All 288 frame outputs/pixels match, tracked 512-resource disposal succeeds per context, and 13,004 source bindings match. These are diagnostic timings under tracing. Two earlier preflights produced no frames; the first offline analyzer’s signed-delta failure remains preserved. Repaired offline analysis neither changes nor repeats the capture.

The trace-integrated CPU profile is aligned with original update windows through post-end User Timing measures. Signed deltas are accumulated from the profile head’s trace timestamp and sample/timestamp pairs are stably sorted, matching the documented DevTools model. Actual median sampling cadence is 130–163 µs. With the approximately 0.10-ms browser timer quantum, window-only samples can include `tick`, post-timer measurement or inspection. Therefore the table below additionally requires the exact authored update frame in the stack and a completely contained sampling interval. React’s `tick`/`inspect` contamination is excluded. GC that loses update ancestry is reported separately, not silently treated as zero.

Source supplies the missing causal distinction. Successful notification acknowledgement for 257 one-Store readers captures and immediately inspects 257 temporary receipts, entailing 514 full canonical checks. The reader/history proof is necessary; reproving the same Store shape twice per reader in a passive interval is duplicated work. Root’s `current()` repeatedly constructs `ownerPrefixes`, converts owner IDs, checks every owner/input/code stamp, then scans live readers and spreads each membership Set. Multiple public/prepared/posthost/final predicates can call it. These are real proofs with a mixture of required live checks and repeated preparation of their inputs.

Output construction also survives compilation: `OwnedScalarBatchRows` initializes per-property descriptors, adoption validates and freezes final rows, schedules group input columns, and Store/World capture constructs transaction records. `makeRow`, input capture and row construction are positively sampled. The frame-kernel range includes its wrapper and validation, so it is not evidence that arithmetic dominates. React’s selected stacks instead prominently contain ordinary R3F `applyProps`, `diffProps` and `commitUpdate`. Native’s extra pipeline is visible even though both systems reuse the static tree.

**One integrated slice: make the existing owned Store transaction carry its proof work through the correct boundaries.** Scope is the compiler-owned scalar Store path selected by public `prepareStores` and the existing group receipt. Root/Store/World/VDOM keep their existing identities, versions and accepted histories. The physical retirement is three connected pieces:

1. **Store-owned cohort acknowledgement.** At `async_store_runtime.ts:928–961,1248–1260,1308–1333`, add an internal passive cohort operation. Normalize inputs before the protected interval; private-brand-check real Stores; freshly audit the canonical prototype and each distinct Store instance once; directly check each reader’s existing accepted history, root epoch and root version. Root’s `#acknowledgeCurrentStoreNotifications` at `component_state_runtime.ts:11357–11391` consumes this result, retaining blocked-reader, membership, subscription and notification-generation checks before advancing its existing committed generation. Retire the per-reader capture/immediate-inspection receipts only on this route. Subclasses, proxies, altered descriptors/intrinsics or any unproved callback dependency retain the defensive path. Audit validity expires on return and before callbacks. Shape work targets one prototype audit plus one instance audit per distinct Store, while all reader stamp checks remain; no persistent canonicality cache.

2. **Prepare coverage metadata once per candidate.** In `#stageClosedStoreOutputs` and its `current()` closure (`component_state_runtime.ts:3258–4021`), finalize immutable owner-prefix/coverage descriptors when the selected owners are known, and reuse them until candidate release. On the proven canonical route, iterate live membership directly with captured operations instead of repeatedly allocating `[...membership]` and `.some` closures. Retire repeated normalization and temporary owner-prefix Sets. Keep the full live-reader sweep, per-owner/cache/code/source checks, accepted receipt semantics, resource holds and mixed-input checks. There is no demonstrated existing version that licenses an O(1) membership test: reader maps can change in place. No persistent membership index or new generation counter is added. Public/custom iterator or descriptor behavior stays on the current conservative path.

3. **Fuse canonical posthost preparation inside the existing group authority.** Today `native_root_work_queue.ts:527–553` performs posthost validation, calls each `preparePublication` (which validates again), validates again, then calls the final private group check. Extend the existing private `groupPublicationReceipts`/lifecycle core, not a second registry, with a canonical group operation that joins required posthost validation and Store publication preparation without reentering public candidate wrappers. All-member eligibility must be established without phase changes; any overridden candidate/work validator, getter, Proxy, Store/World method or unproved input declines before mutation. Captured canonical operations and private owned records must make the subsequent interval callback-free. Then each member performs its required posthost check and canonical preparation once, reaches publication-ready, and the existing final all-member private check still runs immediately before pointer publication. An actual preparation failure after entry uses existing failure/quarantine handling, never an unsafe mid-group fallback or replay.

The third part is a concrete replacement boundary, not permission to turn on `owned-scalar-immediate` for public candidates. Keep delayed-candidate admission, later-member continuation after an earlier host dispatch, chronological cutoffs, root-specific history and forks. At `vdom_snapshot_runtime.ts:3709–3777,4773–4950`, VDOM retains target/writer/parent/child identity authority, every changed-write readiness check and the final private target sweep. Host setters and descriptor reflection are callback boundaries. No validation fact survives them merely because the outer operation is synchronous. Managed accepted pointers remain old until all required host writes succeed; partial failure quarantines touched domains.

The main opportunity is reducing duplicated proof work around one existing captured cut. The complete source proof of passivity is an implementation acceptance condition, not something this profile establishes. If a boundary cannot be proved passive, preserve its current checks and explicitly report the smaller delivered slice. Do not remove a final sweep based on root version alone.

**Budget and residual.** The two largest grouped families occupy about 59% of selected samples, but much of that work must remain and sharing adds eligibility/normalization cost. No defensible numerical saving or resulting median/p95 follows. Even deleting all prototype audits in the previous unsound control failed to reach React. This slice addresses broader repeated proof work; it still retains transaction capture, final immutable rows, host application and other required checks. It introduces no row-pool, scratch reuse, container, writer or compiler redesign. Those costs are recorded residuals, not automatic successor projects. Old accepted snapshots make indiscriminate output-buffer reuse especially unsafe.
