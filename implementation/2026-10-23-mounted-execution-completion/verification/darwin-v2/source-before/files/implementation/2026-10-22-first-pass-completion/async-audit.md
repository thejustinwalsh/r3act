# Units 5 and 8: async source audit

Source basis: current committed frame slice `9759a0b`, the semantic contract and dependency backlog in `final-master-plan.md` §§5, 8, 16, `implementation-checkpoint.md`, current runtime/tests, and the preserved installed async receipts. This is a source-only audit; no test, build, browser, server or benchmark was run. It does not qualify latency, fallback frequency, cold or retained memory, or an independent device.

## Supported active path

The public Native task path uses `NativeTaskTransitionQueue`, not `TransitionCoordinator`. It snapshots authored tasks and immutable inputs, captures each root's live Store projection with `StoreRenderTransaction`, subscribes and revalidates after registration, and groups equal input cuts into one execution (`src/native_task_transition.ts:170-245, 337-421, 444-558`). A changed live input recaptures the cohort, cancels obsolete work, and offers completed outputs only outside the changed-input descendant closure (`src/native_task_transition.ts:619-724`; `src/async_task_scheduler.ts:159-202`). The scheduler starts all ready independent tasks up to `maxConcurrency`, and late results after abort cannot enter its values (`src/async_task_scheduler.ts:203-250, 309-355`). This is asynchronous overlap on one JavaScript thread, not CPU parallelism.

Explicit operation keys claim replacement before displaced callbacks, while unkeyed overlapping operations remain independent (`src/native_task_transition.ts:241-272`; `src/root_work_queue.ts:239-287`). `RootWorkQueue` prepares each work record independently, retries stale candidates, and serializes synchronous host application per root; `NativeRootWorkQueue` admits all group members before writes, validates the group again, publishes all accepted pointers before Store/effect callbacks, and classifies partial failure (`src/root_work_queue.ts:477-725`; `src/native_root_work_queue.ts:452-647`). Root/Store history, exact captured acknowledgement and quarantine remain with their existing authorities. Tests specifically cover reverse-ready same-root/fork resource work, grouped observer visibility, stale task-only inputs, partial failure, fork convergence and lifetime (`src/native_root_work_queue_test.ts:62,119,583,878,963`; `src/native_forked_transition_test.ts:35,86,143,198`). I found no source evidence that the older root-overlap supersession in `src/transition_coordinator.ts:104-110` runs on this public Native task path; it remains used by the separate legacy async transition modules.

Suspense retains accepted content on update suspension and exposes first-load fallback/error choices in `src/component_state_runtime.ts:12440-12669`. Selected fulfilled resource reveals can publish beside unrelated pending siblings when their finite dependency footprint is proved: `prepareResources` finds affected boundaries, gathers direct resource/Store dependencies and waits on the declared cut, then prepares scoped reveal regions (`src/component_state_runtime.ts:2461-2599, 7287-7514`). Automatic boundary retries drain independently before falling back to a whole-tree retry (`src/component_state_runtime.ts:6990-7068, 6358-6473`). Existing tests cover joint Store/resource reveal, settlement order, stale source, host-time newer action, fork projection, independent scoped work and accepted fallback (`src/component_joint_async_inputs_test.ts:24,97,211,268,365`; `src/component_scoped_async_test.ts:108,134`). The installed forked app also proved A retention, B/C cancellation, C reveal, urgent actions, fork convergence and cleanup in its exact frozen scenario (`implementation/2026-10-20-installed-async-ux/results.md`).

## Remaining source boundary and evidence

The dependency-scoped reveal fast path is deliberately finite. `#boundaryResourceDependencies` accepts frozen, data-property, direct/forwarded component props and stops after nine nodes; a dynamic/accessor/array/nonfrozen or deeper chain returns `null` (`src/component_state_runtime.ts:3221-3261`). `#stageBoundaryReveal` also requires an authenticated runtime-owned child and same-revision forwarding path (`src/component_state_runtime.ts:7523-7595`). For a settled resource behind a child outside that proof, `prepareResources` returns `null` rather than an independently publishable candidate (`src/component_state_runtime.ts:2482-2513, 2593-2599`); automatic retry then takes the generic route (`src/component_state_runtime.ts:7025-7042, 6435-6480`). A concrete trigger is a Suspense child whose resource is supplied through an accessor or unproved wrapper while an unrelated sibling remains pending. This is limited optimization coverage with a safe generic fallback, not a demonstrated defect or a mandatory source gap inside the documented subset. Whether the trigger causes a visible delay in an authored workload is unmeasured; only such evidence would justify a bounded compiler-authenticated footprint extension. No broad opaque callback speculation or new registry is justified by this audit.

The active path's grouped work waits for every member of an expressly declared group (`src/native_root_work_queue.ts:368-426`); that is coherent group semantics, not a source defect. Separate unkeyed operations and distinct ready boundaries can progress independently. Arbitrary host setters still have no rollback or cross-renderer paint atomicity; the accepted-pointer group contract and partial-failure quarantine are narrower (`src/native_root_work_queue.ts:551-647`; master plan §5). Task identity/reuse is bounded to this operation's captured inputs and completed DAG outputs; it does not prove general effect-free prefetch or reuse across unrelated operations.

The larger Unit 8 acceptance remains **missing evidence**: Recording C's resource start/settle and hard-path attribution, equal React preload across more than the frozen installed episode, fallback/keep-previous intervals, physical urgent-input-to-present, p95/cold/retained-memory, and independent-device behavior. The installed receipt's one fixed-order page pair observed Native urgent median/p95 0.9/1.5 ms versus React 0.2/0.4 ms, measured only to a matching MutationObserver before paint with controlled deferred providers and unequal graphs (`implementation/2026-10-20-installed-async-ux/results.md`). It establishes neither a broad async UX advantage nor a CPU/worker claim. The next decision is evidence collection on a concrete authored async/reveal workload. This audit found no named mandatory source defect in the active documented path and no source-grounded speed helper, worker, or replacement registry to implement now.
