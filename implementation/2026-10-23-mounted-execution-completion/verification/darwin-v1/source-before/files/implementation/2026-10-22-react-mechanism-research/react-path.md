# Pinned React Compiler/R3F frame path

Source-only research, 22 October 2026. No application, gate, browser, build or benchmark was run. This follows the **declarative `react` arm**, not the distinct `react-frame`/`useFrame` arm. The pinned source and hashes are in [react-source-basis.json](react-source-basis.json). [Astra's earlier report](../2026-10-22-astra-compact-gap-plan/report.md) established `_c(8)` and R3F `commitUpdate`; this trace follows the notification, bailout, and surviving host work beyond that observation.

The one archived 256-object, 12-warmup/60-measured episode reports Native update 4.10/4.80 ms median/p95 against declarative React Compiler/R3F 1.10/1.60 ms, and through shared draw/readback 6.60/7.80 against 4.80/5.80 ms ([result](../2026-10-22-native-frame-publication/results.md#L25-L36)). This is a source question, not a causal timing decomposition: fixed arm order, concurrent read-only Git work, one device, and no phase/GC trace remain limitations.

## Exact per-frame route

1. The authored `App` creates 256 fixed keyed outer groups, each containing a `Position` or `Rotation`, a retained child group, mesh, geometry and material. Only those 256 motion functions plus `FrameMarker` subscribe to the clock. `clock.dispatch` freezes a new `{phase,epoch}` snapshot and invokes the `Set`'s listeners; `update` encloses that dispatch in R3F's `flushSync` and tests the accepted marker ([react.tsx:7–44, 62–65](../2026-10-22-native-frame-publication/consumer/react.tsx#L7-L65)). `OBJECTS=256`; warmup/measured counts are 12/60 ([scene.ts:3–5](../2026-10-22-native-frame-publication/consumer/scene.ts#L3-L5)). The snapshot object changes even when individual numeric outputs could happen to compare equal.
2. The archived React reconciler's `subscribeToStore` checks the latest snapshot against each hook's stored value using `Object.is`; changed subscribers call `forceStoreRerender`, which enqueues lane `2` and schedules that fiber ([production reconciler:3173–3190](../2026-10-22-native-frame-publication/proof-canvas-v3/inputs/installed-store/react-reconciler@0.34.0_react@19.3.0/node_modules/react-reconciler/cjs/react-reconciler.production.js#L3173-L3190)). There are 257 registered clock listeners after mount by construction; dispatch calls all 257. This is **not** a sparse clock selector. The stable `subscribe` and `getSnapshot` functions avoid an identity-driven resubscription each frame; `updateSyncExternalStore` still reads the snapshot and checks identity ([3110–3153](../2026-10-22-native-frame-publication/proof-canvas-v3/inputs/installed-store/react-reconciler@0.34.0_react@19.3.0/node_modules/react-reconciler/cjs/react-reconciler.production.js#L3110-L3153)).
3. R3F exports `flushSync` by calling `reconciler.flushSyncFromReconciler` ([reconciler.tsx:876–885](../2026-10-22-native-frame-publication/source-basis/r3f-v10/reconciler.tsx#L876-L885)). The archived implementation sets current priority to `2`, calls the dispatch once and then flushes synchronous work across scheduled roots on exit ([production reconciler:12748–12760](../2026-10-22-native-frame-publication/proof-canvas-v3/inputs/installed-store/react-reconciler@0.34.0_react@19.3.0/node_modules/react-reconciler/cjs/react-reconciler.production.js#L12748-L12760), [1224–1260](../2026-10-22-native-frame-publication/proof-canvas-v3/inputs/installed-store/react-reconciler@0.34.0_react@19.3.0/node_modules/react-reconciler/cjs/react-reconciler.production.js#L1224-L1260)). Thus 257 notifications schedule work before one synchronous root flush; source does not justify calling them 257 separate root commits.
4. The **runtime subscription boundary** excludes the static authored tree from ordinary clock updates. `App` has no clock subscription, so normal frames need not execute it. The actual transform also gives `App` a `_c(2)` cache: if `App` does rerender with the same dependencies, it reuses the `Array.from(256)` element tree after its initial sentinel ([transform:134–181](../2026-10-22-native-frame-publication/proof-canvas-v3/transforms/react/react.tsx.js#L134-L181)). This ordinary-frame absence of `App` reexecution would hold without React Compiler; `_c(2)` is observed code, not an established cause of savings on this clock path. React's `beginWork` checks pending props and scheduled lanes and can early-bail, while `bailoutOnAlreadyFinishedWork` traverses children carrying update lanes and stops at unchanged subtrees without such lanes ([production reconciler:5383–5417, 5539–5555](../2026-10-22-native-frame-publication/proof-canvas-v3/inputs/installed-store/react-reconciler@0.34.0_react@19.3.0/node_modules/react-reconciler/cjs/react-reconciler.production.js#L5383-L5417)). This still walks the 256 live subscriber paths; it does not rebuild the 256 keyed outer JSX objects, 256 child groups, 256 meshes, 256 geometry/material pairs or 512 resources per update. It also does not diff their unchanged props in the ordinary case. That identifies React's runtime bailout boundary; Native also avoids rerunning component bodies and retains child objects/resources on this closed path, so static scene reuse alone does not explain the Native/React timing gap.
5. Each of the 256 scheduled `Position`/`Rotation` functions does run `useSyncExternalStore`, `useState`, and the Compiler expression path. The emitted `_c(8)` reuses each stable `id`-keyed layout-effect closure/deps and retained `children`; it still calculates three scalars and makes a new motion `group` element when they differ ([transform:30–116](../2026-10-22-native-frame-publication/proof-canvas-v3/transforms/react/react.tsx.js#L30-L116)). `FrameMarker` is `_c(2)` and makes one new marker element when `epoch` changes ([118–132](../2026-10-22-native-frame-publication/proof-canvas-v3/transforms/react/react.tsx.js#L118-L132)). For the usual changing frame this means **256 changing motion elements, one marker element, and up to 769 scalar prop changes** (3×256 + marker), rather than 256 reconstructed scene subtrees. The stable `children` reference comes from the static parent tree; React Compiler retains it in the leaf cache. The authored `[id]` effect dependency prevents per-frame local-control effect churn even without Compiler. There are no per-frame event or resource changes in this authored path. The source proves code paths and work shape; it does not prove an exact runtime count of React fiber visits or host commits without instrumentation.
6. React reconciles those updated motion host fibers and reaches R3F's `commitUpdate`. R3F validates type, checks primitive/args reconstruction, calls `diffProps`, replaces `instance.props` with a new snapshot, then calls `applyProps` only for nonempty changes ([archived R3F source:641–678](../2026-10-22-native-frame-publication/source-basis/r3f-v10/reconciler.tsx#L641-L678)). In the delivered baseline, `diffProps` skips reserved props, compares against old props, handles dashed-property dependency keys and removed props ([bundle:3522–3539](../2026-10-22-native-frame-publication/proof-canvas-v3/dist/react/assets/react-Dn0IWIE6.js#L3522-L3539)). `applyProps` handles events, typed/copy values and paths; a dashed scalar `position-x`, `position-y` or `rotation-z` resolves through the Three object then assigns `root[key]=value` ([bundle:3449–3487, 3540–3615](../2026-10-22-native-frame-publication/proof-canvas-v3/dist/react/assets/react-Dn0IWIE6.js#L3449-L3487)). No scene host object or geometry/material is reconstructed for these stable `args` and numeric props. There is still per-leaf prop diff, path resolution and host assignment; React has not compiled away the 769 writes.
7. The separate `react-frame` arm mutates refs from registered R3F update-phase jobs, uses a render-phase takeover and manually calls `advance`; it does not dispatch the external store or reconcile 256 motion components each frame ([react-frame.tsx:32–81, 99–137](../2026-10-22-native-frame-publication/consumer/react-frame.tsx#L32-L137)). The R3F scheduler has separate system render work ([loop.ts:140–174](../2026-10-22-native-frame-publication/source-basis/r3f-v10/loop.ts#L140-L174)). Its 3.50/3.90 ms update result is a distinct control with callback/scheduler obligations, not evidence that declarative React secretly mutates refs.

## What this explains, and what it does not

The source establishes React's effective dependency cut: one snapshot identity fans out to 257 subscribed leaves; runtime child-lane bailouts retain the static authored tree and unaffected child fibers; Compiler caches leaf closures and element outputs where dependencies allow; only the motion hosts and marker carry changing values into R3F's actual diff/apply path. Native likewise retains unchanged component bodies, child hosts and resources on its closed path. This common static reuse is not a causal explanation for the measured Native/React gap. React still performs O(N) listener checks, O(N) subscribed-leaf work and O(W) changed host assignments for N=256, W≈769. Its favorable measured time can plausibly reflect smaller constants and fewer publication obligations than Native's versioned, multi-root accepted-history path, but neither this source trace nor the sole wall-time episode identifies how many milliseconds any particular React or Native phase costs.

There is no evidence here of a bespoke JIT optimization, shared-array data layout, direct Three writer, or special numeric fast path. The delivered `resolve` splits dashed strings on the changing path and `diffProps` iterates property dictionaries, so those specific source paths are not a hidden precompiled scalar kernel ([bundle:3449–3487, 3522–3615](../2026-10-22-native-frame-publication/proof-canvas-v3/dist/react/assets/react-Dn0IWIE6.js#L3449-L3615)). A JavaScript engine may optimize warmed code, object shapes or inline caches, but no IC/deopt/shape trace was captured. Such claims remain hypotheses. The actionable handoff to Astra is the **precise omitted work and survivor set** above, not a proposal to copy a cache or change Native source before causal evidence.
