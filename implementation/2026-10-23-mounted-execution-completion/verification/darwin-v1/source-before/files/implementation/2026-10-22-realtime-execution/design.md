# Integrated realtime execution slice

This executes Slice2 of the [authorized task graph](../2026-10-22-architecture-slices/plan.md), after Slice1's correctness/delivery and single preserved timing boundary. No backwards compatibility requirement. Replace eligible per-row frame adoption and deferred one-root queue facades, and move compiled numeric-row acceptance into the existing candidate lifecycle. Root/World/Store/VDOM/host-domain identities and versions remain authoritative. No duplicate committer, version registry, new arithmetic backend or helper benchmark campaign.

## Contracts agreed before implementation

**Batch values (Sol B):** retain current Rust `batchKernel(shared,varying,outputs:number[][],rowCount)` ABI. `captureVerifiedOwnedScalarBatch` returns an opaque immutable `OwnedScalarBatchPage`, exposing `layout`, `rowCount`, `valueAt(row,prop)` only. Validate the entire private output before freezing rows/page and exposing any reference. Output rows carry an inline discriminant `{kind:"page",page,rowIndex}` or `{kind:"frame",frame}` plus existing owner/lineage/cells/host metadata. Keep interpreted/initial generic `OwnedScalarFrame.create`; retire verified per-row frame adoption. No extra per-row scalar wrapper. Supply union-aware layout/value/materialization helpers to other owners. Never expose writable rows or reuse published arrays. Page/row arrays, output metadata and target records still allocate; this is not allocation-free. A saved internal row can retain its whole page, which is a retained-memory obligation.

**VDOM (Sol C):** mounted owned elements and image targets carry that inline union directly. Read old/new values through page/frame helpers; capture old generic props into an initial frame as needed. Publication changes accepted references only through existing VDOM/Root lifecycle; old snapshots/forks and host-callback observations remain valid. Public snapshot materialization owns ordinary prop values. Existing warm plans already reuse child/prop preparation; keep exact cold fallback, per-key owner map and live membership checks. Removing that map with per-row scans would be quadratic for same-key cohorts; no replacement registry or O(1) freshness claim. Keep pre/post full target sweeps, per-write readiness, journal and resource lifetime. Page targets exclude generic bound groups today; do not invent a second accepted-value authority for unrelated `BoundPropGroup` state.

C also factors the numeric row executor: `prepareNumericRowCut(...)` validates packed indices/tokens/leases/duplicates/reached dependencies before publication, returning a one-shot root-bound private cut or null with no source-mirror/host effects. `executePreparedNumericRowCut(cut)` consumes it under host application and never returns null; `discardNumericRowCut(cut)` releases scratch if admission fails. Retire old `executePreparedNumericRows` after Root production callers migrate, and migrate current tests. Preparation and execution are adjacent without authored callbacks; any intervening callback requires live revalidation. Failure/cancellation after entry never becomes generic replay. Avoid duplicate full preflight work where factoring can preserve the checks.

**Root/frame (Sol A):** a narrow Root immediate-frame method returns committed with existing publicationVersion, or defers before callback-bearing preparation. Preserve public selected-Store coverage/holds and `groupContinuation=true` newer-host-action/canonical-posthost/notification-ack semantics; the old internal helper's false continuation is insufficient. Use private mounted metadata for conservative eligibility; uncertain cases retain existing queue. Do not prepare/discard then execute authored callbacks again. Busy host/resource/opaque/deferred/multi-root work keeps queue coordination. Frame driver uses existing Root publication version for immediate results and final before-draw validation, without a new handle/version authority. Stable or copy-valued writers may reenter; callback-free preparation does not imply callback-free host writes.

Compiled numeric rows supply capture/apply/exact-ack/source-mirror operations to `#createCandidateLifecycle(spec,true)`. Move exact acknowledgement, source mirrors and Root version advance into its publish callback; retire row calls to separate direct commit/publish helpers. Null preflight declines before beginPublication; any post-entry failure goes through existing quarantine, never lane/generic retry. Unmigrated direct paths remain until their real callers migrate. Root output cache/staging/keyed output/change comparisons/publish adapt to page/frame union without materializing batch rows on the hot route.

**Ownership:** A `component_state_runtime.ts`, `native_frame_loop.ts`, `native_root_work_queue.ts`, related tests. B `closed_scalar_output.ts`, `closed_store_execution.ts`, owned frame input/capture/proof modules and related tests. C `vdom_snapshot_runtime.ts`, mounted/numeric-cut modules and related tests. Primary `jsx_binding_runtime.ts` materializer, native public exports/docs, installed/compiled consumer runner and integration/checkpoint. Agents coordinate interface names directly; no cross-owner edits without agreement. Only Sol medium authors implementation; Luna runs no workloads until freeze.

## Acceptance and limits

Preserve exact captured acknowledgements/newer actions, immutable old snapshots, per-root/fork histories, live source/code/owner/writer checks, resources, generic fallback, host-domain claims and partial-failure quarantine. Whole-tree/cache candidates retain whole-root guards. No visual DOM/canvas atomicity unless explicitly scoped to managed publication; arbitrary host mutation is not rollbackable.

Author meaningful page immutability/partial-failure/snapshot/fork, stale binding/topology/lifetime, numeric preflight/one-shot, one-root public-frame reentry/deferral/shared-host and delivery regressions. Primary reviews entire integrated source, then Luna runs one consolidated correctness/package/HMR/installed boundary and one bounded balanced minified-production comparison. Median+p90 primary; rawp95/max retained. Preserve failures; no timing-driven helper reverts. Same-run parity is a target, not a proven0.6ms promise. Cold/setup/retained memory, independent-device and full async/host/package/product evidence remain requirements.
