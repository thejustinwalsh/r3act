# Numeric owner effect boundary

The replaced mechanism admitted a named component's pure numeric host expression as sufficient reason to skip its entire render on local-state invalidation. The invariant authority is the existing compiled component AST, state/effect sites, owner identity, accepted host tree and module revision. A callback, getter, initializer or capture elsewhere in that owner must remain observable even when one numeric attribute is pure. The Rust proof decides eligibility; the harness supplies no purity metadata.

`compiler/fixtures/native-numeric-owner-effects.tsx` has the source-reachable case: `OpaqueSibling` reads local numeric state, registers its setter in an activation effect, calls an opaque getter and returns numeric and opaque attributes on one output. `compiler/compiled_numeric_owner_effects_test.mjs` checks the actual Rust/OXC registration, then updates the accepted owner and records output identity, callback/getter counts, exception delivery and unchanged effect setup. Pure named/arrow and derived numeric controls must keep their supported numeric programs; an initializer, captured callback and hidden capture must remain generic. Direct primitive prop proof must emit `numericPrimitiveProps: ["id"]`; profiling checks that only runtime-owned immutable primitive input skips component execution, while object, unowned and Proxy inputs execute the generic owner. A same-owner, same-valued transition from owned primitive to unowned Proxy must lose numeric admission before the next state cut. A separately mounted unowned Proxy remains generic even when an effect mutates and freezes its private props copy after admission was captured. An activation effect's attempted mutation cannot change the owned prop. Separate keyed and forked roots preserve their own accepted output. A pending Three resource stays independent of the opaque update. Exact module revision invalidation retires compiled owners, and disposal balances effects and clears host owners/resources.

`baseline/ui-graph-compiler-spike-darwin-arm64` and `baseline/package-report.json` are immutable copies of the prior packaged compiler and its report (`ddeb55aa...0510`, 3,483,088 bytes). The baseline mode executes that exact old compiler against the **current runtime** and records what it actually does in a fresh `.cache/compiled-numeric-owner-baseline-*` artifact. It is a compiler diagnostic, not a frozen old-product comparison; the receipt hashes the current component, JSX, VDOM and semantic-plan runtime sources before and after execution. It does not assume that a source-level suspicion is a measured failure or relabel a failed invocation as passing. The fixed mode is the new actual compiled regression in the consolidated gate. The baseline copies are never rebuilt or overwritten.

The installed consumer uses the same named opaque owner and safe arrow owner, plus DOM and a pending Three scene. The untimed production browser proof updates the safe owner, then changes the opaque getter value and local state, reveals the Three resource and checks accepted output, stable host identity, effect lifetimes and teardown. The React arm has equal initial values and actions. React Compiler must emit memo caches and `CompileSuccess` for the matched `App` and safe `HotCounter` with `react/jsx-runtime`. Opaque callback/getter correctness is untimed; the only measured Native-first episode is a safe local update from button click to its output attribute mutation. This observation does not compare equivalent package graphs or qualify CPU, tails, paint, cold start, memory or overall product performance.

The protocol snapshots and rechecks the package-build report/source hashes, five tarballs, selected installed graph, current compiler, immutable baseline, authored fixture/test, harness source, transforms and exact production assets. Browser assets are served only through offline HTTPS request interception. The browser is headless, GPU-off, interruptible and bounded to 90 seconds; no project server, Portless route or VM is needed. Failure receipts retain phases, snapshots and cleanup errors. After the primary's source review and consolidated correctness gate, Luna runs:

```sh
node compiler/compiled_numeric_owner_effects_test.mjs --baseline
node implementation/2026-10-19-numeric-owner-effects/prepare.mjs --proof-dir implementation/2026-10-19-numeric-owner-effects/proof-v1
node implementation/2026-10-19-numeric-owner-effects/run-build-pair.mjs --proof-dir implementation/2026-10-19-numeric-owner-effects/proof-v1
node implementation/2026-10-19-numeric-owner-effects/verify-browser.mjs --proof-dir implementation/2026-10-19-numeric-owner-effects/proof-v1 --phase proof
```

The primary writes a hash-bound `proof-v1/run-authorization.json` only after the untimed proof passes. Luna then runs the single measured pair:

```sh
node implementation/2026-10-19-numeric-owner-effects/verify-browser.mjs --proof-dir implementation/2026-10-19-numeric-owner-effects/proof-v1 --phase measure
```

Falsifiers are stale opaque output, a missing getter call or exception, an unsafe owner with closed metadata, object/Proxy props entering the numeric cut, a lost safe numeric program, repeated activation setup, a changed fork/host identity, stale revision writes, leaked owners/resources, hash drift or an unbounded browser run. Historical wins, dense FAIL and physical HOLD retain their prior scope.
