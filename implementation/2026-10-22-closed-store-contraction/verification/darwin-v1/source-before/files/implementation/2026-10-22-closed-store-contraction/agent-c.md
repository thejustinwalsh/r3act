## Contract and source change

`createOwnedScalarStorePropDelta(region: StorePropDelta): StorePropDelta | null` is exported only from the internal VDOM module. It copies own data descriptors from a plain record and bounded dense arrays (at most 32 prop pairs, exactly two pair entries, and zero marker children), rejects symbols/accessors/extra fields/duplicates/nonfinite or structured output values, and requires `snapshotScopedHostProp` to accept each primitive value before freezing the region, pairs and pair list. Thus primitive `style` does not acquire eligibility merely because it is primitive. A module-private `WeakSet` brands only the copy. The builder accepts ordinary scalar props, schema 5 marker `{children: []}` (including no prop writes), and motion `{retainedChildren: true, componentOwner}`. It rejects a retained region combined with any children description, including `[]`, preserving the existing public API. The brand proves copied data ownership only; it grants no host, callback or lifecycle purity.

`prepareStorePropDelta` still resolves mounted nodes, buckets, owner, old descriptors, scoped authored provenance, previous values and journal data. Each region's own brand controls its copied-value and final-VNode path; the record's separate all-owned flag alone controls scan retirement. Mixed region order therefore cannot change eligibility or copied values. Branded scalar proposals bypass repeat value capture and construct one props object and one final VNode per target. The final VNode clone preserves nonenumerable `scopedSourceProps`; retained children refer to current mounted child VNodes. Generic aggregate, text, structural and arbitrary regions follow their former construction path.

The end-of-wrapper Store currency scan is skipped only when the prepared record says every consumed region was branded and no keyed, retained-source or replacement plan exists. The previous `prepareStorePropDelta` final scan is the immediate preceding check. Between it and wrapper completion, the owned branch touches only private record/array state and performs no user callback. The commit guard still validates the exact Store token; it then sets local state and directly invokes a private checked-apply helper. No retained/structural/replacement operation or callback lies between this guard and helper entry. Public direct apply and all mixed plans retain their separate apply guard. `commitAdmitted` retains its private fresh guard. Post-host and final private validation remain.

Owned application resolves the live writer first because its descriptor lookup may invoke a Proxy callback; it then checks the target, version, publication token, bucket, exact child lengths/identities and mounted key membership before each changed host write. This is bounded target work, not a whole-footprint scan after every write. An earlier writer can invalidate a later target and stop the later write. Accepted mounted journal capture remains before host calls; VNodes and accepted history advance only after the write loop and later publication. Host partial failure is quarantined by the existing publication flow.
