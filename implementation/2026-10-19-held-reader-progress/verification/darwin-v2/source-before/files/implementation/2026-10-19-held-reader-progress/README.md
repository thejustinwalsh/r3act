# Held Store reader progress

This unit tests independent generic work while a resource-only publication hold retains a Suspense boundary that read Store A before suspending. The replaced mechanism is the global notification guard in `ComponentStateRoot.#captureHeldGenericState`: a pending reader of A must not block a notification from independent Store B. The existing Store reader memberships, owner lifetimes, resource versions, root accepted history and publication receipt remain the authorities. No separate identity or version registry is introduced.

The authored compiler fixture is `compiler/fixtures/native-held-reader-progress.tsx`. `compiler/compiled_held_reader_progress_test.mjs` checks Rust/OXC output before executing it: both DOM and Three leaves must emit schema-5 `closedStoreHostProgram` with lexical Store-A-first, resource-second inputs. Dynamic Store-A and local-state resource choices must remain generic. This is an actual compiled execution, not hand-authored proof metadata. The fixture mounts a shared-World DOM/Three resource group plus an independently scheduled fork. Store B must publish while A's pending reader remains held; A may change without exposing a partial held output. Once both resources settle, the group must publish one final output with the latest A. The fork Store projection can receive A while its accepted host tree remains an old fallback until its own scheduled commit. Separate explicit queues hold each initially selected detail resource while Store A or local state changes the selection: obsolete detail work must fail conservatively, never reveal old output, and the later signal must reveal the new branch. An unchanged-ancestor queue must commit that same initially selected detail, proving the changed-ancestor failures reach the guarded publication path.

`consumer/` installs the five current `@r3act` packages with React 19.3, Radix Dialog and Three. Its Native DOM and Three leaves read A before the resource and are compiled by the installed Vite plugin. The keyed generic dialog reads B, owns local state and mounts a React island. `comparison/native/native.tsx` imports that same authored scene. The React comparison preloads both deferred resources at module evaluation, keeps the dialog outside Suspense, and uses React Compiler. This matches the interaction being observed; it does not equate Native group publication with a React/Three paint boundary.

The harness snapshots the current package report, tarballs, installed graph, compiler, transformed modules and production assets. `run-build-pair.mjs` builds Native then React **untimed**, requires schema-5 Native provenance and a React Compiler success plus `react/jsx-runtime`, and hashes every production asset. `verify-browser.mjs` serves only those exact hashed assets through an offline intercepted HTTPS origin. No project server, VM, Portless route or network lookup is needed. The browser is headless with GPU disabled and a 90-second deadline. It checks the actual production app's fallback retention, B dialog/React island/local state, A change, partial resource settlement, one joint final reveal, cleanup and unexpected browser errors. An untimed proof must pass first. After primary authorization recorded in `proof-vN/run-authorization.json`, one separate Native-first browser pair measures only the open-button-to-dialog-portal episode while both resources are pending. These are descriptive elapsed times, not a broad speed, CPU, paint or cross-renderer atomicity claim.

The primary selects a new proof directory path and writes the run authorization after reviewing the source and consolidated gate. `prepare.mjs` creates the directory. Luna alone executes the scripts, in dependency order:

```sh
node implementation/2026-10-19-held-reader-progress/prepare.mjs --proof-dir implementation/2026-10-19-held-reader-progress/proof-v1
node implementation/2026-10-19-held-reader-progress/run-build-pair.mjs --proof-dir implementation/2026-10-19-held-reader-progress/proof-v1
node implementation/2026-10-19-held-reader-progress/verify-browser.mjs --proof-dir implementation/2026-10-19-held-reader-progress/proof-v1 --phase proof
node implementation/2026-10-19-held-reader-progress/verify-browser.mjs --proof-dir implementation/2026-10-19-held-reader-progress/proof-v1 --phase measure
```

The last command requires the hash-bound authorization and runs once. The compiler fixture belongs in the primary's consolidated gate, after the Rust compiler binary is current. A failure leaves its receipt and logs intact. The source and evidence here add no claim that old timed HMR or joint-async attempts passed; the old unit and its proof directories remain frozen.
