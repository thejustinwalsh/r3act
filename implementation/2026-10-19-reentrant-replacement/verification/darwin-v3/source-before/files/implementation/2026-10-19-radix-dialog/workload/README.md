# Radix Dialog bridge workload

The native arm compiles `compiler/fixtures/native-radix-dialog.tsx` through the actual Rust/OXC native compiler. `NativeRadixApp` reads controlled open and point Stores, owns a native state button, and renders the public `RadixDialog` from `@r3act/react-bridge/radix-dialog`. Its `children` prop is a React-created `DialogBody`; native VNodes do not cross into React. The direct arm renders the same `ReactRadixDialog` and `DialogBody` with equivalent controlled external stores. Radix Dialog is pinned to 1.3.1. The caller owns the portal container and keeps it outside the native root.

The browser check externally opens the modal, validates Title/Description ARIA links and the caller-owned portal, uses headless `page.keyboard` Shift+Tab from the first input to the last Close button, Tab back to the first input, and Escape to check focus wrapping and restoration, and checks Trigger and Close callbacks. It edits an uncontrolled input and selection, increments React-local and native-local state, updates a Store-derived prop, and reorders the keyed dialog row while preserving its portal and form identity. It rejects portal effects from discarded and stale native candidates, keeps the accepted modal during a pending resource request or React transition, then removes/reinserts the open dialog and verifies fresh state. Disposal occurs while open and checks empty host and portal, unrelated nodes, ARIA hiding, body scroll style, focus guards, and matched React mount/cleanup counts. The native wrapper has one private `div` and React commits asynchronously after native publication; the comparison makes no cross-renderer visual atomicity claim.

After primary source review, Luna creates one new proof directory under this workload and runs `node implementation/2026-10-19-radix-dialog/workload/build-gate.mjs --proof-dir ABSOLUTE_NEW_PROOF_DIR`. The gate freezes and archives exact raw source bytes (including selected installed Radix/transitive package files and LICENSE files), the debug compiler hash, and package versions before building. It captures native and React transforms, React Compiler events, bundle assets, raw build logs and failure status. A separate compiler AST/source gate checks actual native lowering; the browser supplies the real ReactDOM behavior evidence. After reviewing the build proof, the primary writes `run-authorization.json` with `status: "APPROVED_FOR_ONE_DESCRIPTIVE_PAIR"` and `buildProofSha256` matching that exact proof. Luna then runs `node implementation/2026-10-19-radix-dialog/workload/run-pair.mjs --proof-dir ABSOLUTE_PROOF_DIR --origin https://radix-dialog.localhost`.

The runner uses a headless, GPU-off browser and serves frozen local production assets through a synthetic HTTPS `.localhost` origin. It starts no project server or VM and does not steal desktop focus. Native runs first, then direct React, under one 90-second deadline. The sole measured interaction is controlled external open dispatch to the first matching portal `MutationObserver`; it includes scheduling and observer delivery, excludes paint, and is descriptive rather than a CPU or distribution claim. Initial setup-return and first observed mount times are labeled separately. The first one-shot receipt and all failures are preserved; no favorable retry is allowed.
