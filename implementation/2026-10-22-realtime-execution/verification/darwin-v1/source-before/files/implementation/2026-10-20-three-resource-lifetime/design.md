# Three resource handle lifetimes

Basis: main a81bafbf, MIT. Master plan Units 5/9 require host resource ownership and coherent cleanup. Source review finds same-object factory resources are represented by a Set without handle lifetimes: releasing either handle disposes the object immediately. releaseHandle marks a handle dead and removes it before attachment restoration, so a thrown restore skips its owned resource disposal. These are source findings until the immutable baseline runs.

Replace the existing host-local owned resource Set with one resource lifetime authority for handle references and ownership. Multiple geometry/material handles within one host may alias; dispose a host-owned resource once only after the final relevant handle releases it. A primitive borrowing that resource pins it while live, including a borrower registered before an owning factory handle. Borrowed-only objects never become host-owned. Shared fallback mesh resources remain host-owned until host teardown. Diagnostics count distinct owned resources, not alias handles. A disposed host-owned resource cannot be readmitted. Separate Three Object3D handles may not claim one live object; resources support aliases because geometry/material have different attachment semantics.

This is host-local ownership, not a global lifetime registry. Across hosts or direct mesh args/property references outside resource handles, the caller retains the documented borrowed-resource lifetime responsibility. Do not silently dispose caller-owned assets or promise cross-renderer visual atomicity. Host resource ownership does not prove render purity or resource loader idempotence. Explicit repeatable generic preparation from the preceding unit remains.

Handle retirement, attachment restoration and owned reference release must each run despite other cleanup failures. Preserve original errors and aggregate cleanup errors; one disposal exception does not prevent other resources/handles from retiring. Mark/retire ownership before calling fallible disposal listeners so reentry cannot double-dispose or readmit a dying object. Preserve live attachment ordering, borrowed-parent restoration, current props/copy capture, events, args identity, exact acknowledgements, newer reentry, root accepted histories and partial-host quarantine.

Required cases: shared geometry and material, both removal orders, whole-host teardown, owned/borrowed alias ordering, pure borrowing, attachment restore throwing with disposal throwing, reentrant disposal, duplicate live Object3D handle rejection, dead resource readmission, ordinary keyed root removal and grouped DOM/Three failure. Replace the Set authority rather than stack parallel identity/version maps. No traversal layout or speculative storage redesign is selected.

Falsifiers are early or double disposal, borrowed disposal, leaked ownership after restore failure, corrupted surviving attachment/event identity, cleanup masking or a stale host write.
