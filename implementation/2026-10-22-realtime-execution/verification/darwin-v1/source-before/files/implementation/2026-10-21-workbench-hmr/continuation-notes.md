# Main-thread batching source audit

The human's batching/fusion steer remains open beyond numeric expression sharing. A bounded Sol read-only audit during this boundary inspected World dispatch and Root scheduling; no implementation, helper test or timing follows it.

OwnerStateWorld committed dispatch computes updater synchronously, rechecks owner/cell after user code, advances value/source/version, marks existing WorldDirtyJournal and captures dirty/public listener cuts. Dirty notifications precede public change notifications. ComponentStateRoot's dirty subscriber filters lineage, immediately updates its per-root PendingStateChanges latest-version entry, then requests scheduling. PendingStateChanges already coalesces owner/site writes without reordering; Root #schedule already deduplicates through #scheduled and the default microtask. Native/Root work queues coordinate async publication rather than replacing synchronous local dispatch.

A scheduling-only explicit batch could define behavior for custom synchronous schedulers, but default microtask scheduling already coalesces. It would not retire per-cell dispatch, dirty membership, numeric validation, history or host work and has no demonstrated speed benefit. Do not add that narrower API as if it fulfilled the main-thread computation-batching requirement.

Deferring internal dirty callbacks under the existing API would leave Root pending frontiers stale during synchronous public callbacks or reentrant flush. Forks need distinct accepted histories, exact captured acknowledgements must preserve newer actions, and updater/listener failures and owner retirement keep their contracts. Any substantive next dispatch/batching design must identify a real owned boundary and reuse existing World/source/Root authorities; it cannot delete those meanings or add a parallel identity/version world. Default public callbacks and live validation remain. No new physical plan, cache, selector or performance budget is established by this source audit.
