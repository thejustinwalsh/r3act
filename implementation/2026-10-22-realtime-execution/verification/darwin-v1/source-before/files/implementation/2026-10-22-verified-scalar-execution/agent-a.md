# Sol A compiler handoff

The replaced mechanism is recursive runtime evaluation of eligible closed numeric Store host props. The normalized host expressions remain the semantic authority. The compiler now emits schema-2 `owned-data` metadata with the same four serializable identity fields as schema 1; actual module code adds an optional `numericKernel` function. Diagnostic JSON contains no function, expression copy, hash, or source authority.

The emitted function is an ordinary two-parameter arrow block: `(inputs, outputs) => {const $r3actDag0 = (...);outputs[0] = (...);...}`. It reads only literal-indexed `inputs` slots; writes dense numeric `outputs` slots in host prop order; and uses single-assignment `const` locals only for repeated structural subtrees. Each unary or binary expression is parenthesized, preserving operator/operand order and grouping. Unary `+`, `-`, `~` and binary `+`, `-`, `*`, `/`, `%`, `**`, `<<`, `>>`, `>>>`, `|`, `^`, `&` are the only operators. Finite numeric JSON literals retain their numeric spelling, including signed zero. Schema-5 nonnumeric literal props remain in the normalized host program and consume no numeric output slot.

The existing structural DAG scanner now recognizes `inputs[n]` in addition to its unchanged owner-row and flat-range forms. Shared numeric subtree interning, structural keys, literal bit identity, 128-local cap, 32-KiB source cap and dependency-ordered declarations are reused. If bounded lowering or the emitted-body size fails, schema 2 omits the optional function and the runtime interprets the normalized data. No authored eligibility, owner grouping, reader history, runtime authority, host writer or physical layout changes.

Source cases cover repeated and nested subtree reuse, nonshared grouped expressions, signed zero, overflow followed by bitwise coercion, all accepted numeric operators, flattened input slots, schema-5 literal mixtures, identity fields, wrong input index and conservative aggregate/logical/conditional decline.
