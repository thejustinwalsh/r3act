# Authored lifecycle workload

This source-locked diagnostic mounts the same 256-row application through the public Native `@r3act/core` authoring surface and a React Compiler comparator. Each row has a local counter, a shared numeric step, authored transform/opacity/text, and an activation lifecycle. An ordered-array edit removes row 1, inserts row 256, and moves row 0 while retaining its host and local count. Two prestarted resources reveal independently. The Native arm uses `use(store)` and ordinary array `map`, so unsupported map structure remains on the generic keyed path; React uses `useSyncExternalStore`, keyed JSX, and layout effects. The Vite aliases point the public import to this checkout's runtime source; this is not installed-consumer evidence.

The fixed episode is mount, row 0 click, steps 1–60, keyed edit, detail reveal while health waits, health reveal, and disposal. `entry.ts` exposes `window.__authoredLifecycle` with `mount`, `clickRow`, `update`, `edit`, `settleDetail`, `settleHealth`, `inspect`, `dispose({retain})`, and `release`. Inspection reads actual DOM rows, styles, text, resource flags, and controller diagnostics; it performs no flush. The timing collector requires every update to have committed synchronously when its dispatch call returns. All DOM inspection and RAF settlement waits occur outside the measured intervals.

The gate freezes source and the debug Rust compiler binary before invoking one Vite build, captures both transformed arms, checks compiler hook sites, a generic array map, React Compiler runtime/memo use, and hashes every generated asset. `BUILD_CAPTURED_PENDING_PRIMARY_REVIEW` means the primary still must review the source, proof, transforms, and assets. It is not browser correctness evidence. A failed or incomplete proof remains in place; this script refuses to overwrite it.

The primary writes `proof-v1/timing-authorization.json` only after review. It must contain `status: "APPROVED_FOR_ONE_AUTHORED_LIFECYCLE_TIMING_PAIR"`, `kind: "timing"`, and SHA-256 fields `buildProofSha256` and `sourceLockSha256` binding the exact proof files. The runner invocation is:

The primary separately authorizes the heap pair after the timing receipt passes, in `proof-v1/heap-authorization.json` with the analogous status and `kind: "heap"`, both proof hashes, and `timingPairSha256` binding the completed timing receipt. Invoke the same runner with `--kind heap`. Each mode writes one exclusive receipt and refuses replacement. Each has its own 90-second total deadline, sequential Native-first fresh contexts, a headless GPU-disabled browser, and exact offline synthetic HTTPS asset replay. No server, external network, or focus-stealing window is used. Interruptions and failures preserve the first receipt and cleanup errors; do not retry for a favorable result.

The timing pair reports first update, nearest-rank within-page median and p95 of 60 dispatch-through-commit intervals, sum, mount, disposal, and a mount+sum+array-edit+disposal measured subtotal. The subtotal excludes local click, resource waiting/reveal work, and harness inspection; it is not total episode CPU. A RAF wait and complete row inspection follow each update outside the timed interval. Timer quantum is sampled separately. This is one fixed-order diagnostic, without warmup, cold-cache claim, population tail, CPU attribution, or a performance budget. Combined asset bytes describe this shared build and are not an equivalent-feature per-arm size comparison. The separate untimed heap pair forces GC and records raw CDP `Runtime.getHeapUsage` and `Memory.getDOMCounters` at baseline, mounted, updated/edited/revealed, disposed-controller-retained, and released-controller, plus signed changes from baseline. Those samples include browser/module/application costs; they do not isolate per-row allocation, establish a leak bound, or qualify retained-memory budgets. The existing physical selection HOLD and product release gates remain outside this episode.
