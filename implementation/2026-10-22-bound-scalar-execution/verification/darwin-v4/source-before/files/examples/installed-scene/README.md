# Installed DOM, Three and Dialog example

This private-alpha template uses only installed `@r3act/*` package exports. The package namespace is currently unpublished. Supply current local tarballs for `@r3act/core`, `@r3act/host-dom`, `@r3act/host-three`, `@r3act/react-bridge`, and `@r3act/vite` in place of the matching version entries in `package.json`, then install dependencies and run `pnpm check` and `pnpm build`. The Three TSX file selects the public `@r3act/host-three` JSX types; the DOM file selects core JSX types. Vite compilation and TypeScript checking are separate steps. The Vite configuration uses the compiler bundled with the installed `@r3act/vite` package; it has no checkout source aliases. The repository's `native-package-integration.md` explains tarball creation and supported compiler platforms.

The page has a native DOM root and a native Three root sharing one World and a numeric Store. The Three root creates real scene objects and owned geometry/material resources. This example does not set up a WebGL renderer; its browser view shows the scene's numeric state in accessible DOM text. The caller supplies `#dialog-portal` and keeps it alive until after native disposal. The controlled Radix Dialog is an independent React island whose portal and form are React-owned.

The page offers buttons for both independent loads, the grouped reveal, scene movement, and dialog interaction. The built page can run through an offline file route without a listening server. If a development server is used, follow the repository's Portless HTTPS workflow. It also exposes `window.installedScene` with methods `settleA()`, `settleB()`, `settleHealth()`, `updatePoint(next?)`, `reorder()`, `externalOpen()`, `externalClose()`, `removeDialog()`, `reinsertDialog()`, `snapshot()`, and `dispose()` for bounded conformance. The snapshot contains only serializable values. Calls that publish through the native queue or React island settle asynchronously; inspect after the corresponding DOM or status change.

A deterministic check starts with `domDetail: "waiting"`, `health: "waiting"`, `sceneSignalName: "signal-waiting"`, and `domPoint: "1"`. Call `settleA()` while B remains pending: detail stays waiting. Call `settleHealth()`: health can become `"healthy"` while A/B remain waiting. `updatePoint(2)` can advance the independent DOM/Three position while the resource group waits. Call `settleB()`: the declared cross-root reveal publishes detail `"3"`, joint value `"5"`, and signal x `5`; `revealCallbacks` becomes one with `revealView: "3:5"`. A later `updatePoint(4)` requests a declared cross-root Store cut, giving DOM/Three point `4` and joint value `7` when it commits. The ordinary event on “Move scene” uses the same controller path.

`reorder()` moves the keyed dialog wrapper while retaining its native owner and React form. `externalOpen()` or the trigger opens the controlled dialog; type in “Dialog note,” reorder, and inspect `noteValue` and `dialogRetained`. `removeDialog()` retires the island and portal content; `reinsertDialog()` starts a new lifetime. `dispose()` retires native roots, their owned Three resources and the React island. Its `borrowedAtHostDisposal` counters record whether the host left two caller-owned Three resources alone; the application then disposes those resources itself, making final `borrowedDisposed` counts one each. `snapshot().sceneChildren` then returns zero while the caller-owned Three `Scene` and portal element remain available. The snapshots and counters are conformance observations, not performance or accessibility certification.

Disposal may occur while the reveal is still pending. Its cancelled queue outcome is expected and does not count as a successful reveal or position callback; resource providers remain independently owned.
