# Portable source and installed consumer proof

The replaced mechanism was a Darwin-specific archived runtime/compiler baseline in the installed host-value proof. The invariant authority is the current shared native verification source selector, its copied-and-rehashed schema-1 manifest, the package report and its five current tarballs. The selected package compiler must match the executing platform, architecture and Rust target. This proof does not use historical baselines, proof receipts or generated dependency trees as source.

The installed consumer preserves the fixed host-value workload: public custom-host capture, mutable Three position and rotation, DOM style removal, scalar/retaining controls, keyed lifetimes, independent suspended work, reveal and empty cleanup. The Native and React arms use their public installed packages. React Compiler must actually compile `Hot` and emit its memo cache; the Native arm must contain the actual Rust-compiled owners. The browser checks ten equal output and lifetime stages over exact offline HTTPS assets. It is headless, GPU-off, interruptible and bounded to 90 seconds; no server or VM starts.

After the consolidated native platform/package gate, the verifier runs preparation in a new proof directory. Preparation copies the selected current source, source context, five tarballs, installed graph, compiler, transforms and assets, hashing both sides. It typechecks and builds the Native consumer. One untimed Native-first comparison build establishes actual React Compiler and Native owner transforms. The offline browser then proves the ten equal behavior stages:

```sh
node implementation/2026-10-19-portable-source-delivery/prepare.mjs --proof-dir implementation/2026-10-19-portable-source-delivery/proof-v1
node implementation/2026-10-19-portable-source-delivery/run-build-pair.mjs --proof-dir implementation/2026-10-19-portable-source-delivery/proof-v1 --phase proof
node implementation/2026-10-19-portable-source-delivery/verify-browser.mjs --proof-dir implementation/2026-10-19-portable-source-delivery/proof-v1
```

The primary then reviews `build-proof.json`, `input-lock.json`, `pair-proof.json` and `browser-untimed.json`. The `run-authorization.json` must contain `status: "APPROVED_FOR_ONE_BUILD_PAIR"` and their SHA-256 values under `buildProofSha256`, `inputLockSha256`, `pairProofSha256` and `browserUntimedSha256`. Only then does the verifier run the single timed fresh-process Native-first Vite pair:

```sh
node implementation/2026-10-19-portable-source-delivery/run-build-pair.mjs --proof-dir implementation/2026-10-19-portable-source-delivery/proof-v1 --phase measure
```

That pair writes `build-one-pair.json` and new `comparison-one-pair/` outputs. It requires every transform, asset and compiler metadata record to match the untimed proof hashes and paths. The browser records no runtime timing. One fixed-order build observation cannot qualify cold build, CPU, memory, runtime latency, presentation, other devices or a speed advantage. Any source, compiler, tarball, transform, asset, output, identity, lifetime or cleanup mismatch fails its proof and leaves the failed receipt intact.
