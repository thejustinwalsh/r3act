# Recovery contract and comparison protocol

`AsyncResource` is a one-shot record of one provider. Retry creates another resource identity. The authored native arm dispatches that identity through `resourceStore` under a declared transition and submits the same compiled tree to `NativeRootWorkQueue`. The queue orders publication for each participating root; an independent urgent Store update remains live. Cancelled queue work releases intent, while provider cancellation is caller-owned. A late provider result cannot authorize a retired candidate.

DOM, the forked DOM root, and Three share one World, Store and resources. The fixture checks their joint output and cleanup; it does not separately prove diverging accepted histories. The error renderer is generic. The direct closed-resource leaf in the compiler fixture is a separate narrow test: rejection declines selected closed preparation, releases the hold, and leaves the generic error path active. Nothing in the fixture treats an arbitrary error callback as a pure closed program.

The React comparison preloads the same number of deferred promises. It reads each selected promise with React `use`, surrounds it with Suspense and an ErrorBoundary, and updates resource identity through `startTransition`. Both arms use explicit accepted-view retention during queued work. The comparator does not use React's promise cache to manufacture sequential loading. The urgent output uses `useSyncExternalStore`; native uses the existing independent Store. One cancelled intermediate provider settles late before the final provider resolves.

The fixed sequence is initial accepted view → pending replacement with urgent progress → rejected provider/error view → queued retry with accepted error retention → explicit cancellation and newer retry → late stale settlement ignored → final recovery → balanced disposal → separate early disposal with late settlement. The timed interval begins immediately before the final provider is resolved and ends at the first matching MutationObserver notification. The verifier runs Native first, React second, each in a fresh page, and records the timer quantum and exact output. It does not isolate CPU or include paint.

The measured budget remains the plan's separate async UX gate; no threshold is inferred from this single pair. Source and compiler hashes, actual emitted component registrations, exact assets, browser request errors, output digest, lifecycle counts and post-disposal ownership form the correctness gate. A failed gate is retained, not replaced by favorable reruns. Whole-root guards and generic fallback remain in force.
