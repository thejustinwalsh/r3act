# Apple container Linux ARM64 route

Status: source prepared, **unexecuted**. This local route uses Apple container 1.5.0 with `CONTAINER_APP_ROOT=/Volumes/Depot/Containers/apple/data`. Service installation and start are separate user-controlled operations. The scripts never start or stop the shared service, publish ports, prune images or volumes, or touch another container.

`prepare-image.mjs` pulls the official `node:24.18.0-bookworm` ARM64 image and records its resolved OCI digest and Apple CLI/API version. It does not invoke the shared BuildKit builder. The first named, labelled bootstrap container installs Rust 1.97.1, Deno 2.9.7 and pnpm 11.25.0 into the owned workspace volume, verifies the Rustup and Deno release checksums, and records tool versions and download hashes in `toolchain-proof.json`. The bootstrap and every later container phase have deadlines and owned-container cleanup; failure logs stay in the exclusive image/evidence directories. Base image pull is separately bounded at the CLI, although an interrupted remote image transfer may need inspection before retry.

After primary source review, Luna may use these commands with new, absolute output directories:

```sh
node implementation/2026-10-18-native-platforms/linux/prepare-image.mjs --output-dir "$PWD/implementation/2026-10-18-native-platforms/linux/image-v1"
node implementation/2026-10-18-native-platforms/linux/run-linux-arm64.mjs --image-proof "$PWD/implementation/2026-10-18-native-platforms/linux/image-v1/image-proof.json" --evidence-dir "$PWD/implementation/2026-10-18-native-platforms/linux/evidence-v1" --phase bootstrap
node implementation/2026-10-18-native-platforms/linux/run-linux-arm64.mjs --image-proof "$PWD/implementation/2026-10-18-native-platforms/linux/image-v1/image-proof.json" --evidence-dir "$PWD/implementation/2026-10-18-native-platforms/linux/evidence-v1" --phase verify
```

Bootstrap creates one labelled, size-bounded named volume under Depot. Each phase uses a new short-lived labelled container with four CPUs, 6 GiB memory and a hard deadline; the named volume keeps the same Linux workspace and toolchain across phases. The checkout is mounted read-only, and bootstrap copies only product source, scripts, configs, CI/unit source and the explicit frozen Deno gate lock. It excludes host `node_modules`, Cargo `target`, `.cache`, `.git`, old verification directories and generated proof/evidence. `container-source-lock.json` hashes every selected source before and after copying. Later phases execute the copied control script, compare every copied file to that lock, and check the actual host control script against it. The host launcher hash, source-lock hash and toolchain-proof hash are bound into the owned-volume receipt. The shared native-platform runner creates its own fresh evidence directory, installs with the frozen lock and checks the actual Linux ARM64 target, compiler artifact and installed consumer.

Only after the correctness receipt passes and primary releases the benchmark should Luna run `--phase benchmark-prepare`. It performs the required untimed proof builds in the **same volume**, then copies reviewable evidence to the host while excluding installed `node_modules` except the exact compiler binary and manifest. Primary reviews `benchmark/proof-v1/build-proof.json` and writes the hash-bound `run-authorization.json` into that host proof directory. Luna then runs `--phase benchmark-run`, which copies only those authorization bytes into the volume, checks they bind the unchanged build proof, and executes the single native-first pair. `--phase archive` copies incomplete proof after interruption without rerunning work. `--phase finalize` deletes only the receipt-labelled owned volume after evidence review. Every phase has an exclusive receipt and raw host logs; a failed phase is not silently retried.

This proves a Linux ARM64 native build/consumer case inside a VM on the same Mac if the future gate passes. It is not a separate physical machine, cold-cache timing, runtime latency or hosted CI result. The required untimed proof builds can warm filesystem caches before the one timed pair.

## Docker/Colima alternative

`run-docker-arm64.mjs` uses an already running Linux ARM64 Docker daemon. It does not start, stop, reconfigure or prune the shared daemon and publishes no ports. Colima's current VM does not mount Depot, so this route transfers an explicit source snapshot through `docker cp` into an owned source volume, mounts that volume read-only during each phase, and exports an owned evidence volume back to an exclusive Depot directory after each phase. The workspace/toolchain and these transfer volumes occupy the Docker daemon's storage; Docker provides no per-volume disk quota here. The image proof records the actual daemon identity, root path, resolved official Node 24.18.0 Bookworm repository digest, ARM64 image ID and runtime limitation. A Colima VM on the same Mac is not independent hardware.

After primary source review, Luna may use these commands. The output directories must be new and their names must start with `image-docker-` and `evidence-docker-` so source selection excludes them.

```sh
node implementation/2026-10-18-native-platforms/linux/run-docker-arm64.mjs --phase prepare-image --output-dir "$PWD/implementation/2026-10-18-native-platforms/linux/image-docker-v1"
node implementation/2026-10-18-native-platforms/linux/run-docker-arm64.mjs --phase bootstrap --image-proof "$PWD/implementation/2026-10-18-native-platforms/linux/image-docker-v1/image-proof.json" --evidence-dir "$PWD/implementation/2026-10-18-native-platforms/linux/evidence-docker-v1"
node implementation/2026-10-18-native-platforms/linux/run-docker-arm64.mjs --phase verify --image-proof "$PWD/implementation/2026-10-18-native-platforms/linux/image-docker-v1/image-proof.json" --evidence-dir "$PWD/implementation/2026-10-18-native-platforms/linux/evidence-docker-v1"
```

The Docker route reuses `run-container.mjs` for bootstrap, native verification and benchmark phases. Source staging includes the exact current authored-lifecycle workload and current design/source-review inputs required by the shared runner; it excludes historical verification and proof trees. Bootstrap hashes all copied inputs in `container-source-lock.json`. The Docker launcher owns three labeled volumes and short-lived labeled containers, applies four CPU/six GiB memory limits and hard phase deadlines, and keeps original failure receipts and logs. `--phase archive` exports incomplete evidence without rerunning work. Benchmark preparation, reviewed authorization, one bounded benchmark run and finalization follow the same phase order and proof requirements as the Apple route. Finalization removes only the three receipt-labeled volumes after evidence review. A failed or interrupted run requires inspection of its host receipt and owned Docker resources before any retry; the script does not retry silently.
