# Urgent retained-prop slice: verification preparation

## Contract and evidence limit

The slice contract is in `../design.md`. The matched authored action is one synthetic DOM click on a button already mounted with `x = 1`, while sibling A has an accepted primary and its Store-selected resource is pending. The button click changes only the local state value to `2`; the rendered outputs are `data-x="2"` and inline `opacity: 0.2`, with constant text. Native uses the ordinary root event handler and its normal scheduler. React uses the ordinary handler. A's native source is `use(use(aStore))`; React changes A's selected resource inside `startTransition` so the accepted primary remains visible.

Before timing, each arm mounts and waits for initial readiness. It dispatches the A resource change, waits two animation frames, then verifies A's original primary node/text remains and its fallback was not inserted. Timing starts immediately before `button.dispatchEvent(new MouseEvent("click", { bubbles: true }))` and ends at the first matching `MutationObserver` callback that observes `data-x="2"` and opacity `0.2`. This is synthetic event-to-DOM-observer delivery, includes runtime scheduling and observer delivery, and stops before paint. It does not represent a physical human click, input-to-presentation, CPU time, frame time, or general UX.

One fresh build proof and one matched pair are allowed after the consolidated correctness boundary and primary hash-bound authorization. Browser work uses headless Chromium, GPU disabled, a hard 90-second interruptible deadline, no focus, and offline replay of only exact source-locked production assets at a synthetic HTTPS `.localhost` origin. No project server, Portless proxy, external network, TLS connection, trust change, retry, warmup, extra sample, or measurement comparison will be used.
