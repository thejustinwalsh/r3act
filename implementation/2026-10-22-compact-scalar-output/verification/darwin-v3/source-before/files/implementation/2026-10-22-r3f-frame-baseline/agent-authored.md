# Authored R3F frame arm handoff

The comparator replaces per-frame React subscription/reconciliation in the existing declarative React arm with ordinary R3F `useFrame` mutation of the 256 motion groups and one accepted-frame marker. The shared passive `{ phase, epoch }` input is assigned once before each public `rootStore.getState().advance()` call; that method reaches the pinned v10 scheduler's root step. Local activation controls remain `useState` setters and are committed with `flushSync`, followed by one manual step at each activation and reset. The graph remains JSX-owned by R3F, with 256 alternating motion components, retained children and 512 geometry/material resources. The renderer, camera, scene validation and shared draw/readback are inherited byte-for-byte from `scene.ts`.

The invariant authority for this arm is R3F's reconciler at mount/control commits and its `useFrame` scheduler at each frame. The authored callbacks directly mutate their own refs; they do not ask React to commit every frame. A user `useFrame` render-phase job performs no draw and suppresses v10's default render job, allowing the common harness to render once after scene validation. The job and the 257 update-phase callbacks all run through the real v10 scheduler. No private scheduler registration or callback invocation is used.

The source basis adds the exact R3F hook and `@pmndrs/scheduler@0.3.0` scheduler/types sources at immutable commits. `useFrame.ts` shows effect registration and cleanup; inherited `loop.ts` shows public root-bound advance and default draw takeover; `scheduler-v0.3.0.ts` shows `stepRoot` execution and the public render-phase job query; inherited `root.tsx` shows unmount callback after hook cleanup, root unregistration and scene disposal. The inherited provenance file is unchanged.

Proof-only per-update counters report 256 motion callbacks, one marker callback, one render takeover, zero local-control commits and zero draws during scheduler advance. The proof-only renderer wrapper preserves the renderer as `this` when calling the original method. It requires no draw during setup and the two control steps, exactly `epoch - 1` shared draws before each frame, and exactly 72 shared draws after the episode. The timing path does not wrap the renderer and returns no counters. Teardown reports zero authored active frame callbacks/setters and checks the public scheduler for no update/render user jobs under the captured root ID after the actual R3F unmount callback. `FrameNextControls.rootId` is public in the pinned scheduler types; `getScheduler().hasUserJobsInPhase` is a public method on the exported scheduler class. This root-job query is an observation of public scheduler state; the source's root teardown supplies the lifecycle explanation. No build, typecheck, browser proof or benchmark was run by this implementation agent.

The required falsifiers at the tooling boundary are: installed React Compiler transformation of the authored component source; all four arms building from the pinned dependency set; exact per-frame callback counts, unchanged local-control commits and zero scheduler draws in all 72 proof samples; scene/retained-object/resource/pixel equivalence; 72 actual shared renderer calls; 512 exactly-once disposals; zero registered setters/frame jobs and stopped root after unmount. The new arm is an idiomatic direct-mutation baseline with different semantic work from native Store acceptance; it cannot alone establish a Store or coherence contract advantage.
