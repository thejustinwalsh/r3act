# World finalization handoff

The proposed public World publication guard was withdrawn before verification. A privately branded World may inherit a Proxy-backed prototype chain; resolving effective public methods by walking that chain can invoke a trap during the supposed callback-free finalization segment. A strict exact-prototype guard would instead reject supported real subclasses and public validation overrides.

The selected boundary is a canonical internal World protocol for accepted-state bookkeeping after the last external callback. Public World capture and validation retain their existing observable behavior, including subclass callbacks. Root integration owns the internal finalization calls and must keep exact cell/version acknowledgement and newer-action preservation. The passive capture helper and its strict `cellHandle`/source/version/lineage descriptor audit remain unchanged.

No publication guard, publication trust key, or reusable permit was retained. The finalization protocol now has two module-internal exported operations: `canRetireOwnedWorldOwner` privately checks a committed owner and every descendant for zero numeric lanes, and `retireOwnedWorldOwner` rechecks the same admission before invoking shared private recursive destruction. Staged owners decline. Public `destroyOwner` still recursively calls public overrides. Private retirement shares the existing owner maps, capability revocation, lane cleanup and dirty journal; it adds no identity registry. Numeric lanes decline because their column storage is externally reachable and lane cleanup could invoke a caller trap.

Root must call fresh preflight before host writes and after host callbacks, before accepted pointers advance. The last possible caller callback is therefore outside `retireOwnedWorldOwner`; after its brand and primitive-owner checks, the zero-lane private map walk and private recursive destruction use only canonical runtime records. A lane that appears during host work makes the final preflight decline. No tests, builds, benchmarks, browser workloads, servers, or VMs ran here. The consolidated correctness gate should falsify this boundary if an inherited callback runs after accepted Store history advances, a lane-bearing subtree retires, a retained capability survives, or a newer cell action is cleared.
