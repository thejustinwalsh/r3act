Let `N` be live entities, `U` writes, `S` unique dirty sources, `D` dependency edges reached, `A` unique affected projections, `P` projections evaluated, `E` equalities checked, `W` actual host writes, `K` keyed edits, `I` repaired index entries, `V` owner/lifetime visits, `Q` pending actions acknowledged, `R` roots and `C` simultaneous candidates. These are work counts, not a claim that any one representation achieves the bound.

| Problem | CS classification | Desired work and unavoidable work | Decision evidence |
| --- | --- | --- | --- |
| Scalar-to-prop updates | Incremental computation, partial evaluation, materialized views | Sparse target `O(S+D+A+W)` plus validation/ack; dense `O(Nk+W)` for `k` slots/row. Every changed output requires a decision and every required host mutation costs `Ω(W)`. | Reached sinks, fanout, equal-output rate, projection and host fractions, callback/effect proof. |
| Dirty selection across densities | Physical query planning over one logical dependency relation | Sparse edge walk, marked tile scan, or dense range scan. A source with huge fanout can be output-dense even when `S/N` is tiny. Online selection has its own cost and tail. | Crossovers by `N`, `A/N`, fanout, clustering, `W/N`, JIT/cold state and selection overhead. |
| Keyed insertion/move/removal | Dynamic ordered sequence plus incremental materialized-index maintenance | At least `Ω(K + changed owner/binding records + host placements)`; global filter/sort may touch `Ω(N)`. Tree lookup `O(log N)` does not remove owner or host work. | Count owner visits, rank/index repairs, row-token rebuilds, binding repairs, placements, resource disposal by edit position and kind. |
| Root/store/local-state coherence | Multi-version concurrency control and optimistic validation | Capture read footprint, validate it, serialize conflicting publication, acknowledge exactly the captured action cutoff; retention cost rises with `R,C` and history depth. | Reentry, stale cuts, fork divergence, disposal, partial host failure and exact accepted-view observations. |
| Async resources and Suspense | DAG critical-path scheduling and display-state policy | Completion cannot beat longest hard value dependency plus resource latency; discovery and bounded prefetch may start independent work sooner. | Request-start/finish timeline, prerequisite identity, stale result rejection, reveal/fallback and urgent-input latency. |
| Independent transitions | Conflict detection and serializable publication | Disjoint work may prepare together; overlapping writes require ordering/rebase or explicit replacement. Root overlap is only a coarse proxy. | Operation keys, read/write sets, host-domain overlaps, rebase work, cancellation and reveal outcomes. |
| Workers | Parallel task DAG with communication overhead | Benefit only when pure compute saved exceeds transfer, startup, queueing, result validation and stale-work cost. Host mutation remains on owner thread. | Named CPU-heavy task, immutable snapshot size, compute/transfer crossover and urgent-input effect. |
| Compiler, hooks, HMR, custom callbacks | Effect/alias/escape analysis and revisioned ABI | Static proof reduces repeated interpretation only when observable reads/effects are sound; opaque behavior has a conservative cost. | Supported syntax corpus, actual provenance, callback boundary, site correspondence and revision invalidation. |
| DOM/Three/resources/React island | Host capability and lifetime ownership | Host operations, object identity and disposal have irreducible observable work; a React island has a separate commit domain. | Copy/borrow/retain and owned/borrowed declarations, writer cost, event/lifecycle conformance. |
| Server streams | Replication, log ordering and reconstruction | Versioned snapshots/deltas, dedup, replay, recovery, schema/code revision; CRDT merge only when multiple concurrent writers are required. | Concrete delivery/reorder/duplication workload and ownership protocol. |
| Maintainability | Invariant ownership and state-space reduction | Complexity is driven by mutable authorities, fallbacks and interactions more than line count. | Human comprehension/extension results, invariant fanout, retired mechanisms and migration cost. |

These are distinct graphs: ownership forest, source-to-sink dependencies, ordered children, task prerequisites and publication groups. They share stable entity incarnations and revisioned views; they must not be collapsed into one graph that loses each relation's semantics.

## 4. The causal cost budget that must precede a physical choice

For the current timed update, use a nonoverlapping ledger:

`T = dispatch/coalesce + select + capture/gather + validate + mirror/stage + project/equal + host application + acknowledge/publish + allocation/GC + unattributed residual`.

Report cold compiler/plan preparation, mount, retained memory and teardown separately. Structural operations add sequence edit, owner discovery, binding repair and placement. Async operations add discovery, queueing, network/resource time, stale work and reveal. Do not charge a nested function to both its parent and child. For a candidate change `j`, measure a semantically removable amount `R_j`, retain a necessary floor `F_j`, and estimate new cost `δ_j`; the optimistic total is `T'_j ≥ T - R_j + δ_j`. With removable fraction `p_j=R_j/T`, even a free replacement is bounded by Amdahl: maximum speedup `1/(1-p_j)`. Combine phase uncertainty and interaction overhead before claiming the sum of several savings. A sample profile is not `p_j`.

The locked dense median ratios imply required native reductions, **assuming the paired React denominator stays fixed**:

| Rows | To median parity | To 0.8 paired ratio | Current p95 ratio |
| ---: | ---: | ---: | ---: |
| 128 | 6.0% | 24.8% | 1.0223 |
| 1,024 | 24.4% | 39.5% | 1.2437 |
| 10,000 | 33.2% | 46.5% | 1.0890 |

The registered strong-win gate requires two of three size medians at or below 0.8; parity requires all three medians and p95 at or below 1. The older mixed-workload gate has its own p95 criterion; do not substitute one gate for another. At 1,024/10,000, a proposed phase that occupies less than 39.5%/46.5% of *current total* cannot alone deliver a 0.8 ratio, even if entirely removed. The host floor must be measured with identical mutation semantics; if unavoidable host work plus residual exceeds the target total, report infeasibility for this API/output workload. Do not silently change outputs, timing interval or React baseline.

For every proposed optimization, the decision sheet must state: source/build identity, workload and output count; current total median/p95; phase count/time and interval; maximum removable share and confidence; retained obligation; new bookkeeping/copy/selection cost; startup/memory/GC cost; predicted total and p95 bounds; falsifier. A transformation that adds a cache but retires no measured work has no positive budget.

For an added cache or compiled plan with cold cost `C0`, extra retained memory `ΔM`, per-update saving `ΔT` after all new maintenance, and a realistic lifetime of `F` updates, break-even requires `F·ΔT > C0` and a declared memory budget must accommodate `ΔM` without unacceptable GC or teardown cost. Report `F` from the named workload; do not amortize setup over an infinite animation. If `ΔT≤0`, no reuse horizon recovers the change. If the output/host floor already exceeds the target, changing lookup structure cannot fix it.

## 5. Unified semantic contract

### Identity, reads and compiler proof

An entity handle is `(entity identity, incarnation)`, independent of physical row or keyed order. A compiler site identity includes module revision and repeated-scope key. Moving a keyed owner preserves incarnation, state, host identity and hook meaning; removal revokes them. The retained VDOM remains the observable structure and general reconciliation oracle.

Rust/OXC emits a versioned **semantic plan**: source/sink and owner/site identities, structural operations it can prove, read/effect provenance, output equality and host capability. The same module revision emits code and plan. Its **physical plan** chooses sparse, clustered or dense traversal and may change without creating another state/VDOM universe. Unsupported authoring semantics produce an explicit diagnostic; safe unspecialized syntax uses the native generic path. A compiler proof covers only closed expressions on controlled inputs. Runtime-observed reads describe one execution's footprint; controlling inputs must rerun it when a future branch could change reads. Author declarations convey capability and are never silently upgraded to purity. Unknown reads are opaque, never an empty edge set.

The internal owned cut contains code revision, root incarnation, structural base, source incarnations/versions, slot/value pairs, captured action cutoffs and staged outputs. Public array-like inputs preserve their observable getter/exception order and live checks. Conversion cost belongs in the ledger. Only compiler/runtime-created private cuts can use stronger ownership rules; `readonly` types and function-shaped properties do not prove them. For eligible state-setting operations, chronological updates to one slot may coalesce to the last value; ordered commands retain order. Immutable scalars compare with `Object.is`, preserving signed zero and `NaN`. Mutable object outputs follow explicit host value/copy rules.

Pure closed computations may prepare, speculate and retry. Tracked dynamic computations may stage only if effect-free, all participating sources are versioned, and controlling inputs or a conservative boundary trigger reruns them. An untracked global needs a versioned adapter to gain freshness. Opaque/effectful computations are excluded from specialized or suspending retryable preparation unless an explicit capability establishes the missing contract. The supported generic boundary runs opaque work non-speculatively once per stated invalidation; it promises neither exact freshness for untracked globals nor rollback of escaped effects. Irreversible effects belong after publication, with documented failure rules. HMR preserves a site only on proven correspondence; uncertainty remounts the smallest affected owner and revokes old tasks, subscriptions, leases and plans.

### State, publication and failure

Keep three separate times: latest domain/World state and chronological pending actions; private candidate captured inputs/outputs; and each root's accepted view/history. Forks may intentionally show distinct accepted versions. A synchronized group names the roots/frontiers that must move together. The current root source-history meaning is mandatory even if its physical Map changes later.

Preparation is private and may run eligible callbacks. Admission validates live source and entity versions, exact read footprints, structural base, writer lifetime and host ownership after the last preparation callback, in a callback-free region. This preserves the getter-revocation counterexample. Host application is serialized per owning host domain and does not yield. The publication states are **prepared → admitted → applying → published**, or **applying → failed-partial**. During applying, managed accepted-view reads return the previous accepted view; reentrant dispatch queues later work, and destructive disposal waits for the active batch. After all host writes succeed, a callback-free pointer swap advances every group member and exact action acknowledgements; only then do notifications and committed lifecycle work run. Newer reentrant actions remain pending.

Arbitrary host writes cannot generally be rolled back. If a writer partially applies then throws, keep accepted pointers/history unchanged, stop writes, retain the receipt, quarantine that publication domain, and use explicit disposal/remount from the last accepted snapshot or terminal failure. Never blindly replay an unknown partially applied custom writer. Postpublication notification/effect errors do not reject the published view. The linearization claim covers managed accepted pointers and subsequent notifications; it does not claim atomic paint across hosts, observations inside custom setters, raw domain-head reads, or a React island's independent renderer commit. Direct host mutation/destruction outside the publication API violates the adapter contract.

### Structure, tasks and hosts under the same receipt

A keyed delta repairs order, binding/dependency membership, row tokens and placement under the same accepted receipt as numeric changes. A move retains entity incarnation; a removal revokes source/writer/task eligibility before a stale numeric cut can apply. Numeric admission validates the resulting structure base. The general VDOM path handles unproved filter/sort/opaque transforms.

Task identity includes operation, actual input revision, code revision and owning lifetime. A stale task result is discarded when its inputs change even if a root candidate can rebase. Distinguish hard value prerequisites from optional discovery/prefetch, operation replacement keys from read/write conflicts, publication serialization from reveal grouping. Same-root disjoint preparations can coexist; overlapping output writes publish in order, rebase pure affected derivations or explicitly supersede. A revealed Suspense boundary retains its accepted UI while a new candidate waits; first-load fallback, error, disposal and transition animation are separate policies.

Hosts declare scalar, copied-value, borrowed-for-call or retained-reference prop semantics. A retained reference cannot use reusable scratch storage. Resource handles declare owned or borrowed disposal, including shared ownership. DOM/Three namespace/type generation does not prove copy or lifetime semantics. React islands receive committed boundary snapshots and retain their own commit domain. Streams later use versioned snapshot/delta replay with dedup and recovery; CRDT merge enters only for a real concurrent-writer requirement.

### Dependency-scoped coherence: required next capability

Dependencies choose affected consumers; transaction intent chooses which outputs must advance together. Neither a common ancestor nor membership in one store creates a transaction by itself. In a scene, a position action reaches `mesh.position` and `outline.position`; that pair may publish while an unrelated health resource remains pending. A consumer of both position and camera has a real joint read footprint, including the inputs controlling which branch it reads. Multiple host roots can participate in the same declared transaction while sharing the existing World/store authority.

A candidate replacing a complete tree or cache still requires its whole-root publication and VDOM bases. Those checks must remain until the replacement is expressed as a mergeable delta. A scoped delta must identify its owner incarnations, code revision, complete read/control versions, actual sink writes and writer lifetimes; it patches those records in the current accepted view rather than installing its captured whole cache. Admission validates these identities after the last callback. An unrelated accepted delta may intervene only when the captured reads, controlling inputs, structure and target writer generations still validate. Overlapping writes serialize or reprepare; an obsolete input or reused owner never gains freshness from rebasing a root version.

Use existing source versions, owner identity and publication coordination. Do not introduce a parallel mutable conflict/version world. Compiler dependency metadata selects work but does not infer a user's transaction intent or certify an extension callback as pure. Opaque work retains the documented conservative boundary and generic reconciliation fallback. Dense and sparse execution must share the same logical footprints and accepted history.

For a declared DOM/Three group, prepare every required delta, admit every member, apply required writes synchronously before the application's renderer observation boundary, finalize every internal accepted storage record, then publish callbacks. An independent transaction may proceed while another waits on resources. A stale retained view requires an explicit reveal policy. Custom setters may observe intermediate physical writes; arbitrary host mutations have no general rollback. This is managed accepted-state coherence, with no claim of cross-renderer visual atomicity or coordination with an independent React-island commit.

The finite acceptance slice is: mergeable retained-prop deltas first, then structural/cache deltas, then resource/reveal admission. Its regressions must include nested sparse and dense scenes, position/outline versus independent pending health, a joint position/camera consumer, an intervening unrelated commit, overlapping writes, source replacement, remove/reinsert, stale code, forked accepted histories, partial host failure and disposal. The 17 October retained-prop slice implements scoped admission for runtime-owned closed primitive bindings through explicit cell/root transaction sets. The subsequent structural/cache slice adds explicit existing-row move/remove cuts over selected collections, current ancestor-cache patches and shared transaction grouping. The 18 October integrated extension adds joint closed numeric/keyed cuts and allows unrelated Store/resource/Suspense work to remain pending without advancing its history. Static primitive intrinsic VDOM insert/replace deltas are supported; authored insert/replace remains generic because callback purity is unproved. Whole-tree/cache replacements keep whole-root validation. See `implementation/2026-10-17-retained-deltas/design.md` and `implementation/2026-10-17-scoped-structure/design.md` with their source-locked verification receipts. General structural/cache and resource/reveal admission remain open; these semantic checks establish no speed or cross-renderer visual-atomicity claim. The 18 October slice passes 813 runtime tests and installed private-alpha package execution; its one descriptive mixed browser pair is slower than React Compiler (0.85 / 0.50 ms median), with no qualification. See `implementation/2026-10-18-first-pass/` for source locks, failures and the full remaining-work ledger.

## 6. Ranked physical choices and rejected shortcuts

1. **One semantic plan with three eligible traversal families.** Sparse compiled fanout/affected-sink dedup serves few reached outputs; marked owner/archetype tiles serve clustered intermediate activity; dense prepared ranges serve high reached-output density or known full updates. Choose by compiler-known shape first, measured batch facts second. Count selector overhead and switching tails. This is the leading *architecture*, not an approved crossover or claim of speed.
2. **Compiler-owned cut and generated vertical numeric path, conditional on causal savings.** The strongest plausible dense opportunity is to remove measured repeated resolution, gathering, mirror/stage or dispatch work while preserving validation, exact acknowledgement and host writes. It must replace named passes rather than add a fourth buffer. The existing generated arithmetic kernel alone did not win end to end; further specialization is justified only where the ledger shows enough removable work.
3. **Proven local structural deltas with existing bounded buckets or indexed arrays.** First remove whole-region owner discovery and binding reconstruction for a local edit while preserving VDOM fallback. Compare sequence families only after those counts shrink. Object buckets have narrow mechanism evidence; arrays may be preferable when scans/tails dominate. A B+ tree/rope stays on hold until sequence/rank work, after integration, is a material measured bottleneck.
4. **Conflict-aware async preparation and reveal over the same receipt.** This is a semantic completion path, not an assumed performance winner. Current frontier results support automatic parallel *resource starts* for known independent keys; equal React preloading matches it. Worker execution needs a separate CPU break-even study.

Discard as current solutions: a universal SoA VDOM, a second independent dirty/version registry, a B+ tree chosen from asymptotics alone, deletion of live public validation or accepted root history, a generic speculative callback fallback, a Wasm rewrite, workers for cheap DOM arithmetic, and CRDTs for one-way stream delivery. Each either breaks a known contract, adds bookkeeping without retiring measured work, or lacks a workload showing an end-to-end benefit. Direct host writers may estimate a floor under identical semantics; they are a diagnostic, not a substitute product architecture.

## 13. Formal work and memory analysis for the named algorithms

Assume expected `O(1)` Map/WeakMap operations only for ordinary hash behavior; adversarial collision, GC and JIT deoptimization can violate that expectation. Let `B` be retained binding edges, `H` be host nodes, `M` mounted keyed siblings, `b` a bucket capacity, `d` owner depth, `τ` touched tiles, `q` tile width, `L` task dependency edges and `T` tasks. Each bound below excludes unpredictable JS engine and host constants unless named explicitly.

| Path | Current or proposed work | Memory, cold and adversarial case |
| --- | --- | --- |
| Current prepared row cut | Expected `O(U + Σ_r k_r + Σ_i f_i + P_changed + W)` as traced above; worst case `Θ(B + W)` when one source fans to every sink, and `Θ(Nk+W)` for all rows dirty. Every required host write is `Ω(W)`. | Mounted state, VDOM and edges `O(Nk+B+H)`; Root token/scratch capacity tracks peak cut and VDOM staged capacity can reach `r × sinks/row`, retained until release. Cold token preparation and JIT costs are not included in warm update. Adversary: alternating 1-cell and 10k-cell cuts retains large buffers while cold sparse latency pays cache and branch overhead. |
| Proposed exact sparse | Invalidate `S` sources, walk `D` edges, deduplicate `A` sinks, gather each sink's `k_a` inputs, compare and write: `O(S+D+A+Σ_a k_a+W)` plus validation/ack. If shared sinks are reached repeatedly, dedup prevents repeat projection but cannot skip edge visits. | Static adjacency `O(B+N)`, dirty membership `O(S)` active with mounted reusable nodes, dedup epochs `O(A)` or `O(total sink IDs)`. High fanout from one source makes `A=Θ(N)`; a sparse selector then competes poorly with dense sequential traversal. |
| Proposed clustered tiles | Mark `τ` tiles from dirty edges, scan at most `τq` slots, project reached outputs and write `W`: `O(S+D_mark+τq+W)`. | Tile directory/marks `O(N/q + B)` or less if derived from existing owner layout; relocation must repair membership. Adversary: one dirty row in every tile gives `τq≈N` plus mark overhead. No threshold follows from asymptotics because JS cache behavior and host calls dominate constants. |
| Proposed dense | Walk `N` homogeneous rows and `k` declared slots: `O(Nk+W)` with low selection overhead. | Numeric columns may use `O(Nk)` contiguous scalar bytes, while owner/host references still need `O(N+H+B)` and lifecycle indexes. Cold compilation, columns and shape transitions must be amortized over real reuse. Sparse one-cell updates are adversarial. |
| Current/proposed local keyed delta | Eligible collection delta prepares `K` operations plus inserted/replaced subtrees `Z`, region lookup, binding/index changes `I`, host placements/disposals `W_s`: expected `O(K+Z+I+W_s+lookup)`. Fallback generic reconciliation can be `Θ(M+Z+W_s)`, and historic owner path visited `Θ(M)` for one edit. | Indexed flat array has `Θ(M)` suffix shifts/position rewrites for middle edits. Current object-backed `KeyedRegionBuckets` uses a key→entry Map, linked buckets capped at `b`, one/two-bucket split/merge/rebalance and local reindex, so a lookup is expected `O(1)` and an insert/remove/move is worst-case `O(b)` bucket work under ordinary Map behavior; full iteration is `Θ(M)`. It stores `Θ(M)` entry objects plus `O(M/b)` buckets, with a full new bucket/entry construction cost at mount. A B+ tree offers `O(log_b M+b)` order edit in an abstract RAM model but still pays `I+W_s`; JS allocation/scan costs are unmeasured. Global filter changes `Θ(M)` outputs and naturally pays broad work. |
| Store/candidate snapshots | Prepare work proportional to read footprint plus affected owners; validate `O(|read set| + changed structural bases)`, publish/ack `O(R_group + Q)`. Rebase recomputes affected pure derivations; opaque work cannot be retried freely. | Retained accepted history grows with forks and in-flight candidates: at least `Ω(R+C)` frontiers plus values/footprints they keep alive. Compaction needs oldest-live frontier, task/candidate leases and disposal. An unbounded pending fork is an adversarial retention case. |
| Task DAG | The abstract CSR build/validation target is `O(T+L)`. Current `defineTaskGraphPlan` is a build-time fixture compiler and uses `dependents[node].includes(task)` to deduplicate each insertion, so worst-case construction can be `O(T+L²)` under one high-fanout node; production Rust should emit packed edges directly. Current prepared scheduler validation is `O(T+L)`. Ready heap operations cost `O(T log T)` plus `O(L)` dependency bookkeeping; completion lower bound is longest hard dependency chain plus external resource latency. | Plan `O(T+L)`, candidate values/results `O(T)` plus payloads. A promise starts I/O/concurrent asynchronous work but a long synchronous callback still blocks input. Worker break-even is compute saved `> transfer + startup + queue + result check + stale work`. |

For any sparse/dense crossover, compare measured *total* models on the same output: `C_sparse = a_s S + a_d D + a_a A + a_g Σk_a + C_select + C_validate + C_host(W)`, `C_tile = b_s S + b_t τq + C_mark + C_validate + C_host(W)`, and `C_dense = c_r Nk + C_validate + C_host(W)`. The coefficients are engine/workload-specific unknowns. The host term cancels only when all plans make identical writes in identical order; otherwise compare it explicitly. A static compiler can eliminate ineligible plans and choose for known full-update shapes. A runtime policy can use already counted `A`, tile marks and structure revision, but charging extra enumeration just to estimate density may erase the gain. Hysteresis is useful only if a measured switching tail exists. Never use a hard-coded percentage derived from the old notebook mechanism sweeps.

`WorldDirtyJournal.markPrepared/deletePrepared` are expected `O(1)` per active membership under ordinary Map behavior and retained token validity; `entries()` and `clear()` are `Θ(active dirty pairs)`, while `removeOwner` visits its retained sites. Its memory scales with **mounted sites ever prepared and not retired**, even when no pair is currently dirty. This is an amortization benefit for repeat frames and a retention cost for large transient worlds. RootWorkQueue's default two stale retries bound retries attributed to stale root versions; dynamic resource refresh can trigger further preparation, so this is not an absolute bound on all attempts, user callback duration or queue occupancy. For bounded concurrency `c`, a task schedule's elapsed time has a work/span lower bound `max(critical hard path, total non-overlappable service/c)` before provider/network limits; the current main-thread promise scheduler has `c=1` for synchronous JavaScript computation despite overlapping asynchronous resource waits.

The output-sensitive lower bound is central: if all `N` rows produce `k` changed host props, exact semantics imply `P+W=Ω(Nk)` even with perfect dependency lookup. If all outputs are equal, equality can reduce `W` but at least the affected output decisions remain. An opaque mutable vector can require a host write even when its reference is unchanged. For one local move, necessary work can approach `Ω(1 + host placement)` only if owner, binding and anchor identities already exist; otherwise deriving them may cost `Ω(M)`. A tree changes sequence lookup complexity, not the lower bound on changed owner/host records. A renderer-level optimization cannot produce presentation smoothness simply from lower measured JavaScript CPU; the 8,192-segment Snake evidence is the concrete counterexample.

## 14. Algorithms and ABI: precise proposed design

The following sketches are **design notation**, not code to paste into the repository. Their types separate semantic facts from physical indexes. A runtime may implement them with the existing classes; the authority and proof rules, rather than a literal class layout, are the requirement.

```ts
type EntityRef = { id: number; incarnation: number };
type SiteRef = { moduleRevision: string; componentSite: string; scopeKey: string };
type SourceRef = { entity: EntityRef; site: SiteRef; slot: number };
type SinkRef = { entity: EntityRef; hostKey: string; prop: string };
type Provenance =
  | { kind: "closed"; ownedInputs: readonly number[]; effectFree: true }
  | { kind: "tracked"; versionedSources: readonly SourceRef[];
      controlInputs: readonly SourceRef[]; effectFree: true }
  | { kind: "declared"; capabilityId: string }
  | { kind: "opaque" };
type SemanticPlan = {
  abiVersion: number; moduleRevision: string; site: SiteRef;
  sourceToSink: readonly { source: SourceRef; sink: SinkRef }[];
  outputs: readonly { sink: SinkRef; provenance: Provenance;
    valuePolicy: "scalar" | "copy" | "borrow-call" | "retain" }[];
  structuralProofs: readonly { region: string; operations: readonly string[] }[];
};
type PhysicalPlan = { semanticRevision: string;
  traversal: "sparse" | "clustered" | "dense" | "generic";
  reason: string };
type HostWriterCapability = {
  hostId: string; hostRevision: number; writerGeneration: number;
  value: "scalar" | "copy" | "borrow-call" | "retain";
  resource: "none" | "owned" | "borrowed" | "shared-owned";
  mayThrow: boolean; ownsPublicationDomain: boolean;
};
type TaskResultStamp = { taskId: string; operationId: string;
  codeRevision: string; owner: EntityRef;
  inputVersions: readonly { source: SourceRef; version: number }[] };
```

The compiler emits `SemanticPlan` and executable projection code from the **same revision**. Registration validates schema and sinks once, as current `normalizeCompiledStateLayout`/`associateCompiledOwnerUpdateProgram` already do for their narrower ABI. The module registry is the sole plan-revision authority; HMR either proves a site mapping or remounts. The dependency authority owns the logical source→sink relation. CSR, tile membership, dirty epochs and row-token caches are derived physical indexes with explicit invalidation on structure/site/source lifetime changes. A host registers capabilities for a writer generation and revision; it is not inferred from TypeScript shape. An extension declaration may select a host capability but cannot turn an opaque function into a closed proof. A `TaskResultStamp` is validated against actual input versions and owner lifetime before reveal or reuse; operation/root version alone is insufficient.

```ts
type Cut = {
  root: EntityRef; codeRevision: string; structureBase: number;
  reads: readonly { source: SourceRef; version: number; value: unknown }[];
  actionsThrough: readonly { source: SourceRef; version: number }[];
  outputs: readonly { sink: SinkRef; value: unknown; writerGeneration: number }[];
  writes: readonly SinkRef[];
};
type PublicationReceipt = { groupId: string; roots: readonly EntityRef[];
  hostBases: readonly { hostId: string; version: number }[];
  codeRevision: string; cuts: readonly Cut[];
  status: "prepared" | "admitted" | "applying" |
    "published" | "failed-partial" };
```

**Prepare a cut.** Read immutable or versioned inputs once into private storage, maintaining public getter order on the public API. Snapshot the exact pending action cutoff. Track dynamic source reads, controlling inputs, entity incarnation and structural base. Deduplicate affected sinks so each pure projection runs once per cut. Stage outputs and host operations without exposing them. Closed pure work may retry; effect-free dynamic work may retry after footprint/control invalidation; opaque work follows its non-speculative explicit boundary. No host mutation occurs in this stage.

**Select a traversal.** Use compiler eligibility first: homogeneous closed numeric rows may use dense; proven source fanout may use sparse; existing stable owner tiling may use clustered. For a batch, obtain `S,D,A,τq` from work already performed. Evaluate measured crossover surfaces rather than a fixed density threshold. If determining `A` itself requires walking all edges, charge that work before comparing plans; a compile-time known full update may choose dense without that enumeration. Record chosen plan and fallback reason. All plans fill the same `Cut.outputs` identity space and use the same equality/writer policy. This is physical query planning over a single semantic relation, not three independent renderers.

```text
prepare_delta(changed_sources, plan, accepted_view):
  cut = capture_exact_actions_and_versioned_inputs(changed_sources)
  candidates = unique_reached_sinks(plan, cut)       // or selected tile/dense traversal
  for sink in candidates in defined dependency order:
      require sink incarnation and code revision live
      next = evaluate_effect_free_projection(cut, sink)
      if value_policy_requires_write(sink.last_accepted, next): stage(sink, next)
  return cut

admit_and_publish(group):
  lock each affected host publication domain in canonical order
  validate all read versions, incarnations, structure bases, writer generations
  if stale: unlock; discard or reprepare only eligible pure work
  set group.status = applying
  apply staged host operations synchronously; queue reentrant dispatch/disposal
  if host throws: quarantine touched domains as failed-partial; keep accepted views old
  else: swap every participating accepted pointer; acknowledge captured cutoffs
        set status = published; release locks; notify and run committed lifecycle
```

The sketch is intentionally stricter than some existing paths. Admission performs no user callback between final validation and host application. A callback during preparation can invalidate earlier leases; it must be followed by validation. Serial host application gives a defined managed-read boundary, **not** database serializability over arbitrary DOM/Three/custom-host observations. If a host writer throws after prior writes, the algorithm cannot roll those writes back. Quarantine/remount is required; a no-throw preflight contract is an optimization only for host implementations that can actually guarantee it. During applying, managed accepted reads remain old; raw World head and a custom setter's direct host inspection lie outside that guarantee.

**Exact acknowledgement.** Given captured action version `v` for source `s`, clear only pending actions at or before `v` that this receipt consumed; preserve any action with version `>v`, including reentrant dispatch. Advance the root accepted value to the staged value only after successful host application. For a forked root, acknowledge only that root's accepted frontier; a shared chronological store log retains entries needed by other roots. Current `#acknowledgeNativeCellCut`, `clearCellChangesThrough`, `clearNativeThrough`, and `StoreRenderTransaction.commitAfterValidatedRender` are the existing narrower operations to map onto this rule. Do not replace them with a broad `clear()`.

**Keyed delta.** A compiler proof may emit an ordered operation log `(insert|remove|move|replace, key, beforeKey, subtree)`. Validate all keys, anchors, base version, owner incarnations, callbacks and binding shapes before the first host write. Use existing key→bucket/slot and owner→binding indexes. An insert allocates a new incarnation and attaches only its subtree; a move changes placement token and one host placement while retaining owner/state/ref; a remove revokes the incarnation, detaches bindings/events and disposes owned resources after the safe host phase. Update order and derived indexes under the same receipt as numeric outputs. For unsupported transforms or unsafe callbacks, run generic VDOM reconciliation. The operation log's local time is `O(K+Z+I+W_s)` only when lookup/repair is local; count those units instead of assuming it.

**Scheduling.** Build one hard-prerequisite DAG for task values and a separate conflict graph for host/store writes. The ready frontier launches a task when its hard inputs exist, within provider backpressure and `maxConcurrency`; optional discovery manifests may start only permitted effect-free/idempotent loaders with cache identity. Tag each result with input revision, task ID, code revision and owner incarnation. A changed input invalidates descendant outputs (the current scheduler already does descendant invalidation for reuse); a stale result never gains freshness merely because the root candidate rebased. Same-root disjoint operations prepare concurrently, but publish through one host authority; explicit equal operation keys replace prior work. A revealed Suspense boundary keeps its accepted UI while waiting, first load may show fallback, and error/disposal has an explicit policy. Useful CPU worker tasks are a separate backend with immutable transferred inputs and measured break-even.

**Host capability.** Extend current `VDOMHost` with registration-time descriptions of value handling and resource lifetime, without changing generic host semantics by inference. A scalar writer may compare by `Object.is`; a copy writer can consume a temporary tuple only if it copies during the call; a borrowed-for-call writer cannot retain it; a retaining writer receives stable storage. Event handlers remain native host registrations and are detached on removal. Owned Three geometry/material is disposed once by its owning adapter; borrowed resources are restored or left alive per contract. A React island receives a committed boundary value and owns its own commit/lifecycle. The host's writer generation changes on replacement/disposal so old cuts decline.

| Fresh outputs | Every closed sink reads only captured values; every dynamic sink records a full current footprint and controlling invalidation; opaque work has explicit boundary semantics. Adversary: branch changes from reading `a` to reading `b` after `a` stayed equal. |
| Valid cut | Last callback precedes final source/lease/structure/writer checks. Adversary: a later getter retires a previously checked row, exactly as the lease audit demonstrated. |
| No stale row/host write | Output carries entity incarnation, structure base and writer generation; admission checks all three. Adversary: remove and reinsert the same key between preparation and commit. |
| Defined no-tear view | All roots in a declared group swap accepted pointers before notifications; unrelated fork frontiers may differ by design. Adversary: observer callback reads two group roots during notification. Visual paint and custom setter observations have narrower guarantees. |
| Exact action cutoff | Reentrant `v+1` remains pending when receipt acknowledges `v`. Adversary: host setter dispatches an update synchronously. |
| Partial failure | A thrown second writer leaves accepted view old and domain quarantined, with no blind replay of first writer. Adversary: custom setter mutates external object then throws. |
| Physical-mode equivalence | Sparse/tile/dense/generic produce the same sink identities, order, values, host writes permitted by value policy, refs/effects and acknowledgements. Adversary: equal scalar, mutable vector, moved keyed owner, stale token and HMR remount in one sequence. |

These are obligations for later implementation/qualification, not claims that present code has a formal proof. Existing focused tests establish individual behaviors; the combined cross-product remains open.

## 17. Final whole-system correctness and feasibility review

The design is coherent only if the following implication chain holds:

1. **Compiler soundness → correct invalidation.** A closed expression contains only owned captured inputs. Dynamic reads have versioned source identity and controlling invalidation. Opaque work executes at a documented non-speculative boundary. If any imported helper, getter, proxy, closure or extension can hide a read/effect behind a “closed” label, sparse execution can miss an output regardless of how fast its index is.
2. **Identity + capture → valid candidate.** Entity incarnation, site/module revision, structural base, source/store versions and writer generation are captured together. An old key that has been removed and reused is not the same owner. A public callback may invalidate a previously checked lease, so admission checks after the last callback.
3. **Admission + host authority → defined publication.** One host domain applies at a time; group read/write conflicts are resolved before application. Managed readers see old accepted pointers while applying. All group pointers swap before notifications, giving a no-accidental-tear claim *within the declared group*. Forks outside that group may deliberately show different versions. Arbitrary DOM paint, custom setter inspection and React island commits are not inside this atomicity claim.
4. **Successful application → exact acknowledgement.** The receipt advances only accepted roots and clears only captured versions. Reentrant and other-root actions survive. Store selector history commits after successful host work. This is where World current values, Root accepted values and pending actions must remain distinct.
5. **Failure → quarantine rather than false rollback.** A failed host write may leave physical partial mutations. Keep accepted pointers old, preserve pending actions/receipt, prevent subsequent publication into the damaged domain, and remount/dispose from known accepted data under an explicit recovery rule. Notification/effect failures after a successful pointer swap are postpublication errors.
6. **Physical plans preserve the chain.** Sparse, clustered and dense traversals may change iteration order only where it is unobservable; they share sink identity, value policy, host ordering constraints, writer lifetime, receipt and acknowledgement. Selector and index maintenance costs appear in the ledger. A plan with an independent mutable version/owner universe violates the proposed authority model.

There are unavoidable tradeoffs. Public arbitrary getters preserve observable order and live checking, which costs time. Multiple roots retain distinct accepted histories, which costs memory. Exact sparse propagation needs dependency indexes and dedup, which costs cold setup and maintenance; dense scans do necessary work efficiently only when outputs are dense. A retained VDOM and host resources cost memory. Partial host writes cannot be made rollbackable for every custom adapter. Opaque arbitrary React semantics cannot be made compiler-proven without restricting or bridging them. These costs are product choices to budget, not bugs that can be deleted by a new data structure.

| Claim | Current status and next proof |
| --- | --- |
| Qualified dense owner-kernel slower on registered workload | **Measured and independently verified** for archived source/environment; causal phase shares unresolved. |
| Fixed-topology Snake and async DAG narrow wins | **Measured** on their stated historic source/workload; no universal performance claim. |
| Public second-check deletion and accepted-history deletion | **Falsified** by lease/source-history audits; preserve meanings. |
| Local keyed identity, sparse store readers, Three extension, packaged native compiler | **Implemented with focused tests/checkpoints** in the cited current source and plans; integrated product/release gates remain open. |
| Owned cut, one semantic plan, three physical traversals, receipt state machine, host capabilities | **Proposed architecture**; neither implementation nor speed is certified. |
| Exact removable fraction, host floor, density crossover, structural container, worker break-even, human maintenance advantage | **Unresolved**; each has the bounded observation/stop rule above. |

The **blocking proof** for a physical redesign is still the causal cost ledger. Recording A either identifies one semantically removable vertical path with enough budget for the registered target or establishes that the fixed-output target is infeasible. That is the exact next action. No code edit, benchmark, server or browser run was performed in writing this guide, and the implementation freeze remains in force.

## Final recommendation and approval boundary

Approve the **semantic architecture and bounded diagnostic program** as the working research plan. Run the source-locked dense ledger first, calculate removable shares and host floor, then select at most one vertical physical candidate for independent review. Preserve sparse/clustered/dense as eligible execution families over the same identities and publication receipt; do not implement an adaptive selector or storage variant without its crossover and overhead evidence. After that, evaluate structural locality and async interaction under their distinct gates. The individual 0.8 budgets are 24.8%, 39.5% and 46.5% at 128, 1,024 and 10,000; the registered strong-win gate needs two sizes, not necessarily the two largest. If the bounded ledger cannot plausibly recover the required reduction at any two sizes, state the limit and revisit the product claim rather than expanding optimization indefinitely.

What can be approved now: classification, semantic contracts, recording protocol, evidence ledger and finite decision order. What remains on **HOLD**: exact sparse/clustered/dense thresholds, owned-cut performance benefit, sequence container, worker/Wasm/stream backend, claims of React superiority or lower maintenance, any physical migration or implementation. The code freeze remains until the user explicitly ends it after the causal ledger and reviewed concrete plan.
