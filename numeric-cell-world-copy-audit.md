# World numeric-cell representation audit

Read-only audit of `src/owner_state_world.ts` against `numeric-cell-shape-findings.md`, 13 October 2026. The file currently implements lane attach/detach by redefining the own `value` property; this audit describes the copy/publication paths that a prototype-accessor implementation must preserve.

## Representation contract

Compiler-eligible numeric cells should have the shared accessor prototype when constructed, including private candidate cells. Before lane publication, the accessor must read and write a private boxed value. With a lane attached, the column is the sole logical value store. Generic cells remain ordinary writable objects. A late layout declaration on an already-existing generic cell must preserve the current semantic path and setter behavior.

No current internal call site spreads, `Object.assign`s, enumerates, or requests a property descriptor from a `StateCell`. The cell type is private to this module. Its existing `value` is an own, enumerable, writable data property, so moving it to a prototype accessor changes `Object.keys(cell)`, own-property checks, and own-descriptor results even if the prototype accessor is enumerable. Those observations are not used by the audited World, Root, VDOM, or store paths. Keep this as an explicit compatibility boundary; do not copy a live cell with object spread or use enumerable-own-property copying as a substitute for the explicit candidate copy.

World and Root consume `cell.value` through normal property access. State reads, lane validation, candidate copying, rollback, publication, source resolution, and destruction therefore continue to observe the logical value through a getter. Root's native lane path reads the lane column for the prepared VDOM cut; the VDOM mirrors the captured value into the associated `ScalarSource` before projections. World setter and publication paths also update the scalar mirror. The mirror remains a separate object and must not be mistaken for authoritative state storage.

## Cell lifecycle and copy paths

| Path | Current behavior | Required representation invariant |
|---|---|---|
| Direct `useState` creation (`useState`, around line 1314) | Creates the committed cell as an object literal with own `value`; optional layout is normalized after insertion. | Select the numeric-cell factory only when a declared slot and numeric initializer make the cell eligible at birth. Ordinary/no-layout and ineligible cells retain ordinary behavior. |
| Direct layout attach (`#ensureCellLayout`, `#ensureNumericLane`, `attachNumericLane`, around lines 252–360) | Late layout metadata is cached; numeric cells get a row, the column is seeded from `cell.value`, then the lane is attached. Today attachment uses `Object.defineProperty`. | For birth-eligible cells, seed the column before publishing the lane address; attach by changing only lane fields. For a pre-existing late-metadata cell, preserve the compatibility path and retained setter semantics. Do not assume every declared slot is eligible if its runtime initial value is nonnumeric. |
| Direct setter / promotion (`#dispatchState`, around lines 1610–1665) | Reads previous value, detaches an active lane on a nonnumber, permanently marks compiler-slot cells promoted, writes the new value, updates source/version/journal, and emits stable cell handle notifications. | Detach must first copy the last column value into private boxed storage and clear the lane pointer before clearing/recycling the row. Then the setter writes the nonnumeric value to the box. A promoted cell must never reattach after a later numeric write. Preserve the same cell object, handle, version ordering, and notifications. |
| Candidate committed-cell copy (`makeCandidateCell`, around lines 601–685) | Captures the committed cell/version, reads `committed.value`, then explicitly constructs a separate candidate object. It copies layout/promotion state, but not lane, handle, or cell identity. A committed `ScalarSource` is cloned with the same source id and current value. | Keep the explicit copy. Candidate storage must be private even when the committed cell is lane-backed; never copy its lane address or reuse its backing column. A candidate write or discard must not mutate committed lane values. The cloned source stays a candidate mirror and must not be treated as the committed source identity. |
| Candidate layout metadata update (`makeCandidateCell`, existing candidate branch, around lines 607–635) | Adds layout/slot metadata to an already-created candidate and records an undo closure when a checkpoint is active. | Rollback must restore layout, slot resolution, promotion, and any representation-specific factory state together. If this metadata is late for a committed generic cell, do not silently convert it into the birth-eligible representation or lose its retained setter. |
| Candidate setter and checkpoint rollback (`useState` preparation path, around lines 780–830; `rollbackTo`, around lines 878–906) | Candidate writes update the candidate cell and its cloned source. Undo closures restore value/version/source/promotion and source value. | Candidate cells must not carry a committed lane. Every undo write must target the candidate's boxed storage. Include all newly added boxed-value or representation flags in rollback closures; test both numeric and nonnumeric writes and nested checkpoint rollback. |
| Private-owner subtree removal (`discardPrivateOwner`, around lines 913–1059) | Candidate cells are zeroed/released; undo closures retain prior cell/source values until the checkpoint is resolved. | During ordinary discard, clear boxed payload and source references. When a checkpoint can roll back the removal, keep enough boxed state to restore it; after checkpoint release/terminal discard, no callback or discarded candidate may retain payload-owning values. |
| Preparation publish to existing cell (`publish`, around lines 1106–1144) | Reuses the exact committed cell. If promoted, releases its lane first. A changed candidate writes through `existing.value`, increments version, updates the existing source, and ensures a lane if still eligible. If unchanged, an eligible existing numeric cell may be attached. | Preserve committed cell object, identity, handle, and existing source object. A write through an already attached accessor must update the same authoritative column; lane initialization must copy the candidate value only after it is valid. Do not replace the committed cell with the candidate snapshot. |
| Preparation publish of a new cell (`publish`, around lines 1146–1159) | Installs the candidate object itself, assigns its live dispatch, then allocates/attaches a lane for eligible numeric state. | New candidate cell must already have the intended prototype before publication. Attachment must not redefine its `value` property. The candidate's boxed value is copied once into the column before the lane becomes observable. |
| Preparation discard (`discard`, around lines 1178–1208) | Marks setters discarded, clears candidate cell values, zeros cloned sources, and clears candidate maps. | Candidate cells have no committed lane; clear their boxed payload, source and private references. Retained candidate setters remain rejected and cannot alter a committed column. |
| Staged owner activation (`createStagedOwner`, `activateStagedOwner`, around lines 1260–1305) | Staging only changes owner/slot maps; later `useState` follows the normal direct cell path. | Staged owner activation must not copy/replace a cell. Verify activation and replacement retain the same representation and that rollback/destruction clears staged candidate payloads. |
| Owner destruction and row reuse (`destroyOwner`, `#releaseNumericLane`, around lines 1548–1585 and 365–383) | Recursively destroys children, removes identity entries, detaches lanes, clears column rows and advances generation, then sets retained cell value to `undefined` and drops its source/map. | Detach before clearing the box or releasing the row. A retained dead setter still throws because owner liveness is checked; a retained cell must not read a reused row. Verify lane address/generation invalidation and that detached cell's `value` is cleared independently of the new owner. |

## Consumer and compatibility checks

- `component_state_runtime.ts` consumes values returned by `world.useState`, `world.scalarSource`, `world.scalarSourceForCell`, and `world.numericLaneForCell`; it does not access the private cell object or enumerate its fields.
- `#tryCommitNativeLanes` reads `lane.column.values[row]` as the captured numeric cut. VDOM updates the corresponding `ScalarSource.value` before running projectors. `#dispatchState` and publication also update source values. Tests should assert the cell's logical value, column value, and source mirror at each transition; they are three related but distinct observations.
- `ScalarSource` snapshots in a preparation are distinct objects. Their value must not alias the authoritative cell backing, and publishing an unchanged candidate must preserve the committed source object observed by existing Root indexes.
- Existing tests exercise candidate privacy/discard/publish (`owner_prepared_identity_test.ts`), reentrant versions, row reuse, and promotion. They do not currently assert cell prototype, own `value` descriptor, boxed candidate isolation at every transition, or late-layout behavior. No production call site found depends on `Object.keys(cell)`, spread, `Object.assign`, or an own `value` descriptor.

## Material risks and target tests

1. **Accessor ordering:** attach must seed the column before setting `lane`; detach must save the column value before clearing `lane`. Test direct initialization, publish of changed/unchanged candidates, promotion, destruction, and immediate row reuse. Assert old cell reads `undefined` after destroy and never sees the replacement owner's value.
2. **Candidate isolation:** copying a committed lane-backed cell must produce an independent candidate box and cloned source. Test candidate numeric and nonnumeric writes, rollback to nested checkpoints, private subtree discard, full discard, successful publish, and stale publish. Before publication, committed cell, lane, source and Root-bound output must remain unchanged.
3. **Publication identity:** existing-cell publication must preserve the exact internal cell, cell identity/handle, source identity and lane address where applicable. New-cell publication must install a correctly prototyped candidate without a live-cell copy. Include unchanged and changed existing cells, promotion, and a host/publication failure path if World publication can throw after prevalidation.
4. **Late layout:** create a generic cell without layout, retain its setter, then supply matching layout metadata. Verify same value/version/setter behavior, promotion, source/handle behavior and no silent eligibility loss. Also test layout mismatch still throws without partial lane attachment.
5. **Logical value versus mirror:** after setter, prepared write, publish, rollback and promotion, compare `useState` result, `numericLane` column (when present), and `scalarSource` value. Check source snapshots do not mutate a live lane and discarded sources are detached/cleared per existing lifetime policy.
6. **Shape boundary:** for a birth-eligible cell, verify the intended shared prototype/accessor and absence of per-cell accessor redefinition on lane attach/detach. Verify a generic cell remains an ordinary writable own-property object. If own-property enumeration compatibility is intentionally changed for eligible private cells, keep that distinction private and covered by a test; do not rely on spread copying.

This is a representation/correctness audit only. It makes no allocation or latency claim and does not establish that the prototype-accessor implementation passes the frozen timing gate.
