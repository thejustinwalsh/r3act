# Forked native transitions

A [fresh installed-package browser evaluation](../../implementation/2026-10-20-installed-async-ux/results.md) now preserves this app/scene/controller and checks separate Native/React graphs, twenty urgent button actions during pending B/C, cancellation and immediate disposal. Identity, accepted output and cleanup pass; Native is slower in the sole descriptive observer-delivery comparison. This does not qualify physical presentation, release performance, cold/memory or independent-device behavior.

This private-alpha example uses public native packages only. Its primary DOM root, forked DOM root and Three root share one World and two Stores. The Three scene is observed as an object tree; this page does not create a WebGL renderer. Replace the local private-alpha dependency versions with fresh package tarballs before installing. The Vite plugin uses its bundled Rust compiler and no checkout alias. Run a production build to obtain an offline file route; a development server must follow the repository's Portless HTTPS workflow.

The controller declares `renderPreparation: "repeatable"` on its generic root publications and task operation. These authored projections may be prepared, discarded, and retried while providers settle or roots diverge. Activation effects remain tied to accepted views.

`mountNative(host)` in `main.ts` returns a controller and the page exposes it as `window.forkedTransitions`. After initial A has revealed, await `beginB()`: a queued host publication advances the primary DOM and Three query projection to B while the fork keeps accepted A. One authored `NativeTaskTransitionQueue` operation then spans all three roots. Its compiler-inferred detail edge reads each root's live query; the primary and Three share one pending B execution while the fork has A. The initial result remains mounted as local pending work proceeds. Await `catchUpFork()` while both providers remain pending: a second queued host publication advances the fork to B, so the same task operation can reuse the existing B execution and retire A. The controller never mutates a Store's committed-root frontier directly.

`urgent()` dispatches an urgent counter action that both DOM roots and Three project during pending work. Await `beginC()` to publish a newer query C on all three roots, restarting only query-dependent tasks and retaining the completed independent catalog. Resolve the superseded B provider with `resolveB()` before `resolveC()`; late B must not replace accepted A. `resolveA()` permits a late result from the retired fork execution. The providers deliberately ignore abort for a stale-result guard test; `providerTrace` records each start, abort and resolution. `cancel()` retires task work but does not undo already dispatched B/C or urgent Store actions.

`snapshot()` exposes serializable DOM, Three, Store, task, provider, effect and cleanup observations. The Three result mesh, geometry and material UUIDs permit within-arm retention checks across A to C; UUIDs from separate app mounts or comparison arms are unrelated. Provider settlement methods remain callable after disposal so a late result can prove it has no retired host to reach. After `dispose()`, DOM owners and pending work should be zero, the Three host should have balanced owned resources, and the host should have left the borrowed geometry/material untouched; the application then disposes those borrowed resources exactly once. The fixture tests accepted host state separately from the chronological Store head. It demonstrates one bounded authored stress sequence, not arbitrary overlapping transition support, visual atomicity, responsiveness or a runtime speed advantage.
